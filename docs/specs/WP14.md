module is `src/services/**`, **not** `src/local/service/**`, so WP14 never edits WP04's
`local/mod.rs`. The proxy mapping needs `a3s_transport::ProxyConfig`, which `store` cannot depend
on, so it goes to `a3s_sync` (`net`).

## Scope

- `ClientData`: the in-memory state the Java services keep in static DAO maps (configuration,
  preferences, profiles, repositories), loaded once through WP04's `LocalStore`, with Java's startup
  fix-ups (`ui/main/MainPanel.java:457-490`).
- Every mutation of `ConfigurationService`, `PreferencesService`, `ProfileService` and the CRUD and
  setter part of `RepositoryService`, each persisted immediately through `LocalStore`, with
  Java's validation order and exact messages.
- Generic transactional updaters (`update_active_profile`, `update_repository`,
  `update_configuration`, `update_preferences`) so that WP07, WP10, WP11, WP13 and the UI can apply
  their pure logic and persist with one call.
- `CommonService`: `save` on exit, autoconfig export selection, autoconfig import merge (with the
  D-8 fix for repositories), and the help-menu link constants.
- `a3s_sync::proxy`: `configration.Proxy` → `a3s_transport::ProxyConfig`, routed per target protocol
  the way Java's JVM-wide system properties actually route traffic
  (`service/ConfigurationService.java:356-409`), plus `transport_options(target, proxy)`.

## Behaviour contract

### General persistence policy (applies to every mutator below)

- B1. Every public mutator of `ClientData` persists the affected file(s) through WP04's `LocalStore`
  before returning `Ok`. If validation fails, or the closure of an `update_*` method fails, or the
  write fails, the in-memory state is restored to what it was before the call and the error is
  returned. Java instead mutates memory first and swallows `WritingException`
  (e.g. `service/ProfileService.java:36-42`, `service/ConfigurationService.java:46-52`), and many
  Java setters never write at all, leaving it to the caller or to exit
  (`service/RepositoryService.java:661-667, 1188-1256, 1295-1352, 1562-1633`,
  `service/ConfigurationService.java:200-325`). Local-only deviation, see Q3.
- B2. `update_*` closures return `bool` (or `Result<bool, ServiceError>` for repositories) meaning
  "changed". `false` writes nothing. A closure must not change the name of the profile or
  repository it receives. If it does, the change is rolled back and
  `ServiceError::NameChange` is returned (renames have their own methods).
- B3. Multi-file operations (`rename_*`, `set_favorite_servers_to_autoconfig`, autoconfig import)
  write in the order given in their bullet. They stop at the first failed write. Memory then reflects
  exactly what reached the disk.

### Loading (`ClientData::load`, `ui/main/MainPanel.java:457-490`)

- B4. `ClientData::load(store: Arc<LocalStore>) -> LoadOutcome { data, warnings }` runs, in this order:
  1. `tracing::info!("Loading configuration...")` (`service/ConfigurationService.java:33`), then
     `store.read_configuration()`. On `Err`, push `err.user_message()` to `warnings`, log it, and use
     `Configuration::default()` (`MainPanel.java:460-464`).
  2. `store.read_preferences()`, with the same error rule and `Preferences::default()`. See B5.
  3. `tracing::info!("Loading profiles...")` (`ProfileService.java:28`), then `store.load_profiles()`.
     `ProfilesLoad::error_message()` (if `Some`) goes to `warnings` (`MainPanel.java:466-470`). An
     `Err` (unreadable directory) also goes to `warnings`, and the profile map is then just
     `{"Default": Profile::new("Default")}` (WP04 B12).
  4. `tracing::info!("Loading repositories...")` (`RepositoryService.java:68`), then
     `store.load_repositories()`. Successfully loaded repositories are kept even when there are
     failures. `error_message()` and duplicate warnings go to `warnings` (`MainPanel.java:472-476`,
     WP04 B16). The source path of each repository is remembered (B41).
  5. `tracing::info!("Loading proxy configuration...")`, then log `services::proxy_summary(&proxy)`,
     which returns the B56 text (`ConfigurationService.java:358, 403-407`). `a3s_repo_files` cannot
     call `a3s_sync`, so this short text is duplicated there; A1 and A23 check both give the same
     strings.
  6. Active-profile fix-up (`MainPanel.java:481-490`): if `configuration.profile_name` is not a key
     of the profile map, set it to `"Default"` and **write the configuration**
     (`ConfigurationService.setProfileName` writes, `ConfigurationService.java:46-52`). A write
     failure is pushed to `warnings`; the in-memory fix-up stays (start-up must not fail).
  7. `configuration.sort_favorite_servers()` (WP03 B20; Java sorts on every
     `getFavoriteServers()`, `domain/configration/Configuration.java:60-66`). Not written.
- B5. Preferences **are** loaded at start-up. Java lost this call in commit `f726f31`
  ("refactor: reuse theme toggle state"): `PreferencesService.read()` (`service/PreferencesService.java:13-15`)
  has no caller in b7753ce, so Java runs with default preferences and `CommonService.save`
  (`service/CommonService.java:46`) overwrites the user's `a3s.prefs` with defaults on every exit.
  Local-only bug fix, see Q5.
- B6. `ClientData` holds no transient runtime state: `repositorySyncStatus`, `serverInfo`,
  `downloadReport`, `lastIndexFileTransfered` and the remote metadata
  (`service/RepositoryService.java:794-810, 1457-1473, 1523-1539`) belong to WP07/WP21.

### Saving on exit (`CommonService.save`, `service/CommonService.java:41-52`)

- B7. `save_on_exit(height: i32, width: i32)`: set `configuration.height` and `.width`, then write,
  in this order, configuration, preferences, and the active profile if it exists
  (`:43-51`). Stop at the first error and return it (Java throws the first `WritingException`;
  the viewer then asks "Exit ArmA3Sync anyway?", `ui/main/MainPanel.java:886-898`, which is WP22's
  job). With B1 in place this mostly rewrites unchanged files, which is harmless.
- B8. `save_configuration()`, `save_preferences()`, `save_profile(name)` and
  `save_repository(name)` write the current in-memory value as is (Java `write()`,
  `ConfigurationService.java:37-39`, `PreferencesService.java:17-19`,
  `RepositoryService.java:72-78`). `save_repository` of an unknown name is `Ok(())` and writes
  nothing (Java `if (repository != null)`, `:75`).

- B19. `proxy() -> &Proxy` (`:327-331`).

### Repositories (`service/RepositoryService.java`)

- B34. `repositories()` iterates in name order (`BTreeMap`; Java iterates a `HashMap`,
  `:150-159`, local-only). `repository(name) -> Result<&Repository>`: missing →
  `RepositoryNotFound(name)`, text `"Repository <name> not found!"`
  (`exception/repository/RepositoryNotFoundException.java:6-8`, `:161-170`).
- B35. `ProtocolInput { protocol_type, url, port, login, password, validate_ssl_certificate }` is
  the form data of the connection dialogs. `build_protocol(input, unsupported_text)` =
  `new_protocol(...)` (WP03 B29), `None` → `UnsupportedProtocol(unsupported_text)`, then
  `check_protocol` (WP03 B33). The SSL policy (`a3s_types::ssl_policy`, WP05) is **not** applied
  here: Java applies it in the dialogs (`RepositoryEditionDialog.java:120-125`), and WP29/WP19 do
  the same.
- B36. `create_repository(name, input)` (`:80-97`), checks in this order:
  1. `name` empty → `EmptyRepositoryName`, text `"Repository name can't be empty."` (`:83-85`).
     Rust also rejects a whitespace-only name (Q2b): WP04 refuses to load such a file
     (`"Repository name is missing."`), so Java's acceptance of `" "` creates an unloadable file.
  2. Name already present → `RepositoryExists(name)` (Q2a; Java's `repositoryDAO.add` silently
     replaces the in-memory repository and loses its settings, `dao/repository/RepositoryDAO.java:47-50`).
  3. `build_protocol(input, "Protocol not supported yet.")` (`:87-93`).
  4. Insert `Repository::new(name, protocol)` (WP03 B2) and write it (Java writes later, through the
     caller, `RepositoryEditionDialog.java:146`).

  The caller-side follow-ups stay with the callers: default download location = first addon
  search directory of the active profile (`RepositoryEditionDialog.java:138-143`, WP29), and
  timeouts `"0"` for the console (`console/CommandConsole.java:333-339`, WP19).

### Proxy mapping (`a3s_sync::proxy`, `service/ConfigurationService.java:356-409`)

Java applies the proxy by setting JVM-wide system properties and a default `Authenticator`. Which
connections are then proxied depends on the Java networking stack used by each DAO:
`HttpDAO` uses `HttpURLConnection` (`dao/connection/http/HttpDAO.java:96`); `WebdavDAO` uses Apache
HttpClient with `useSystemProperties()` (`dao/connection/webdav/WebdavDAO.java:90`); `FtpDAO` uses
commons-net, which opens plain `java.net.Socket`s; `SftpDAO` uses Apache MINA SSHD (NIO2 channels).
The Rust mapping reproduces that effective routing per connection.

- B50. `proxy_for(target: ProtocolType, proxy: &Proxy) -> Result<Option<ProxyConfig>, ProxyError>`.
  `!proxy.enable_proxy` or `proxy.proxy_protocol == None` → `Ok(None)` (`:372, 406-407`).
- B51. Routing by proxy type (`:373-389`) and target type (see Q8):

  | Proxy type | Java property | Targets that use it | `ProxyConfig.scheme` |
  | --- | --- | --- | --- |
  | `Http` | `http.proxyHost/Port` | `Http`, `HttpWebdav` | `"http"` |
  | `Https` | `https.proxyHost/Port` | `Https`, `HttpsWebdav` | `"http"` (Java speaks plain HTTP `CONNECT` to an `https.proxyHost`; there is no TLS to the proxy) |
  | `Ftp` | `ftp.proxyHost/Port` | none: only `java.net.URL` `ftp://` connections read it, commons-net does not | — |
  | `Socks4` | `socksProxyHost/Port` | `Ftp`, `Ftps`, `Http`, `Https`, `HttpWebdav`, `HttpsWebdav` (every `java.net.Socket`); **not** `Sftp` (NIO2) | `"socks4"` (Q7) |
  | `Socks5` | `socksProxyHost/Port` | same as `Socks4` | `"socks5"` (local DNS, as Java resolves the host before `Socket.connect`) |
  | any other type | none (no branch) | none | — |

  A target outside the row → `Ok(None)`.
- B52. Host: `protocol.url` as is (Java `getUrl()`, `:375`). Empty, or containing `/`, `@` or
  whitespace → `Err(ProxyError::InvalidHost(url))` (Java would fail at connect time).
- B53. Port: Java `Integer.parseInt` of `protocol.port` (B32 rules); must be `1..=65535`, else
  `Err(ProxyError::InvalidPort(port))`. `"+3128"` gives 3128.
- B54. Credentials (`:390-401`): if `login` is `None` or equals `"anonymous"` (exact, case-sensitive)
  → `login = None, password = None` (Java `Authenticator.setDefault(null)`). Otherwise
  `login = Some(login)`, `password = Some(password.unwrap_or(""))`. Credentials are given **to the
  proxy only**: Java's default `Authenticator` also answered 401 challenges of the repository
  server with the proxy credentials (dropped, local-only security fix).
- B55. `transport_options(target: &Protocol, proxy: &Proxy) -> Result<TransportOptions, ProxyError>`
  = `TransportOptions::from_protocol(target)` with `proxy = proxy_for(target.protocol_type, proxy)?`.
  Every caller that opens a connection for a repository (WP07 checks, WP09 downloads, WP12 uploads,
  the partial-transfer probe) builds its options with this function from the current
  `ClientData::proxy()`.
- B56. `describe(proxy) -> String` (`:403-407`): enabled with a protocol →
  `"Proxy loaded: " + prompt(type) + url + ":" + port` (e.g. `Proxy loaded: http://10.0.0.1:3128`,
  also for an FTP proxy, which Java reports as loaded although it has no effect); otherwise
