## Scope

- **Registry** (`registry`): a small read/write abstraction (`RegistryRead`, `RegistryWrite`) with a
  `winreg` implementation (`cfg(windows)`), an in-memory `MemoryRegistry` for tests on every OS, and
  `CachedRegistry`, which ports Java's positive **and negative** process-wide cache.
- **Detection** (`detect`, `steam`, `vdf`): the Arma 3 directory, Steam directory, TS3 directory and
  Arma 3 RPT directory, as in `ConfigurationDAO.determine*Path`. Also the legacy Java Arma3Sync install
  dirs from the NSIS registry key (input for WP02 `discover_legacy_java`). **New behaviour:** Steam
  library discovery (`libraryfolders.vdf` + `appmanifest_107410.acf`) on Linux/macOS, and as a fallback
  on Windows, plus Proton prefix paths (Documents/Arma 3, AppData/Local/Arma 3).
- **Special folders** (`folders`): Documents and Desktop (Java `JShellLink.getDirectory("personal"/"desktop")`),
  and the log-export folder rule (Desktop on Windows, home elsewhere).
- **Process probe** (`process`): "is X.exe running" (Java `tasklist.exe` scan), with the Arma 3,
  Arma 3 server, Steam and TS3 name sets. Linux `/proc` scanning is new behaviour (it finds Proton/Wine
  processes).
- **Autostart** (`autostart`): Windows `HKCU\…\Run` value (Java used HKLM; deviation), Linux XDG
  autostart `.desktop`, macOS LaunchAgent plist; enable, disable, status.
- **Desktop shortcuts** (`shortcut`): Windows `.lnk` via `mslnk` (Java `JShellLink`), Linux `.desktop`
  launcher (new), with the Java dialog strings.
- **Single instance** (`single_instance`): a local socket (`interprocess`) lock plus an "activate"
  message to the running instance, so it can bring itself to the front (Java JUnique).
- Not included: UI, flags parsing, persistence of the `StartWithOS` preference, launching games.

## Behaviour contract

### Registry abstraction (`registry`)

- R1. A query is `(hive, key path, value name or None for the default value)`. Hives used:
  `HKEY_CURRENT_USER`, `HKEY_LOCAL_MACHINE` (Java supports only these two,
  `dao/WinRegistry.java:25-26, 89-95`). Key paths use `\`. A `/` in a key path becomes `\`
  (`dao/WinRegistry.java:90`). Key paths and value names are matched case-insensitively (Windows
  semantics; `MemoryRegistry` must do the same).
- R2. Reads go to the process's native view. Java's queries spell out `Wow6432Node` explicitly
  (`dao/ConfigurationDAO.java:66, 75`), and Rust must use **those literal paths**, so that a 64-bit
  process reads the 32-bit view exactly as Java's `reg query` did. No `KEY_WOW64_*` flags.
- R3. `read_string` returns:
  - `Ok(Some(s))` for `REG_SZ`, and for `REG_EXPAND_SZ` after `%VAR%` expansion (unknown variables stay
    literal). Both backends share one pure `decode_value(data, var_lookup)`. `SystemRegistry` looks
    variables up in the process env. `MemoryRegistry` uses the vars given to `with_env`. Java's `reg query` parsing only recognised `REG_SZ`
    (`dao/ConfigurationDAO.java:20, 206`), so `REG_EXPAND_SZ` gave `null` there. Accepting it is
    deviation D4.
  - Java `String.trim()` is applied: leading and trailing chars `<= U+0020` are removed
    (`dao/ConfigurationDAO.java:211`). If the trimmed string is empty, the result is `Ok(None)`.
    Java returned `""`, and every caller then failed an `exists()` check, so the effect is the same
    (deviation D5).
  - `Ok(None)` when the key or value is missing, or the value is another type.
  - `Err(_)` for any other OS error (for example access denied).
- R4. Java decoded `reg` output one byte per char (`dao/StreamReader.java:20-23`), which corrupts
  non-ASCII paths. Rust reads UTF-16 through `winreg`, so paths come back correct (deviation D6).
- R5. Writes: `set_string(hive, key, name, value)` creates the key if it is missing and writes `REG_SZ`
  (Java `reg ADD … /t REG_SZ /d value /f`, `dao/WinRegistry.java:55-59`). `delete_value(hive, key, name)`
  returns `Ok(())` when the key or value is already missing (Java swallowed every delete error,
  `dao/PreferencesDAO.java:82-86`).
- R6. `CachedRegistry<R>` ports `queryRegistryValue` (`dao/ConfigurationDAO.java:179-196`). The cache
  key is `(hive, lowercase key path, lowercase value name)`:
  1. If the key is in the positive cache, return the cached value.
  2. Otherwise, if it is in the negative cache, return `None` **without** querying.
  3. Otherwise query. `Ok(Some(v))` is stored in the positive cache. `Ok(None)` **and `Err`** (logged at
     `debug`) are stored in the negative cache and return `None`. Java swallows errors as `null` and
     caches them negatively (`:198-216`, `:190-191`).
  The cache lives for the whole process and is never invalidated, as in Java's statics (`:21-22`).
  Rust adds `clear()` (new; e.g. for a "Detect again" button). Locks (`parking_lot::Mutex`) are held
  only for lookups and inserts, never during the OS query. Two threads querying the same key at once
  may both query, which is benign and matches Java's `ConcurrentHashMap` race.
- R7. `system_registry()` returns a process-wide `&'static CachedRegistry<SystemRegistry>` (a
  `OnceLock`). `SystemRegistry` uses `winreg` on Windows. On other OSes every read is `Ok(None)` and
  every write is `Err(Error::Unsupported)`.
- R8. Detection functions take `&dyn RegistryRead`. On a non-Windows `PlatformEnv` they never query
  the registry (Java checks `isWindows()` first, `dao/ConfigurationDAO.java:62-64, 180-182`).
  `isWindows` is `os.name contains "Windows"` (`:174-177`) → `env.os() == Os::Windows`.

### Detection (`detect`)

- D1. `arma3_dir_from_registry(env, reg)`: `HKLM\SOFTWARE\Wow6432Node\Bohemia Interactive\Arma 3`,
  value `MAIN` (`dao/ConfigurationDAO.java:69-76`). There is no existence check (Java has none).
- D2. `steam_dir_from_registry(env, reg)`: `HKLM\SOFTWARE\Wow6432Node\Valve\Steam`, value `InstallPath`
  (`dao/ConfigurationDAO.java:60-67`; it has no caller in Java). If that is `None`, use
  `HKCU\Software\Valve\Steam` value `SteamPath` with every `/` replaced by `\` (new fallback).
- D3. `ts3_dir(env, reg)`: `HKCU\Software\TeamSpeak 3 Client`, **default** value (`/ve`)
  (`dao/ConfigurationDAO.java:78-85`). If that is `None`, try the same key under HKLM, then
  `HKLM\SOFTWARE\Wow6432Node\TeamSpeak 3 Client` (new fallback for "all users" installs, deviation
  D7). The result feeds WP17 T3 (stored-or-detected; the stored value wins,
  `service/ConfigurationService.java:188-198, 214-224`).
- D4. `rpt_dir(env, steam)`:
  - Windows: if env `APPDATA` is set (non-blank), take its parent directory and append
    `\Local\Arma 3`, as a **string** operation. Strip trailing `\` or `/` from `APPDATA`, cut at the
    last `\` or `/`, then append `\Local\Arma 3`. Return the result **without** an existence check
    (`dao/ConfigurationDAO.java:161-172`). If `APPDATA` has no parent (e.g. `C:\`, or a relative
    `Roaming`), Java threw an NPE. Rust returns `None` (deviation D8). If `APPDATA` is unset, return `None`.
  - Linux/macOS: `None` in Java. **New:** if Steam detection (S5) finds Arma 3 with a Proton prefix,
    return `ProtonPaths::local_appdata_arma3` when that directory exists, else `None`.
  - Caller rule (stored RPT path wins, `service/ConfigurationService.java:249-259`) belongs to WP17/WP30.
- D5. `detect_arma3_dir(env, reg)`. Order:
  1. Windows: D1. If it is `Some`, return it unchanged (no exists check, Java parity).
  2. All OSes (new on Linux/macOS; a fallback on Windows): the Steam app `107410` install dir from S5.
  3. `None`.
  Callers keep Java's handling: the Launcher Options file chooser opens there if it exists
  (`ui/main/LauncherOptionsPanel.java:1140-1160`). At startup, if the profile exe path is unset or
  missing and `<dir>/arma3_x64.exe` exists, the profile is set to it
  (`ui/main/MainPanel.java:1045-1069`, `constant/GameExecutables.java:5`). That startup rule is WP22's;
  this crate only exposes `ARMA3_X64_EXE = "arma3_x64.exe"`.
- D6. `java_install_dirs(env, reg) -> Vec<PathBuf>`: on Windows, read `InstallDir` from
  `HKLM\SOFTWARE\Wow6432Node\Virtuelle Panzerbrigade 21 (vPzBrig21)\Arma3Sync`, then
  `HKLM\SOFTWARE\Wow6432Node\Arma3Sync community\Arma3Sync` (NSIS has no `SetRegView`, so a 64-bit
  OS writes the 32-bit view; `installer/nsis/Arma3Sync.nsi:36, 69, 141`,
  `installer/nsis/include/Version.nsh:6-8`), then the same two keys without `Wow6432Node`. Order is
  kept, duplicates (case-insensitive) are dropped, and only `Some` values are returned. Non-Windows
  returns an empty vec. WP04 passes this to `a3s_paths::legacy::discover_legacy_java`. **New** (Java
  never reads it).
- D7. Not ported (no callers in Java): `determineArmA2Path`, `determineArmA2OAPath`,
  `determineArmAPath`, `determineTOHPath` (`dao/ConfigurationDAO.java:122-159`).
  `determineTS3version` (`:87-120`) is WP17's `ts3_version`.

### Steam libraries (`steam`, `vdf`) — all new behaviour

- S1. Steam roots, in this order, keeping only existing directories, deduplicated by
  `fs::canonicalize` (falling back to the raw path):
  - Windows: D2 result; `%ProgramFiles(x86)%\Steam`; `%ProgramFiles%\Steam`.
  - Linux / other Unix: `$XDG_DATA_HOME/Steam` (absolute only), `~/.local/share/Steam`,
    `~/.steam/root`, `~/.steam/steam`, `~/.var/app/com.valvesoftware.Steam/.local/share/Steam` (Flatpak),
    `~/snap/steam/common/.local/share/Steam` (Snap).
  - macOS: `~/Library/Application Support/Steam`.
- S2. Libraries of a root: the root itself first, then the entries of
  `<root>/steamapps/libraryfolders.vdf` in file order (deduplicated as in S1, existing dirs only).
  Supported formats:
  - Modern: `"libraryfolders" { "0" { "path" "…" "apps" { "107410" "…" } … } … }`. Each child object's
    `path` value is a library.
  - Legacy: `"LibraryFolders" { "TimeNextStatsReport" "…" "ContentStatsID" "…" "1" "D:\\SteamLibrary" }`.
    Each child whose key is all digits and whose value is a string is a library.
  The root key is matched case-insensitively. A missing or unparsable file means "root only", and a
  parse failure is logged at `debug`.
- S3. VDF (KeyValues text) parser, within these limits: input ≤ 1 MiB, nesting depth ≤ 32. Tokens are:
  - quoted strings with the escapes `\\`, `\"`, `\n`, `\t` (any other `\x` stays literal `\x`);
  - unquoted tokens up to whitespace, `{`, `}` or `"`;
  - `{` and `}`;
  - `//` line comments;
  - `[$…]` conditionals after a value, which are skipped.
  The result is an ordered tree `Vec<(String, Value)>` where `Value` is `Str(String)` or `Obj(Vec<…>)`.
  Duplicate keys are kept in order. Lookups are case-insensitive and return the first match.
- S4. App lookup `find_steam_app(roots, app_id)`: for each library in order, if
  `<lib>/steamapps/appmanifest_<app_id>.acf` exists and parses, take `AppState.installdir`
  (case-insensitive; default `"Arma 3"` for `107410` if it is missing). If
  `<lib>/steamapps/common/<installdir>` is a directory, return
  `SteamApp { app_id, library, install_dir }`. The first match wins.
- S5. `ARMA3_APP_ID = 107410`. `find_arma3(env, reg) = find_steam_app(steam_roots(env, reg), 107410)`.
- S6. `proton_paths(app) -> Option<ProtonPaths>`: let
  `pfx = <library>/steamapps/compatdata/<app_id>/pfx`. If `pfx` is not a directory → `None`.
  Otherwise `user = pfx/drive_c/users/steamuser` and:
  - `documents_arma3 = user/Documents/Arma 3` if `user/Documents` exists, else `user/My Documents/Arma 3`
    (older Proton);
  - `local_appdata_arma3 = user/AppData/Local/Arma 3`.
  Paths are returned whether or not they exist, except where D4 checks them. Windows never uses this.

### Special folders (`folders`)

- F1. `trait SpecialFolders { fn home(&self) -> Option<PathBuf>; fn documents(&self) -> Option<PathBuf>; fn desktop(&self) -> Option<PathBuf>; }`.
  `SystemFolders` uses `directories::UserDirs`: the Known Folder API on Windows (FOLDERID_Documents /
  FOLDERID_Desktop, the same folders as `JShellLink.getDirectory("personal"/"desktop")`,
  `service/LaunchService.java:165`, `ui/main/MainPanel.java:721`), and `user-dirs.dirs` on Linux. If
  `directories` gives `None` for documents or desktop, fall back to `<home>/Documents` resp.
  `<home>/Desktop` when that directory exists, else `None`. `MemoryFolders` (pub, plain struct with
  three `Option<PathBuf>`s) is the test double.
- F2. `arma3_documents_dir(env, folders, steam)`: on Windows `documents()/Arma 3`
  (`service/LaunchService.java:165-166`, used by WP16 for `Arma3.cfg`). Elsewhere `None` in Java
  (`:159-163`). **New:** on Linux return the Proton `documents_arma3` from S6 if Arma 3 is found.
- F3. `log_export_dir(env, folders)`: Windows → `desktop()`; elsewhere → `home()`
  (`ui/ErrorLogDialog.java:59-69`; the same rule in `HeaderErrorDialog.java:50-55`,
  `UnexpectedErrorDialog.java:56-61`, `ErrorsListDialog.java:88-93`, `ReportDialog.java:87-92`). The
  file name is `a3s_paths::EXPORT_LOG_FILE_NAME`. If the Windows desktop is `None`, fall back to `home()`.

### Process probe (`process`)

- P1. `trait ProcessProbe: Send + Sync { fn snapshot(&self) -> io::Result<ProcessSnapshot>; }`.
  `ProcessSnapshot::is_running(name)` and `is_any_running(&[names])` compare image names
  case-insensitively (ASCII). Helpers `is_running(probe, name)` and `is_any_running(probe, names)`
  return `false` on any error, matching Java's swallowed exceptions (`dao/LauncherDAO.java:50-52`).
  `is_any_running` takes **one** snapshot. Java spawned `tasklist` once per name.
- P2. Name sets (`service/LaunchService.java:94-127`, `constant/GameExecutables.java:5-6`):
  - `ARMA3_EXES = ["arma3.exe", "arma3_x64.exe"]`
  - `ARMA3_SERVER_EXES = ["arma3server.exe", "arma3server_x64.exe"]`
  - `STEAM_EXE = "steam.exe"` (`:470`)
  - `TS3_EXES = ["ts3client_win32.exe", "ts3client_win64.exe"]`
  - Plus `is_arma3_running`, `is_arma3_server_running`, `is_ts3_running` and `is_steam_running`.
  External applications use `is_running(probe, file_name)` (`:71`).
- P3. Windows (`SystemProcessProbe`): run `<SystemRoot or windir>\System32\tasklist.exe /FO CSV /NH`
  (Java: `%windir%\system32\tasklist.exe` with no args, `dao/LauncherDAO.java:36-38`; if both env vars
  are unset, use `C:\Windows`). Pass `creation_flags(CREATE_NO_WINDOW = 0x0800_0000)` through
  `std::os::windows::process::CommandExt` (safe code; no console flash from a GUI process). Decode
  stdout lossily, then parse it with `parse_tasklist_csv`: the first CSV field of each non-empty line,
  with surrounding quotes removed and `""` unescaped. Java matched `line.toLowerCase().contains(name)`
  on the default table output (`:43-47`), where image names are truncated at 25 chars. Rust matches
  whole image names exactly (case-insensitive) on untruncated CSV (deviation D9). There is no timeout
  (Java had none).
- P4. Linux (`ProcFsProbe { root }`, default `/proc`, injectable for tests) — **new**. Java returned
  `false` on non-Windows (`dao/LauncherDAO.java:39-41`). For every all-digit directory under root:
  - read `comm` (trim the trailing `\n`): this is a *possibly truncated* name (the kernel cuts at
    15 bytes);
  - read `cmdline`, take argv[0] (up to the first NUL), and use its last component after splitting on
    both `/` and `\`. Wine and Proton processes show Windows paths here.
  Unreadable entries are skipped (the process exited or permission was denied). A name matches if it
  equals argv0-basename or comm (case-insensitive), or if comm is exactly 15 bytes and equals the
  first 15 bytes of the name.
- P5. macOS / others: `snapshot()` returns `Err(Unsupported)`, so the helpers return `false` (Java parity).
- P6. WP17 defines `a3s_tools::radio::Ts3ProcessProbe { fn is_ts3_running(&self) -> bool }`. This
  crate does **not** depend on `a3s_tools` (see Q1). The consumer (WP30/WP19) writes a newtype adapter:
  `struct Ts3(&'a dyn ProcessProbe); impl Ts3ProcessProbe for Ts3 { … is_ts3_running(self.0) }`.
- P7. Not ported here: `terminateProcess` / `taskkill /IM` (`dao/LauncherDAO.java:372-376`) belongs to
  WP16.

### Autostart (`autostart`)

- A1. Java behaviour (`dao/PreferencesDAO.java:55-88`, `ui/help/PreferencesDialog.java:357-371, 403-416`):
  - Windows only. On other OSes the combo box is disabled and forced to `Disabled`.
  - On OK with `Enabled`: write `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`, value
    `ArmA3Sync` = `"<canonical cwd>\Arma3Sync.exe" -run`. The `devMode` argument is ignored.
    Success → `runMode = true`. Failure → print `Failed to write into Windows registry.` and set
    `runMode = false`. The preference is saved either way.
  - On OK with `Disabled`: delete that value and swallow errors.
  - The label is `Start with Windows:` and the values are `Enabled`/`Disabled`
    (`constant/StartWithOS.java:5`; `getEnum` maps anything else to `Disabled`, `:17-23`).
  - `-run` starts minimised to the tray (`main/ArmA3Sync.java:125-126`, `ui/main/MainPanel.java:572-578`).
- A2. Rust `AutostartEntry { exe: PathBuf, args: Vec<String> }`.
  `AutostartEntry::for_current_process(args)` uses `std::env::current_exe()`. On Linux, if env
  `APPIMAGE` is set (non-blank), it uses that path instead, because `current_exe` points into the
  transient AppImage mount (new). Java used the **working directory** + `\Arma3Sync.exe` (a bug;
  deviation D2). The args come from the caller. The recommended value is `["-run"]` (Q5).
- A3. Windows backend: **HKCU** `Software\Microsoft\Windows\CurrentVersion\Run` (deviation D1: HKLM
  needs admin rights and usually failed silently). The value name is `AUTOSTART_NAME = "arma3sync-rs"`
  (Q4). The data is `windows_run_command(entry)`: `"` + exe + `"`, then for each arg a single space and
  the arg quoted with `quote_windows_arg` (W1). With args `["-run"]` this is `"C:\…\arma3sync.exe" -run`,
  the same shape as Java. `enable` → `set_string`. `disable` → `delete_value` (missing → Ok).
  `status` → `Disabled` if the value is absent; `Enabled { command }` otherwise. Java's HKLM
  `ArmA3Sync` value is never read, written or deleted.
- A4. Linux / other Unix backend (new): file `<autostart dir>/arma3sync-rs.desktop`, where the
  autostart dir is `$XDG_CONFIG_HOME/autostart` (absolute only) or else `~/.config/autostart`. `enable`
  creates the dir and writes the file atomically (temp file + rename in the same dir) with exactly:
  ```
  [Desktop Entry]
  Type=Application
  Version=1.0
  Name=ArmA3Sync
  Exec=<desktop_exec(exe, args)>
  Terminal=false
  X-GNOME-Autostart-enabled=true
  ```
  (LF line endings, trailing LF). `disable` removes the file (missing → Ok). `status`: if the file
  is missing → `Disabled`. If it has `Hidden=true` or `X-GNOME-Autostart-enabled=false` → `Disabled`.
  Otherwise → `Enabled { command: <Exec value> }`.
- A5. macOS backend (new, Q3): `~/Library/LaunchAgents/com.github.vpzbrig21.arma3sync-rs.plist`, written
  atomically:
  ```xml
  <?xml version="1.0" encoding="UTF-8"?>
  <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
  <plist version="1.0">
  <dict>
  	<key>Label</key>
  	<string>com.github.vpzbrig21.arma3sync-rs</string>
  	<key>ProgramArguments</key>
  	<array>
  		<string>EXE</string>
  		<string>ARG…</string>
  	</array>
  	<key>RunAtLoad</key>
  	<true/>
  </dict>
  </plist>
  ```
  The `<string>` contents are XML-escaped (`&` `<` `>` `"` `'`). `launchctl` is not invoked; the agent
  takes effect at the next login. `disable` removes the file. `status` = file exists.
- A6. `autostart_backend(env, registry)` picks the backend from `env.os()`. `Os::Other` →
  `Unsupported`, and every operation returns `Err(Error::Unsupported)`. For Linux/macOS the paths are
  resolved from `PlatformEnv` (home, `XDG_CONFIG_HOME`), so tests use temp dirs.
- A7. The return value replaces Java's `boolean ok`. The caller (WP29) sets run mode / shows an error
  from `Result`. User message constant: `FAILED_TO_WRITE_REGISTRY = "Failed to write into Windows registry."`
  (`dao/PreferencesDAO.java:69`).

### Shortcuts (`shortcut`)

- K1. Java flow (`ui/main/MainPanel.java:690-734`), with the title `Export profile as shortcut` on every
  dialog. These strings live in `shortcut::strings`:
  - non-Windows → info `This feature is not available for your system.` (`:693-698`);
  - no profile name → silent return (`:700-703`);
  - exe path null or `""` → info `ArmA 3 Executable location is missing for profile name {p}.\nPlease checkout Launcher Options panel.` (`:705-712`);
  - otherwise write `<desktop>\<profileName>.lnk` with target = the profile's exe path and arguments =
    the concatenation of `" " + param` for each run parameter (leading space, **no quoting**,
    `:715-725`). Success → info `Shortcut has been created on desktop for profile {p}.` (`:727-728`).
    Any exception → error `Failed to create shortcut\n{e.getMessage()}` (`:729-733`). An existing
    shortcut is overwritten.
  Menu item label: `Shortcut` in the Profiles menu (`:145-148`). In Rust the dialog flow belongs to
  WP22. This crate provides the strings, `ShortcutSpec` and the writers.
- K2. `ShortcutSpec { name: String, target: PathBuf, args: Vec<String>, working_dir: Option<PathBuf>, icon: Option<PathBuf>, comment: Option<String> }`.
  `validate_shortcut_name(name)`: the name must be non-empty after trim, must not be `.` or `..`, and
  must contain none of `\ / : * ? " < > |` or control chars. Otherwise →
  `Error::InvalidShortcutName`. Java let the OS fail, and the message differs (deviation D10).
- K3. `quote_windows_arg(arg)` (W1) uses the MSVCRT / `CommandLineToArgvW` rules (the same as Rust
  std's `Command` on Windows). If the arg is non-empty and contains none of space, `\t`, `\n`, `\x0B`
  or `"`, it is copied verbatim. Otherwise it is wrapped in `"`. Inside the quotes, a run of *n*
  backslashes followed by `"` becomes 2n+1 backslashes plus `"`, and a run of *n* backslashes at the
  end becomes 2n backslashes. `windows_args(args)` joins the quoted args with single spaces (no leading
  space). Java did not quote, so a `-mod=` path with spaces broke (deviation D3).
- K4. `write_lnk(spec, path)` (available on all OSes, so it is tested on Linux) uses `mslnk::ShellLink`.
  Preconditions, checked first, so that `mslnk`'s internal `unwrap()`s cannot be reached
  (`mslnk-0.1.8/src/lib.rs:77-105`, `linktarget.rs:66-82`):
  - `target` is UTF-8 and absolute, and has a parent and at least 2 normal components;
  - `fs::metadata(target)` succeeds, else `Error::ShortcutTargetMissing`. Java did not require the
    target to exist (deviation D10);
  - on Windows, the target starts with a drive letter `X:\` (UNC paths → `Error::Unsupported`);
  - `windows_args(args)` is ≤ 32 767 UTF-16 units (the `CreateProcess` limit; `mslnk` stores a `u16`
    count). Else `Error::InvalidInput`.
  Then call `ShellLink::new(target)`. It sets the working dir to the target's parent and `IS_UNICODE`.
  Override the working dir if `spec.working_dir` is `Some`. Call `set_arguments(Some(windows_args))`
  only when args are non-empty. Call `set_icon_location` when `icon` is `Some` and `set_name(comment)`
  when `comment` is `Some`. Finally call `create_lnk(path)`, which overwrites (Java parity).
- K5. `write_desktop_entry(spec, path)` (new, for Linux/BSD), written atomically, then mode `0o755` on
  Unix (KDE/GNOME require the executable bit for desktop launchers):
  ```
  [Desktop Entry]
  Type=Application
  Version=1.0
  Name=<escape_value(name)>
  Exec=<desktop_exec(target, args)>
  Path=<escape_value(working_dir)>        (only if Some)
  Icon=<escape_value(icon)>               (only if Some)
  Comment=<escape_value(comment)>         (only if Some)
  Terminal=false
  ```
  `escape_value` uses the Desktop Entry string escapes: `\` → `\\`, newline → `\n`, tab → `\t`,
  CR → `\r`, and a leading space → `\s`. `desktop_exec` follows the Exec-key rules:
  - an arg (including the program) with any of space, tab, `"`, `'`, `\`, `>`, `<`, `~`, `|`, `&`,
    `;`, `$`, `*`, `?`, `#`, `(`, `)` or `` ` ``, or an empty arg, is wrapped in `"`, and inside it
    `"`, `` ` ``, `$` and `\` are backslash-escaped;
  - every `%` becomes `%%`;
  - a newline or NUL in any arg → `Error::InvalidInput`;
  - the result is passed through `escape_value`, so a backslash inside a quoted arg ends up as `\\\\`
    in the file.
  GNOME's `metadata::trusted` is not set (no `gio` call).
- K6. `create_desktop_shortcut(env, folders, spec) -> Result<PathBuf>`:
  - Windows → `folders.desktop()/<name>.lnk` via K4;
  - Linux / other Unix → `folders.desktop()/<name>.desktop` via K5 (new);
  - macOS / Other → `Err(Error::Unsupported)`, which the UI shows as the Java "not available" text.
  If the desktop is `None` → `Error::NoDesktopDir`. Returns the written path.

### Single instance (`single_instance`)

- I1. Java (`main/ArmA3Sync.java:174-254`):
  - The app id is the class name `fr.soe.a3s.main.ArmA3Sync` (`:190`).
  - Single instance is active only on **Windows** and only when not started with `-unlock`
    (`:127-128, 192-197`). Console/CLI modes never take the lock (`:129-171`).
  - On `AlreadyLockedException` it prints `Arma3Sync process is already locked.` (`:217-219`), then
    `Can not start Arma3Sync. Process is already running.`, sends an empty message to the owner, and
    exits with `Runtime.halt(1)` (`:249-253`).
  - Other lock errors are printed and the app starts normally (`:220-222`).
  - The owner's handler brings the window to front: always-on-top on, `setToFront` (remove the tray
    icon, `NORMAL` state, visible, `toFront`), `requestFocus`, always-on-top off (`:204-215`,
    `ui/main/MainPanel.java:938-945`).
  - The deprecated file lock `lockInstance` (`:256-296`) is not ported.
- I2. `InstanceId::for_config_dir(dir)`: `"arma3sync-rs-" + 16 lowercase hex digits of FNV-1a-64` over
  the UTF-8 (lossy) bytes of `dir`, lowercased first on Windows and macOS (case-insensitive file
  systems). Different users and portable installs therefore get different ids. The caller passes
  `AppDirs::config_dir()`. `InstanceId::from_raw(s)` is for tests.
- I3. Socket name: on Windows and Linux, `GenericNamespaced` (a named pipe `\\.\pipe\<id>` or a Linux
  abstract socket `@<id>`). On other Unixes, `GenericFilePath` at `<cache_dir>/<id>.sock` if that
  path is ≤ 100 bytes, else `std::env::temp_dir()/<id>.sock`. `AcquireOptions` carries the cache dir.
- I4. `acquire(id, opts, on_message) -> Acquire`. `on_message` is `Fn(InstanceMessage) + Send + Sync + 'static`.
  Up to `opts.attempts` (default 5) attempts, `opts.retry_delay` (default 100 ms) apart:
  1. Create a listener (`ListenerOptions::new().name(…)`, `reclaim_name(true)`, no `try_overwrite`).
     On success → `Acquire::Primary(InstanceGuard)`, and spawn the accept thread
     `a3s-single-instance`.
  2. On `AddrInUse` (or `PermissionDenied`, which is what Windows returns when the first pipe instance
     exists), connect as a client. Write `HELLO_LINE = "a3s-instance/1 activate\n"` and wait up to
     `opts.reply_timeout` (default 2 s) for `"ok\n"`. Run that client exchange on a helper thread and
     wait with `recv_timeout`, because the sync streams have no timeout.
     - If the reply is `ok` → `Acquire::Secondary`.
     - If the connection is refused, the reply is wrong, or it times out → retry.
     - On non-Linux Unix, if the connection is refused, the socket file is stale: remove it (only if
       it is a socket) and retry.
  3. On any other listener error, or after all attempts fail → `Acquire::Unlocked { reason }` (log at
     `warn`). The app starts without the lock, mirroring Java's "print and continue". A foreign
     process squatting on the name (it cannot answer `ok`) therefore cannot stop the app from starting.
- I5. The server side: each accepted connection is handled on a short-lived thread
  `a3s-single-instance-conn`, so a silent client only parks its own thread and never blocks the accept
  loop. It reads at most 256 bytes or up to the first `\n`. If the line is `HELLO_LINE` (without its `\n`), it writes `ok\n` and then calls
  `on_message(InstanceMessage::Activate)`. Anything else is closed without a reply and without a
  callback. Java delivered `""` → bring to front.
- I6. `InstanceGuard` keeps the listener alive. `Drop` (and `shutdown()`) set a stop flag, connect
  once to self to wake `accept`, and join the thread. The socket name is then free (the file is removed
  on non-Linux Unix via `reclaim_name`).
- I7. Policy: single instance is enabled on **all** OSes (deviation D11). The caller skips `acquire`
  for `-unlock`, CLI and console modes. Constants for the caller (WP19/WP22):
  `MSG_ALREADY_LOCKED = "Arma3Sync process is already locked."`,
  `MSG_ALREADY_RUNNING = "Can not start Arma3Sync. Process is already running."`,
  `EXIT_CODE_ALREADY_RUNNING = 1`.
- I8. Bring-to-front is the viewer's job (WP22). `on_message` runs on the listener thread, so the
  viewer must forward it (channel + `egui::Context::request_repaint`). It then applies
  `ViewportCommand::Visible(true)`, `Minimized(false)`, `WindowLevel(AlwaysOnTop)`, `Focus`, then
  `WindowLevel(Normal)`, and removes or hides the tray state. This replaces `MainPanel.java:938-945`
  and `ArmA3Sync.java:209-212`.

### Errors, cancellation, progress

- One `pub enum Error` (`thiserror`, `#[non_exhaustive]`):
  - `Io { path: Option<PathBuf>, source }`
  - `Registry { key: String, source: io::Error }`
  - `Unsupported`
  - `InvalidShortcutName(String)`
  - `ShortcutTargetMissing(PathBuf)`
  - `NoDesktopDir`
  - `InvalidInput(String)`
  - `Lnk(String)` (`mslnk::MSLinkError` rendered)
  - `SingleInstance(io::Error)`
  It implements `a3s_error::UserFacing` with these kinds: Io → `ErrorKind::from_io`, Registry → `Io`
  (`PermissionDenied` if the source is), Unsupported → `Unsupported`, the shortcut/input variants →
  `InvalidInput`, `ShortcutTargetMissing` → `NotFound`. The user messages are the Java strings where
  they exist (K1, A7).
- Detection never returns errors: failures become `None` and are logged at `debug` (Java swallowed
  them and printed stack traces).
- No retries except the single-instance attempts (I4). No cancellation or progress.

### Concurrency

- Java: `ConcurrentHashMap` caches; one `StreamReader` thread per `reg query`; JUnique's internal
  server thread; `tasklist` per name check.
- Rust:
  - `CachedRegistry` is `Send + Sync` (`parking_lot::Mutex<HashMap>`; not held during OS calls).
  - Single instance: one accept thread `a3s-single-instance`, plus one `a3s-single-instance-conn`
    thread per incoming connection (short-lived), plus one client helper thread
    `a3s-single-instance-client` in `acquire`.
  - All threads are named via `std::thread::Builder`.
  - `ProcessProbe` and `SpecialFolders` impls are `Send + Sync`.
