## Scope

- Theme tokens: port `ThemePalette`, `ThemeMetrics`, `ThemeShadow`, `ThemeDefinition` and
  `ThemeLibrary` exactly, with every light and dark value. Map them onto `egui::Style` /
  `egui::Visuals` for both `egui::Theme`s. Add the `ThemeTokens` / `UiColors` accessors and the
  light/dark switching from `ThemeManager`. Persisting the theme is out of scope.
- Fonts: embed the 6 Geist TTFs and install them as egui `FontDefinitions`. Swing "bold" maps to
  Geist SemiBold, as `FontInstaller` does. Expose the Geist OFL text.
- Icons: add the `UiIcon` enum (42 SVGs), `IconTone` and `IconState`. Rasterize with resvg,
  recolor by tone/state like `FlatSVGIcon.ColorFilter`, apply Java's ×1.5 size scaling, cache
  textures per theme, and build the app icon from `app-rendered.png` (window/tray `IconData`).
- Widgets:
  - Tri-state check tree, generic over a model trait. Ports `CheckTreeCellRenderer`,
    `CheckTreeCellRendererRepository`, `IndeterminateIcon`, `MyRenderer` and
    `MyRendererRepository` icon defaults, plus the hotspot and Space-key toggling.
  - Labelled progress bar (`UiStyle.styleProgressBar` + `ContrastProgressBarUI`), with
    determinate and indeterminate modes and 4 tones.
  - Check list (`CheckBoxList`).
  - Primary button and icon+text button helpers.
  - Frames from `UiStyle`: section, panel, toolbar, status bar, pane divider, table scroll.
- Dialog bases: a modal or non-modal dialog with OK/Cancel/close semantics (`AbstractDialog`)
  and a progress dialog (`AbstractProgressDialog`).
- Constants from `UIConstants` that are not controller op codes.
- A `gallery` module showing every token, icon, font face, widget and dialog. It is used by
  `examples/demo.rs` (eframe) and by the kittest snapshot tests.

### Licensing check

- **Geist fonts:** SIL OFL 1.1, © 2024 The Geist Project Authors (`Geist-OFL.txt:1-5`). The file
  declares **no Reserved Font Name**. Bundling unmodified fonts inside a GPL-3.0 application is
  allowed if the copyright notice and licence travel with the binary. `a3s_ui` exposes the
  licence text as `GEIST_OFL_LICENSE` (B32). Shipping `Geist-OFL.txt` in installers is WP33's
  job. `OFL-1.1` is already in `deny.toml`'s allow list.
- **Icons:** `ICON_GUIDE.md` says nothing about licensing. `README.md:246` says *"Icons and
  branding assets sourced from the original Arma3Sync (GPLv3) project."* Both the Rust workspace
  and the Java project are GPL-3.0, so copying them is fine.
  - Inference, not verified: the 40 single-path 24×24 icons use the path data and Iconify export
    format of Google **Material Symbols** (Apache-2.0). For example, `check.svg` is Material
    Symbols "check". Apache-2.0 is GPL-3.0-compatible.
  - `app.svg` / `app-rendered.png` is the ArmA3Sync logo. `community.svg` is the "PzBrig21"
    community crest (its `<g id="PzBrig21">`): branding, not a generic icon.
  - The implementer adds `crates/viewer/a3s_ui/assets/icons/README.md`. It states that the icons
    come from Arma3Sync (GPL-3.0, Java commit b7753ce), that the glyphs appear to derive from
    Material Symbols (Apache-2.0), and that `app*` and `community.svg` are project/community
    branding.

- B2. **Metrics.** Both themes use the same values
  (`ui/theme/ThemeLibrary.java:35`, `:48`; field order `ui/theme/ThemeMetrics.java:8-19`):

  | Metric | Value |
  | --- | --- |
  | spacingXs | 4 |
  | spacingSm | 8 |
  | spacingMd | 12 |
  | spacingLg | 16 |
  | spacingXl | 24 |
  | spacingXxl | 32 |
  | radiusSm | 8 |
  | radiusMd | 12 |
  | radiusLg | 18 |
  | focusWidth | 1 |

  Store them as integers, as Java does, and convert with `as f32` where needed.
- B3. **Shadows.** `ThemeShadow` clamps opacity to [0, 1] and blurRadius to ≥ 0
  (`ui/theme/ThemeShadow.java:16-21`). Values (`ui/theme/ThemeLibrary.java:36`, `:49`):

  | Theme | Shadow | Colour | Opacity | yOffset | Blur |
  | --- | --- | --- | --- | --- | --- |
  | Light | low | `#1F2937` | 0.10 | 1 | 6 |
  | Light | medium | `#111827` | 0.14 | 4 | 16 |
  | Dark | low | `#000000` | 0.40 | 2 | 12 |
  | Dark | medium | `#000000` | 0.55 | 6 | 28 |

  Conversion to `epaint::Shadow`: `offset = [0, yOffset]`, `blur = blurRadius`, `spread = 0`,
  `color` = the RGB with alpha `(opacity * 255.0).round() as u8`. That gives light 26 / 36 and
  dark 102 / 140.
- B4. **Definitions.** `ThemeDefinition { id: "light" | "dark", dark: bool, palette, metrics }`
  (`ui/theme/ThemeDefinition.java:8-18`). `ThemeLibrary::light()`, `dark()` and
  `for_mode(dark)` return `&'static` definitions (`ui/theme/ThemeLibrary.java:10-26`).
- B5. **Default and fallback.** The default mode is **dark**:
  - `ThemeManager.currentTheme` starts as `ThemeLibrary.dark()` (`ui/ThemeManager.java:20`).
  - The `dark` preference defaults to `true` (`ui/ThemeManager.java:34`).
  - `ThemeTokens.theme()` falls back to dark (`ui/theme/ThemeTokens.java:21-24`).

  `ThemeMode::default() == Dark`. `a3s_ui::theme::current(ctx)` returns the definition that
  matches `ctx.theme()`.
- B6. **Applying and toggling.**
  - `a3s_ui::install(ctx)` installs fonts (B30), calls
    `ctx.set_style_of(Theme::Light, style_for(light))` and
    `ctx.set_style_of(Theme::Dark, style_for(dark))`, then calls
    `ctx.set_theme(ThemeMode::default())`.
  - `set_mode(ctx, mode)` calls `ctx.set_theme(...)`.
  - `toggle(ctx) -> ThemeMode` flips the mode and returns the new one
    (`ui/ThemeManager.java:41-58`).

  Icon textures are keyed by theme, so a toggle needs no explicit invalidation. This mirrors
  `Icons.invalidate()` in `ui/ThemeManager.java:29,52` and the cache key in
  `ui/icon/Icons.java:36,127`. `ThemeManager`'s `java.util.prefs` storage (node `ui.theme`, key
  `dark`, `ui/ThemeManager.java:18-19,33-35,43-48`) is **not** ported. The caller persists the
  mode.
- B7. **UiColors aliases** (`ui/UiColors.java:21-83`) become methods on `ThemePalette` or
  doc aliases:
  - `selection_background` = stateSelectionBg
  - `selection_foreground` = stateSelectionFg
  - `disabled_surface` = stateDisabledBg
  - All other aliases keep their names.
- B8. **ProgressTone.** `ProgressTone { Success, Info, Warning, Danger }` →
  statusSuccess / statusInfo / statusWarning / statusDanger
  (`ui/UiStyle.java:26-28,148-161`). `status_color(tone)` uses the same mapping
  (`ui/UiStyle.java:217-225`).

### Token → egui mapping

- B9. **Corner radii.** FlatLaf `*.arc` keys are **diameters**, so the egui corner radius is
  `arc / 2`:

  | Use | FlatLaf key | Token | egui radius |
  | --- | --- | --- | --- |
  | Widgets, windows, menus | `Component.arc` / `Button.arc` (`ui/theme/ThemeTokens.java:44-45`) | radiusMd 12 | **6** |
  | Text edits | `TextComponent.arc` (`:46`) | radiusSm 8 | **4** |
  | Scroll handle | `ScrollBar.thumbArc` (`:102`) | radiusMd 12 | **6** |

  Swing `LineBorder(c, 1, true)` borders in `UiStyle` (section, panel, progress) draw an outer

  | Update | `update` | yes | INFO |
  | Upload | `upload` | yes | ACCENT |
  | Warning | `warning` | yes | WARNING |

  `UiIcon::ALL: [UiIcon; 42]` is in this order. `file_name()` returns the stem.
  `svg_bytes()` returns `include_bytes!("../assets/icons/<stem>.svg")`.
- B18. **Tone and state colours** (`ui/icon/Icons.java:82-98`).
  - DISABLED → textDisabled.
  - SELECTED → stateSelectionFg.
  - Otherwise, by tone:

    | Tone | Colour |
    | --- | --- |
    | ACCENT | accentPrimary |
    | DANGER | statusDanger |
    | INFO | statusInfo |
    | MUTED | textSecondary |
    | SUCCESS | statusSuccess |
    | WARNING | statusWarning |
    | PRIMARY | **textPrimary** (not `iconDefault`) |
- B19. **When a tint applies** (`ui/icon/Icons.java:62-68`): only when `is_theme_aware() ||
  state == Disabled`.
  - A non-theme-aware icon in `Normal` **or `Selected`** state keeps its original SVG colours.
  - A non-theme-aware icon in `Disabled` state **is** recoloured.
  - Pure fn: `tint_for(palette, icon, state) -> Option<Color32>`.
- B20. **Recolouring.** `FlatSVGIcon.ColorFilter(c -> tone)` replaces every paint colour with
  the tone colour (`ui/icon/Icons.java:123-125`). Rust does the same after rasterization:
  - For every pixel with coverage alpha `a`: output = tone RGB with alpha
    `a * tone.a / 255`, built through `Color32::from_rgba_unmultiplied`.
  - The original SVG fill colours of theme-aware icons are therefore irrelevant. For example,
    `warning.svg` is filled `#D81B60` but renders statusWarning.
- B21. **Size scaling** (`ui/icon/Icons.java:24-25,108-121`):
  - If `size > 64`, return `size` unchanged.
  - Otherwise return `max(8, round_half_up(size * scale))`.
  - `scale` comes from Java system property `a3s.iconScale` with default **1.5**; a parse
    failure gives 1.5. Rust reads env var `A3S_ICON_SCALE` once (`OnceLock`), see Q3. A parse
    failure, non-finite value or value ≤ 0 gives 1.5.
  - Examples: 12 → 18, 16 → 24, 18 → 27, 5 → 8, 64 → 96, 65 → 65, 128 → 128, 256 → 256.
  - The result is in egui **points**. Java requests sizes 12 (tree), 16 and 18 (buttons), so
    callers must request the Java number and let `a3s_ui` scale it. ICON_GUIDE "Zustände &
    Skalierung" documents this as intentional.
- B22. **Rasterization and cache.**
  - Texture pixel size is `ceil(scaled_size * ctx.pixels_per_point())`. Use
    `egui_extras::image::load_svg_bytes_with_size(bytes, SizeHint::Size { w, h,
    maintain_aspect_ratio: true }, &usvg::Options::default())`, then recolour (B20) and
    `ctx.load_texture(name, image, TextureOptions::LINEAR)`.
  - Non-square sources (`community.svg` 827×1063) keep their aspect ratio and fit inside the
    square.
  - Cache key: `(icon, scaled_size, state, theme dark flag, pixels_per_point bits)`. The Java
    key is `(icon, size, state, themeId)` (`ui/icon/Icons.java:127`). Store the cache in
    `ctx.data_mut` (temp storage), keyed by a fixed `Id`.
  - `invalidate(ctx)` clears it (`ui/icon/Icons.java:58-60`).
  - API: `icon_image(ctx, icon, size, state) -> egui::Image<'static>`, sized to
    `scaled_size × scaled_size` points (aspect-fit for Community).
- B23. **App icon** (`ui/icon/Icons.java:40-56,70-80`; `ui/UIConstants.java:24-30`).
  - `UiIcon::App` is always drawn from `app-rendered.png`, decoded with
    `resvg::tiny_skia::Pixmap::decode_png`, which handles 16-bit, and scaled with bicubic
    filtering to the scaled size. This applies to images and to in-UI drawing (Q5).
  - `app_icon_data(size) -> egui::IconData` (straight RGBA) feeds viewport, window and tray
    icons.
  - Java sizes, after scaling (B21):
    - ICON / TRAYICON: `image(APP,16)` → **24 px**
    - PICTURE: `image(APP,256)` → 256 px
    - SOE: `image(COMMUNITY,256)` → 256 px
    - WARNING: `image(WARNING,128)` → 128 px
    - ACRE2_BIG / TFAR_BIG: `image(RADIO,256)` → 256 px
  - Expose `UiIcon::App` constants `WINDOW_ICON_SIZE = 16` and `PICTURE_SIZE = 256`. Callers
    pass the Java sizes.
- B24. **Tree default icons** (`ui/main/tree/MyRenderer.java:15,32-44`):
  - Size 12 (B21 makes it 18 pt).
  - Leaf → Package.
  - Directory → FolderOpen if expanded, else Folder.

  Sync tree override (`ui/repository/tree/MyRendererRepository.java:34-59`) is a model hook (B27):
  - Show Warning if the dir is updated, deleted or changed, or if any direct child is
    updated/deleted, or if any direct child dir is changed.
  - Otherwise show Package if `markAsAddon`.
  - Otherwise show the folder icon.

### Check tree (tri-state)

- B25. **Tri-state rule** (`ui/main/tree/CheckTreeCellRenderer.java:48-70`):
  - The checkbox shows `node.selected`.
  - For a directory **with a parent** (never the root): let `unselected` be the count of
    **direct** children with `!selected`. If `children != 0 && unselected != 0 && unselected
    < children`, the state is **Indeterminate**. This overrides `selected`: Java sets the box
    unselected and draws the indeterminate icon.
  - Leaves and the root are never indeterminate.
  - Java's variable `nbSelectedNodes` actually counts **un**selected children
    (`:59-63`, quirk). The logic above is the effective rule.
  - Pure fn: `CheckState::for_node(selected, is_leaf, has_parent, children_selected:
    impl IntoIterator<Item = bool>) -> CheckState`.
- B26. **Indeterminate mark** (`ui/main/tree/IndeterminateIcon.java:12-26`):
  - The normal (unchecked) checkbox is painted first.
  - Then a filled bar, x from `4` to `w − 4`, height `2`, vertically centred
    (`y = (h − 2) / 2`), colour **rgba(50, 20, 255, 200)**. The colour is hard-coded and
    theme-independent (quirk, see Q6).
  - Use egui's `Checkbox::indeterminate(true)` geometry if it matches. Otherwise paint the box
    yourself. AccessKit must report the toggled state as `Mixed`.
- B27. **Row content and colours.**
  - Each row is `[checkbox][icon][label]`.
  - The checkbox is on the left and the icon+label renderer fills the rest
    (`ui/main/tree/CheckTreeCellRenderer.java:73-76`).
  - Row height is `interact_size.y` = 24 (`Tree.rowHeight`).
  - The label colour comes from the model hook `label_color(key) -> Option<Color32>`:
    - Addons tree: missing or duplicated-selected leaves are red (`Color.RED` = `#FF0000`,
      `ui/main/tree/CheckTreeCellRenderer.java:41-46`).
    - Sync tree: deleted and not updated → blue (`Color.BLUE` = `#0000FF`); updated → red
      (`ui/repository/tree/CheckTreeCellRendererRepository.java:43-51`).

    These hard-coded colours belong to the callers (WP23/WP26). `a3s_ui` exposes
    `JAVA_RED` / `JAVA_BLUE` consts and the hook, without hard-coding them.
  - Selected-row highlight uses `visuals.selection`.
- B28. **Interaction.**
  - A primary click **inside the checkbox hotspot** (the checkbox's own width, measured from
    the row's indented left edge) emits `Toggled(key)`. A click elsewhere on the row only
    selects the row (`RowClicked(key)`) (`ui/main/AddonsPanel.java:503-509`;
    `ui/repository/DownloadPanel.java:580-585`).
  - **Space** on the selected row emits `Toggled(key)`
    (`ui/main/AddonsPanel.java:526`; `ui/repository/DownloadPanel.java:603`).
  - Double-click emits `RowDoubleClicked`. Secondary click emits `ContextMenu(key)` and
    selects the row. Expanding or collapsing a row emits `Expanded(key, bool)`.
  - The widget never mutates the model. Propagation (select all descendants or ascendants) is
    caller logic (`ui/main/AddonsPanel.java:877-918`, WP23).
  - Expansion state lives in egui memory, keyed by `(tree id, key)`.
    `CheckTree::set_expanded(ctx, id, key, bool)` and `expand_all(ctx, id, keys)` support the
    "Expand All" checkbox.
  - Rendering must be virtualised. Flatten the visible (expanded) rows and draw them with
    `ScrollArea::show_rows`, so trees with tens of thousands of nodes stay fast.

### Check list

- B29. **CheckList** (`ui/CheckBoxList.java`):
  - A vertical list of `(label, checked)` items.
  - Pressing a row toggles its `checked` flag **anywhere on the row** (`:24-35`).
  - Single selection: the last pressed row is highlighted with selection colours
    (`:37,70-71`).
  - `checked_labels(items) -> Vec<String>` and `checked_indexes(items) -> Vec<usize>` keep
    list order (`:40-63`).
  - The list mutates `&mut [CheckItem]` directly. It is a plain value list, unlike the tree.
  - Java toggles on `mousePressed` for **any** mouse button (quirk). Rust toggles on a
    primary click only (local-only, Q7).

### Fonts

- B30. **Install.**
  - Start from `FontDefinitions::default()`. Insert the 6 Geist faces as
    `FontData::from_static(include_bytes!(..))` named `"Geist-Regular"`, `"Geist-Italic"`,
    `"Geist-Medium"`, `"Geist-SemiBold"`, `"Geist-Bold"`, `"Geist-BoldItalic"`. Java registers
    all six (`ui/FontInstaller.java:54-60,87-109`).
  - `FontFamily::Proportional` puts `Geist-Regular` **first**, keeping egui's defaults as glyph
    fallback (`ui/FontInstaller.java:62,111-133`).
  - Each face also gets a named family `FontFamily::Name("Geist-<Face>")` = `[that face] +
    proportional fallbacks`.
  - `Monospace` stays egui's default. Java maps even `TextArea.font` to Geist
    (`ui/FontInstaller.java:64-69`), so callers use proportional text unless they explicitly
    want monospace.
- B31. **Face mapping** (`ui/FontInstaller.java:159-162,557-587`):

  | Swing style | Geist face |
  | --- | --- |
  | plain | Regular |
  | italic | Italic |
  | **bold** | **SemiBold** |
  | bold+italic | BoldItalic |

  Geist Medium and Bold are registered but never selected by Java (quirk). They are exposed
  in `FontFace` for later use.
  - `fonts::font_id(FontFace, size) -> FontId`.
  - `FontFace::for_swing_style(bold, italic)` encodes the table.
- B32. **Sizes and licence.**
  - The base size is FlatLaf's `defaultFont` size, which varies by platform; the fallback is
    12 (`ui/FontInstaller.java:145-157`). Rust uses one constant `BODY_SIZE = 13.0` (Q2).
  - Text styles:

    | Style | Size and face |
    | --- | --- |
    | Body | 13 Regular |
    | Button | 13 Regular |
    | Small | 11 Regular (*local*) |
    | Heading | 16 SemiBold (*local*) |
    | Monospace | 12 (*local*) |
  - `GEIST_OFL_LICENSE: &str = include_str!("../assets/fonts/Geist-OFL.txt")`.
- B33. **TTF sanity.** Java rejects font data under 10 KiB or without an SFNT signature
  (`00 01 00 00` or `OTTO`) after skipping BOM and whitespace
  (`ui/FontInstaller.java:43-45,298-312,391-419`). Rust embeds the fonts, so a test asserts
  the same properties on the embedded bytes instead of checking at runtime.

### Progress bar

- B34. **Percent text** (`ui/UiStyle.java:181-188`):
  - `range = max − min`.
  - `percent = if range <= 0 { 0 } else { floor(((value − min) as f32 * 100.0) / range as
    f32 + 0.5) }`. This is Java `Math.round(float)`.
  - Text is `format!("{percent}%")`.
  - `value` is first clamped to `[min, max]`, as Swing's `DefaultBoundedRangeModel` does.
  - Pure fn `percent_text(value, min, max) -> String`.
- B35. **Geometry** (`ui/UiStyle.java:38,72-89,163-168`):
  - Default height **24**. `AbstractProgressDialog` overrides it to **18**
    (`ui/AbstractProgressDialog.java:72-73`).
  - Outer 1 px borderMuted line, radius 1 (B9), with inner padding of spacingXs (4) top/bottom
    and spacingSm (8) left/right.
  - Fill = tone colour from the inner rect's left edge, width `round(inner_w × fraction)`.
  - Default tone INFO.
- B36. **Track.** Java sets `background = surfaceMuted` (`ui/UiStyle.java:80,140-142`) but
  also `setOpaque(false)` (`:75`). `BasicProgressBarUI` therefore never paints the track, and
  the parent surface shows through (quirk). Rust paints the inner track with surfaceMuted
  (Q1, needs approval).
- B37. **Halo text** (`ui/components/ContrastProgressBarUI.java:37-45,54-71`):
  - The text is painted 8 times in **rgba(0, 0, 0, 220)** at offsets (dx, dy) ∈ {−1, 0, 1}²
    \ {(0, 0)}, then once in **white**.
  - Font: SemiBold body size (Swing `deriveFont(BOLD)`, `ui/UiStyle.java:76-78`, + B31).
  - Horizontal: `x = inner.x + round((inner.w − text_w) / 2)`.
  - Vertical: baseline at `inner.y + (inner.h + ascent) / 2 − 2`.
  - The text is clipped to the widget rect, not the inner rect.
- B38. **Indeterminate mode.**
  - Used by 5 Java progress dialogs, e.g. `ui/repository/dialogs/progress/ProgressConnectionAsAdminDialog.java:43`.
  - Draw a tone-coloured box about 1/6 of the inner width that bounces left↔right over about
    4 s, and request a repaint while visible.
  - Java falls back to Basic's non-halo text painting here and shows the stale `"N%"` string
    (quirk). Rust shows the caller's optional text with halo, or no text (Q1).

- None. This WP does not touch the wire.

### Java quirks that are preserved anyway (local, visual fidelity)

- Icons are ×1.5 the requested size (B21).
- Swing bold maps to Geist SemiBold. Medium and Bold are never selected (B31).
- Non-theme-aware icons are tinted when Disabled but not when Selected (B19).
- PRIMARY tone uses textPrimary; the `iconDefault` and `windowBackground` tokens are defined but
  never used (B18, `ui/theme/ThemeTokens.java` never reads them).
- The `shadowLow`, `shadowMedium` and `radiusLg` tokens are unused in Java. They are mapped
  anyway (B10).
- The indeterminate bar colour is the hard-coded rgba(50, 20, 255, 200) (B26, Q6).
- The tri-state rule looks only at direct children and never applies to the root (B25).
- `Close` (window ✕) is distinct from `Cancel` in `Dialog`. In `ProgressDialog` both mean
  Cancel (B40/B41).
- Hard-coded red/blue label colours are exposed as `JAVA_RED` / `JAVA_BLUE` for callers (B27).

### Java quirks that may be dropped (local-only; needs an approved deviation)

- The progress track is never painted (B36). Proposed: paint surfaceMuted. **Q1**
- Indeterminate bars show a stale `"N%"` without halo (B38). Proposed: caller text or none.
  **Q1**
- FlatAnimatedLafChange snapshot animation on theme toggle (`ui/ThemeManager.java:50,55`) is
  dropped. The theme switches instantly.
- FontInstaller's external-directory, classpath and BOM fallback search
  (`ui/FontInstaller.java:173-253,391-419`) and its debug listing (`:474-525`) are dropped.
  Fonts are embedded.
- `CheckBoxList` toggles on any mouse button press. Rust uses primary click only. **Q7**
- Escape closes dialogs. Java has no Escape binding. **Q8**
- `UiIcon::App` drawn in-UI uses the PNG rather than the SVG. **Q5**

### Errors, cancellation, progress

- All assets are embedded with `include_bytes!` / `include_str!`. A decode or rasterize failure
  is an invariant violation, guarded by tests A7–A9. Use `expect("embedded asset <name> is
  valid")`, never `unwrap()`. Java instead logs a warning and skips the font or icon
  (`ui/FontInstaller.java:452-454`, `ui/icon/Icons.java:77-79`).
- Widgets do no I/O and spawn no threads. The progress widgets only display state. Cancelling
  is reported as an action value, and the caller acts on it.

### Concurrency

- Everything runs on the UI thread. Java's `ConcurrentHashMap` icon cache
  (`ui/icon/Icons.java:23`) becomes per-`Context` temp storage. No locks are needed; if one is
  ever needed, use `parking_lot`.

## Open questions

- Q1. Progress-bar track and indeterminate text (B36, B38). Java never paints the
  surfaceMuted track (opaque=false + BasicProgressBarUI), and indeterminate bars show a stale
  `"N%"` without halo. **Proposed default:** paint the inner track with surfaceMuted, matching
  `UiStyle`'s evident intent. In indeterminate mode show the caller's optional text with halo,
  else no text. Needs an approved deviation. Decision:
- Q2. Base font size. Java inherits FlatLaf's per-OS `defaultFont` (fallback 12).
  **Proposed default:** `BODY_SIZE = 13.0` points on every OS, which is FlatLaf's macOS and
  typical Linux size. Decision:
- Q3. Icon scale override. Java reads system property `a3s.iconScale` (default 1.5).
  **Proposed default:** env var `A3S_ICON_SCALE`, read once, default 1.5. Do not expose it as a
  user setting. Decision:
- Q4. Disabled widgets. egui fades disabled widgets by `disabled_alpha` and cannot use a
  dedicated disabled text colour (`Button.disabledText` = textDisabled). **Proposed default:**
  `disabled_alpha = 0.5`. textPrimary at 50 % over surface lands within a few RGB steps of
  textDisabled in both themes. Disabled icons still use the exact textDisabled tint (B19).
  Decision:
- Q5. In-UI rendering of `UiIcon::App`. Java's `Icons.icon(APP)` renders `app.svg`, whose logo
  is an embedded base64 PNG. resvg without `raster-images` drops that image, and Java callers
  only ever use `image(APP)`, which reads `app-rendered.png`. **Proposed default:** always
  render App from `app-rendered.png` and do not enable resvg `raster-images`, which would pull
  gif/webp/jpeg decoders. Decision:
- Q6. Indeterminate checkbox mark colour. Java hard-codes rgba(50, 20, 255, 200) with a
  `// TEST:` comment that suggests the theme foreground was intended. **Proposed default:**
  keep the Java colour exactly (no deviation). Switching to accentPrimary later needs an
  approved deviation. Decision:
- Q7. `CheckList` toggles on any mouse button press. **Proposed default:** primary click only,
  so a right-click does not toggle. Needs an approved deviation. Decision:
- Q8. Escape key. Java dialogs have no Escape binding. **Proposed default:** Escape returns
  `DialogAction::Close` (`Cancel` for `ProgressDialog`), which is egui `Modal` convention, and
  clicking the backdrop does nothing. Needs an approved deviation. Decision:
- Q9. Dialogs as in-app windows. Java dialogs are separate OS windows (JDialog).
  **Proposed default:** in-app `egui::Modal` / `egui::Window`, which works with kittest, has
  no multi-viewport issues on Wayland and needs no per-dialog icon. WP22 may still open
  specific dialogs as OS viewports. Decision:
- Q10. Snapshot tests in CI. GitHub runners have no Vulkan ICD, and `rust.yml` is not owned
  here. **Proposed default:** snapshot tests are `#[cfg(target_os = "linux")]` and always on
  locally through gate.sh. The orchestrator adds `sudo apt-get install -y
  mesa-vulkan-drivers` (+ `VK_ICD_FILENAMES`) to CI in a follow-up. Until then CI may need
  `--skip snapshot`. Decision:
- Q11. Size limit. The Java line count of about 2.5k exceeds the ~1.5k guideline, but 615 of
  those lines (FontInstaller) shrink to about 60 Rust lines. **Proposed default:** no split;
  the expected Rust total is about 2.3k src. If a split is required: WP20a = theme + fonts +
  icons + frames (`src/{theme,fonts,icon,frames,consts}.rs`, assets) and WP20b = widgets +
  dialogs + gallery + example (`src/{widgets,dialog,gallery}/**`, `examples/**`), with WP20b
  depending on WP20a. Decision:
