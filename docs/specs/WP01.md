## Owned paths

- `tools/java_fixture_harness/**`
- `crates/build/a3s_dev_tools/**`

`tests/fixtures/**` is **not** owned. Only the orchestrator writes there, by running
`cargo run -p a3s_dev_tools -- regen-fixtures --write-fixtures`. The implementer generates into
temporary directories only.

## Scope

- `tools/java_fixture_harness/`: Java sources (`src/harness/**`), third-party stubs (`stubs/**`),
  `build.sh`, `run.sh`, `README.md` and `.gitignore`. Together they compile the **minimal** set of
  Arma3Sync Java sources with plain `javac` (no Gradle, no downloads), with two documented
  source patches that make the output deterministic.
- Deterministic fixture generation into `<out>/{java_local,java_built,java_presets,java_roundtrip}/`,
  `<out>/java_descriptors.txt` and `<out>/java_harness_manifest.txt`.
- Cross-check commands for later verifiers (WP04, WP05, WP11, WP12, WP14, WP18):
  - `verify`: Java reads Rust-produced files through Arma3Sync's own readers;
  - `dump`: a canonical JSON view of a Java object graph;
  - `roundtrip`: Java read plus upload-style re-serialization;
  - `selftest`.
- The Rust wrapper `a3s_dev_tools`:
  - a library API (`java_harness`, `fixtures`) usable as a dev-dependency by any crate;
  - a binary with the subcommands `regen-fixtures`, `java-verify`, `java-dump` and
    `java-roundtrip`.
- Resolves the PROVISIONAL items listed under "Pre-measured results": F-1, WP12 Q3, WP11 Q3/Q11
  and WP18 B35. Two spec errors found along the way (WP11 B56/WP12 B63 and WP04 SealedObject)
  are raised under Open questions.

## Behaviour contract

### Build (`tools/java_fixture_harness/build.sh`)

- B1. **Java source root.** Resolution order:
  1. `$A3S_JAVA_SRC`;
  2. `<repo>/java_version/Arma3Sync/src/main/java`;
  3. `$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")/java_version/Arma3Sync/src/main/java`.

  Option 3 is required because `java_version/` is gitignored, so agent worktrees under
  `.claude/worktrees/*` do not contain it (checked: none of the current worktrees has it). If no
  root exists, exit 4 with `java_fixture_harness: Java sources not found (set A3S_JAVA_SRC)`.
  The script never writes below the Java source root.
- B2. **JDK.** `build.sh` and `run.sh` start with `source "$REPO/scripts/java_env.sh"`. If sourcing
  fails, or `javac -version` / `java -version` is not major version **25**, exit 4 with a
  one-line message naming `A3S_JAVA_HOME`. `JAVA_TOOL_OPTIONS` makes the JVM print
  `Picked up JAVA_TOOL_OPTIONS…` on stderr. All parsing is done on stdout only.
- B3. **Stub.** `stubs/org/apache/commons/io/FileUtils.java` declares only
  `public static long sizeOf(File file)`. It mirrors commons-io 2.15 (bytecode of
  `resources/lib/commons-io-2.15.0.jar`, checked with `javap`):
  1. `Objects.requireNonNull(file, "file")`;
  2. if `!file.exists()`, throw `IllegalArgumentException("File system element for parameter 'file' does not exist: '" + file + "'")`;
  3. if it is a directory, return the recursive sum of the regular-file lengths;
  4. otherwise return `file.length()`.

  No jar is downloaded or put on the classpath (Q1).
- B4. **Patched copies.** These are harness-only changes, not Java behaviour. `build.sh` copies
  `dao/repository/RepositoryBuildProcessor.java` to `build/patched-src/…` and applies:
  - **P1** `new Date()` → `harness.HarnessClock.now()`. Exactly **3** replacements
    (`:153`, `:184`, `:200`).
  - **P2** `<ident>.listFiles()` → `harness.HarnessFs.sorted(<ident>.listFiles())`. Exactly **2**
    replacements (`:116`, `:475`).

  If a replacement count differs, the build fails with `patch P<n>: expected <k> got <m>`. No
  other file is patched. `RepositoryBuildProcessor` is not `Serializable`, so patching cannot
  change any descriptor or computed UID.
  - `HarnessClock.now()` returns a **new** `Date(millis)` on every call. This matches Java,
    which creates a separate `Date` for the serverinfo and for each changelog. `millis` is set
    per build step.
  - `HarnessFs.sorted(File[])` sorts in place by `File.getName()` with `String.compareTo` and
    tolerates `null`. This makes Java's scan order equal to Rust's (WP11 Q7).

  Verified while writing this spec: javac resolves the patched copy first when
  `build/patched-src` is listed first on `-sourcepath`, and `javap` shows 5 `harness/Harness*`
  references.
- B5. **Compile.** One `javac` call:
  - flags: `--release 25 -encoding UTF-8 -proc:none -implicit:class -nowarn`;
  - `-sourcepath build/patched-src:<java src>:stubs:src`;
  - `-d build/classes`;
  - explicit files: every `src/harness/**/*.java`, plus every `.java` under `<java src>/fr/soe/a3s/domain`
    and `<java src>/fr/soe/a3s/constant`, so the descriptor dump sees classes nothing references.

  Everything else is pulled in implicitly. Classes must not be listed explicitly from the original
  tree when a patched copy exists.
- B6. **Variant classes** (historical stream shapes, Q7). Each variant copies one current domain
  source into `build/variant-src/<v>/`, applies one count-asserted edit, and compiles it against
  `build/classes` into `build/variants/<v>/`. That output must contain only that class and its
  inner classes. Edits:

  | Variant `<v>` | Class | Edit | Provenance |
  | --- | --- | --- | --- |
  | `repository_pre_connections` | `domain/repository/Repository.java` | add `transient` to the `numberOfRepositoryCheckConnections` and `parallelUploadConnections` declarations (2) | fields added by b3863e6 / f49736d |
  | `prefs_pre_github` | `domain/Preferences.java` | `private Boolean preferGitHubUpdates;` → `private transient Boolean preferGitHubUpdates;` (1) | added by df555cc |
  | `cfg_with_aia` | `domain/configration/Configuration.java` | insert `private AiAOptions aiaOptions = new AiAOptions();` before `private Proxy proxy = new Proxy();` (1) | `b38a64b^:src/fr/soe/a3s/domain/configration/Configuration.java:28` |
  | `treeleaf_pre_workshop` | `domain/TreeLeaf.java` | add `transient` to `workshopId` and `dlcAppId` (2) | `222dd5e^` has neither field |

  Marking a field `transient` removes it from the stream descriptor but keeps the code compiling.
  The UIDs are declared, so the streams are valid for current Java readers.
- B7. **Incremental.**
  - `build/stamp` holds the SHA-256 of: the sorted `src/**` and `stubs/**` contents, `build.sh`,
    the patched Java input files, `javac -version`, and the Java commit
    (`git -C <java src>/../../.. rev-parse --short HEAD`, i.e. the `Arma3Sync` checkout, or `unknown`).
  - If the stamp matches, the build is skipped and prints `up to date`.
  - `build.sh --clean` deletes `build/` first.
  - `tools/java_fixture_harness/.gitignore` contains `/build/`.
- B8. Exit codes for `build.sh`: 0 ok, 3 compile or patch failure, 4 missing JDK or Java sources.

### Runtime (`run.sh`, `harness.Main`)

- B9. `run.sh <command> [args]` does the following:
  - it sources `java_env.sh`, checks major version 25, and runs `build.sh` if `build/stamp` is
    missing or stale;
  - it then `exec`s `java <FLAGS> -cp build/classes harness.Main "$@"`.

  `FLAGS` are:
  - `-Duser.timezone=UTC -Duser.language=en -Duser.country=US`;
  - `-Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8 -Djava.awt.headless=true`;
  - `-Da3s.harness.home=<tools/java_fixture_harness abs>`;
  - `-Da3s.harness.javaCommit=<short sha>`.

  Fixtures are therefore independent of the host time zone and locale. `HeaderMaker`'s `MTime`
  uses the default time zone (`jazsyncmake/HeaderMaker.java:111-116`).
- B10. **Stdout protocol.** At startup `Main` saves `System.out` as the protocol stream, then calls
  `System.setOut(System.err)`. Arma3Sync code prints progress and warnings with
  `System.out.println`, for example `RepositoryBuildProcessor.java:431, 439`,
  `RepositoryZsyncProcessor.java:55`, `ZipDAO.java:31`; all of it goes to stderr. Only protocol
  lines and JSON go to the saved stream.
- B11. **Exit codes** (`Main` and `run.sh`):
  - 0 success;
  - 1 verification failure (`verify`, `selftest`);
  - 2 usage error;
  - 3 internal error (stack trace on stderr);
  - 4 JDK or Java sources missing.
- B12. **Child JVMs.** Every fixture run that needs fresh Java statics (DAO maps, path constants
  initialized once from system properties) runs in a child JVM:
  - executable from `ProcessHandle.current().info().command()`;
  - classpath `build/variants/<v>:build/classes` for variant runs, otherwise the parent's
    classpath;
  - the B9 flags, plus `-Duser.home=<work>/home`,
    `-Da3s.configPath=<work>/config`, `-Da3s.dataPath=<work>/data`,
    `-Da3s.cachePath=<work>/cache` (`ApplicationPaths.java:197-201`), or for the portable
    layout `-Da3s.portable=true -Da3s.installationPath=<root>`
    (`ApplicationPaths.java:24-30, 83-155, 241-243`);
  - main class `harness.Main child-<kind> …`;
  - child stdout and stderr both go to the parent's stderr.

  A non-zero child exit fails the parent with exit 3. Properties are set before any
  `DataAccessConstants` field is touched (`dao/DataAccessConstants.java:6-16`).
- B13. **Work directory.** `--work <dir>` defaults to `Files.createTempDirectory("a3s-harness")`
  and is deleted at the end unless `--keep-work`. No absolute work path may appear in any output
  file. `generate` checks this by searching every generated text and JSON file for the work path
  string and fails (exit 3) on a hit.

### Descriptor dump (`descriptors`, `<out>/java_descriptors.txt`)

- B14. The class set is every class file under `build/classes/fr/soe/a3s/domain/**` and
  `…/constant/**` (found by directory scan, not a hand list) whose class is `Serializable`,
  including enums. Fixed JDK classes are added: `java.lang.Boolean`, `java.lang.Enum`,
  `java.util.ArrayList`, `java.util.Date`, `java.util.HashMap`, `java.util.HashSet`,
  `java.util.TreeSet`, `javax.crypto.SealedObject` and `[B`.
  - Classes are loaded with `Class.forName(name, false, loader)`.
  - Output is sorted by class name (`String.compareTo`).
  - The file starts with a header comment line:
    `# java_fixture_harness descriptors; JDK <java.runtime.version>; Java commit <sha>`.
- B15. Per class:
  - **UID and flags.** Write the `Class` object with a fresh `ObjectOutputStream` and parse the
    first `TC_CLASSDESC`: UTF name, `long` UID, `byte` flags. Both are exactly what Java puts
    on the wire.
  - **Fields.** From `ObjectStreamClass.lookupAny(c).getFields()`, which is already in wire
    order: primitives first, then by name.
  - **`declared` / `computed`.** `declared` if the class has a `static final long
    serialVersionUID` field, else `computed`.
  - **Super.** The nearest `Serializable` superclass, or `-`.
  - **Enums.** Constants in ordinal order.
  - **Transient.** Instance fields marked `transient`, sorted, from reflection.
- B16. Exact text format. Two-space indentation, one blank line between classes, `\n` line
  endings, trailing newline:

  ```
  class fr.soe.a3s.domain.AutoConfig
    uid 6424431620520340750 computed
    flags 0x02 SC_SERIALIZABLE
    super -
    field L favoriteServers Ljava/util/List;
    field L profiles Ljava/util/List;
    field L repositories Ljava/util/List;
  ```

  - Field line: `field <typecode> <name> <type string>`. Primitive fields have no type string
    (`field J lastModified`). Array fields use type code `[` (`field [ encryptedContent [B`).
  - Optional lines: `enum A,B,C` and `transient a,b`, present only when non-empty.
  - Flag names, in this order: `SC_WRITE_METHOD` 0x01, `SC_SERIALIZABLE` 0x02,
    `SC_EXTERNALIZABLE` 0x04, `SC_BLOCK_DATA` 0x08, `SC_ENUM` 0x10, separated by `|`.
- B17. `descriptors` prints the same text to stdout. `generate` writes it to
  `<out>/java_descriptors.txt`.

### Canonical JSON dump (shared by `dump`, `verify --dump-dir`, fixture `dumps/`)

- B18. `harness.JsonDump` walks an object graph and writes UTF-8 JSON. Key order is fixed as
  shown, there is no whitespace except `\n` after the root, and strings use JSON escaping with
  `\uXXXX` for control characters. Identity mode:
  - **References.** Every non-null object gets `"id":N` (1-based, depth-first order of first
    visit, the same order `ObjectOutputStream` uses). A repeat visit is written as `{"ref":N}`.
    Strings are objects too: `{"str":"…","id":N}`. String sharing (back-references) is
    therefore visible.
  - **`fr.soe.a3s.*` objects.** `{"class":FQCN,"id":N,"fields":{…}}`. Fields come from
    `ObjectStreamClass.lookup(c).getFields()` for each serializable class in the hierarchy,
    superclass first, read by reflection. Primitives are JSON numbers or booleans. A `double` is
    written with `Double.toString`. `null` is `null`.
  - **Enums.** `{"enum":FQCN,"name":"…","id":N}`.
  - **`Boolean`, `Integer`, `Long`, `Double`.** `{"class":…,"value":…,"id":N}`.
  - **`Date`.** `{"class":"java.util.Date","time":<ms>,"id":N}`.
  - **`List`.** `{"class":…,"id":N,"elements":[…]}` in iteration order.
  - **`Set`.** The same shape, in iteration order.
  - **`Map`.** `{"class":…,"id":N,"entries":[[k,v],…]}` in iteration order.
  - **Any other class.** Error `unsupported class <name>` (exit 3).
- B19. Semantic mode (`--semantic`) drops `id` and `ref`: a repeated object is written in full
  again. Cycles (`parent` back-pointers) are written as `{"parent":true}` when the value is the
  object currently being expanded one level up. Strings become plain JSON strings. Set elements
  and map entries are sorted by their semantic JSON text, so iteration order and capacity do not
  matter. Two semantic dumps are equal exactly when the object graphs are value-equal.

### Java quirks to preserve (wire-visible; the fixtures capture them, the harness must not "fix" them)

- Files whose names contain `.zsync`, `.pbo.zip` or `.a3s` are left out of the sync
  (`RepositoryBuildProcessor.java:487-489`).
- Empty directories are pruned from the sync (`:436-437`).
- A directory is an addon when it has a child named `addons` in any case (`:478-480`).
- Hidden paths come from the first `indexOf` of `/<main folder>` (`:166-167`).
- `revision` starts at 1 and only increments on a content change (`:150-151`).
- Changelogs keep at most 10 entries (`:196-198`).
- Events keep only addon keys present in the new sync and DLC keys (`:262-270`). Userconfig is
  copied with `putAll` (`:271`).
- An empty file has SHA-1 `"0"` (`FileAccessMethods.java:238-240`).
- The SHA-1 cache is keyed on the absolute path and `lastModified` only (`RepositorySHA1Processor.java:113-127`).
- zsync `MTime` is in the JVM default time zone (`HeaderMaker.java:111-116`). The harness pins UTC.
- `transformDTO2Event` drops userconfig; only `saveEvent` sets it (`ObjectDTOtransformer.java:361-376`,
  `RepositoryService.java:1155-1186`).

### Java quirks that may be dropped (local-only)

- Zip entries carry the current time (`ZipDAO.java:135`). The harness normalizes them (B32), and
  Rust may use any time (D-2).
- `ProfileDAO.write` uses a single-level `mkdir` (`:76`). The harness orders writes around it.

### Errors, cancellation, progress

- Every failure in the harness is fatal: exit 3 with a stack trace, except `verify`/`selftest`
  failures (exit 1). There are no retries.
- An exception from a Java service observer (`ObserverError.error`) during a build aborts the
  generation with exit 3 and the collected exceptions on stderr.
- Cancellation: none (dev tool). Progress: build observers write `text`/`count` lines to stderr.

### Concurrency

- Java's own pools run as in production (SHA-1: `min(8, cpus)` threads,
  `RepositorySHA1Processor.java:83-85`; zip/delete: `cpus`; zsync: 1). Outputs do not depend on
  them (B46).
- Child JVMs run **sequentially**. The Rust wrapper runs one harness process at a time per call.
  Concurrent callers must use distinct `--out`/`--work` dirs. `build/` is shared: `build.sh`
  takes `flock build/.lock`.

- R3, WP11 B56 / WP12 B63: the **`HashMap.readObject` formula in both specs is wrong for JDK 25.**

  - `cap = dc < 16 ? 16 : tableSizeFor((int) dc)`;
  - `threshold = (int)(cap * lf)`.

  The specs use the pre-JDK-19 `fc = n/lf + 1.0f`. The results differ when `n/lf` is an exact

  - n=24: 32 vs 64;
  - n=48: 64 vs 128.

  - after a round trip: n=1, 6, 12 → 16; n=13, 24 → 32; n=25 → 64;
  - with `putAll` into an empty map (`putMapEntries` `:503-511`): 1→2, 2→4, 3→4, 4..6→8,
    7..12→16, 13..24→32.

  The putAll branch of B56 is correct. See Q5.
- R4, WP18 B35: the Java exporter run on the B35 inputs (preset `Event <HS13>`, `@gm`, `WS`)
  wrote a file **byte-identical** to the golden in `docs/specs/WP18.md`, including the trailing
  `\n`. The golden is confirmed.
- R5, WP11 Q3 (from code): with the GUI path, `FavoriteServer.repositoryName` **is the same
  `String` instance** as `Repository.name`:
  - `setFavoriteServerToAutoconfig` stores the passed name (`RepositoryService.java:1279`);
  - the GUI passes the DTO name, which is the repository's own reference
    (`ObjectDTOtransformer.java:222`);
  - the sharing is kept across restarts, because the encrypted `Repository` stream preserves
    back-references.

  `AutoConfig`'s field order is `favoriteServers`, `protocole`, `repositoryName`, so Java writes
  `repositoryName` as a **back-reference** to the first favorite's string. B29 reproduces this.
  The `java_built` dumps make it visible. See Q4.
- R6, WP11 Q11: within one JVM, every empty file's SHA-1 is the interned literal `"0"`, written

  The step 3 sync therefore contains **two** distinct `"0"` objects (`empty.txt`/`empty2.txt`
  vs `new_empty.txt`). `java_built/*/3_modified/dumps/sync.json` documents this.
- R7, WP04 (new finding): the `javax.crypto.SealedObject` descriptor fields are
  - `[ encodedParams [B`;

  - `L paramsAlg Ljava/lang/String;`;
  - `L sealAlg Ljava/lang/String;`.

  The array fields use type code **`[`**, not `L` as WP04's Wire-compat notes say. The second
  `[B` type string is a back-reference (`71 00 7e 00 01`). Measured stream for `"hello"`:
  `encodedParams` null, `paramsAlg` null, `sealAlg` `"AES"`. See Q6.

## Wire-compat notes

- Classes read and written: every `fr.soe.a3s.domain.**`/`constant.**` serializable class, plus
  `ArrayList`, `HashMap`, `HashSet`, `TreeSet`, `Date`, `Boolean`, `SealedObject` and `[B`. Their
  descriptors are exactly what `java_descriptors.txt` lists (B14-B16). The harness defines no
  serialized class of its own. Harness classes live in package `harness.*`, outside the
  `fr.soe.a3s.` allow-list, so they would be rejected if they were ever serialized by mistake.
- Shared instances in the fixtures are whatever Java produces. The identity-mode dumps make every
  back-reference explicit (strings, `Boolean`, `parent`, enum constants), so Rust encoders can be
  checked against them.
- Byte identity, per output:
  - `java_built/**/.a3s/*`, `uploaded/*`, `java_local/**` gz files: the **decompressed** stream is
    the contract, plus the gzip header (WP11 Q2). Deflate bytes may differ between zlib builds;
