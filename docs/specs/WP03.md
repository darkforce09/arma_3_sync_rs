## Scope

- `constants`: Rust ports of every enum in `J/constant/*` that isn't ported yet (descriptions,
  values, `getEnum` parsers with their quirky fallbacks, Java constant names).
- `local`: plain-data types for the client's local state: `Repository`, `Profile` (+ the addon
  group tree `TreeDirectory`/`TreeLeaf`/`TreeNode`), `Preferences`, `Configuration` and everything in
  `domain/configration` (`LauncherOptions`, `ExternalApplication`, `AcreOptions`, `Acre2Options`,
  `TfarOptions`, `RptOptions`, `BikeyExtractOptions`, `Proxy`), `Addon`, `FileAttributes`. All of
  them derive serde for the new TOML store (WP04).
- Java-getter semantics as methods (connection clamps, partial-transfer inversion, null-normalising
  getters), plus `AbstractProtocoleFactory`/`AbstractProtocole.checkData`/`getHostUrl` semantics as
  free functions over the existing `a3s_types::Protocol`.
- **Lenient legacy decoders** (by field name, missing and extra fields allowed, any UID) for
  `a3s.cfg`, `a3s.prefs`, `*.a3s.profile`, the decrypted inner stream of `*.a3s.repository`, and
  `export.a3s.autoconfig`. The one-time importer (WP04) and autoconfig import (WP05/WP14) use them.
- **Exact Java encoders** for the classes in `export.a3s.autoconfig` (`domain.AutoConfig`,
  `Profile`, `TreeDirectory`, `TreeLeaf`, `ModsetType`, `Repository`), plus a descriptor lock
  test for them. WP05 adds gzip and file I/O.
- Port `T/domain/RepositoryUploadSettingsTest` and `T/domain/ProtocolSupportTest`.

- B3. `parallel_upload_connections()` returns `min(raw, 10)` if `raw > 0`, else `4` (`:356-360`).
  `set_parallel_upload_connections(v)` fails if `v < 1` with message
  `"Parallel upload connections must be positive."`, else stores `min(v, 10)` (`:362-367`).
- B4. `repository_check_connections()` returns `min(raw, 4)` if `raw > 0`, else `4` (`:385-390`).
  The setter fails if `v < 1` with `"Repository check connections must be positive."`, else
  stores `min(v, 4)` (`:392-398`).
- B5. `use_partial_file_transfer() == !no_partial_file_transfer`. The setter stores the inverse
  (`:332-346`). The persisted field is the negative one (`noPartialFileTransfer`).
- B6. `number_of_client_connections == 0` means "unset". On the next metadata update the
  caller copies the server's `ServerInfo.numberOfConnections` into it
  (`service/RepositoryService.java:264-266`; that logic belongs to WP07). The raw value is stored
  without normalisation.
- B7. `number_of_connections` (build setting) has no getter normalisation. It goes straight into
  `.a3s/serverinfo` (`dao/repository/RepositoryBuildProcessor.java:156`), so the raw value
  (including a legacy `0`) must be kept.
- B8. Getters that replace a `null` collection with an empty one (`:171-258`) become plain
  non-optional Rust collections. A null in a legacy stream decodes to empty.
- B9. Transient runtime state is **not** part of the type: `repositorySyncStatus` (default
  `INDETERMINATED`, `:416-421`), `serverInfo`, `sync`, `changelogs`, `events`, `autoConfig`, their
  `local*` twins, `downloadReport`, `lastIndexFileTransfered` (`:36,46-50,61,68-73`). They belong
  to WP07 or WP11. `RepositoryStatus` itself is ported in `constants`.
- B10. `mapFilesForSync` and `mapFilesForBuild` are SHA-1 caches keyed by **absolute local path**
  (`dao/repository/RepositorySHA1Processor.java:112-114,145`). They are not part of the TOML
  `Repository`. The legacy decoder returns them separately (see B40).

### Protocol helpers (over the existing `a3s_types::Protocol`)

- B29. Factory mapping (`domain/AbstractProtocoleFactory.java:7-25`): FTP and FTPS map to `Ftp`
  (validateSSL comes from the argument), SFTP maps to `Sftp` (validateSSL is always `true`), HTTP and
  HTTPS map to `Http` (argument), HTTP_WEBDAV and HTTPS_WEBDAV map to `Webdav` (argument), and
  SOCKS4 and SOCKS5 map to `Socks` (always `false`). **A3S has no mapping (`null`).**
  `local::protocol::new_protocol(...) -> Option<Protocol>` returns `None` for `A3s`, else delegates
  to the existing `Protocol::new`. `java_protocol_class(t) -> Option<&'static str>` exposes the
  mapping.
- B30. Null `protocolType` fallback by concrete class (getters): `Ftp` gives FTP, `Http` gives
  HTTP, `Sftp` gives SFTP, **`Socks` gives SOCKS4**, and `Webdav` gives HTTP_WEBDAV
  (`Ftp.java:21-27`, `Http.java:19-25`, `Sftp.java:18-24`, `Socks.java:18-24`, `Webdav.java:19-25`).
  The legacy decoder uses this table. The existing `protocol.rs:114` maps Socks to Socks5 (see Q2).
- B31. Null timeouts read as `"300000"` (`AbstractProtocole.java:45-65`,
  `constant/TimeOutValues.java:5`). The existing `Protocol::*_timeout_ms` already does this.
- B32. `host_url(p) = prompt(type) + hostname + ":" + port + remote_path`
  (`AbstractProtocole.java:67-89`). Example: `https://host:443/path`.
- B33. `check_protocol(p) -> Result<(), ProtocolCheckError>` runs the checks in this order, with
  exact messages (`AbstractProtocole.java:99-135`):
  1. url null or `""` gives `"URL field is empty!"`;
  2. login null or `""` gives `"Login field is empty!"`;
  3. port null or `""` gives `"Port field is empty!"`;
  4. port not a Java `Integer.parseInt` gives `"Port is invalid!"`;
  5. port > 65535 gives `"Port number is out of range!\nMaximum port number is 65535."`;
  6. connection timeout `""` gives `"Connection timeout field is empty!"` (null reads as 300000 per
     B31, so it passes);
  7. connection timeout not parseable gives `"Connection timeout is invalid!"`;
  8. and 9. the same two checks for the read timeout, with `"Read timeout field is empty!"` and
     `"Read timeout is invalid!"`.

  `Integer.parseInt` semantics: an optional leading `+` or `-`, ASCII digits, no whitespace, and
  the value must fit in `i32`. Negative ports therefore **pass** (Java quirk).

### Lenient legacy decoding (input: uncompressed, decrypted Java serialization stream)

- B35. The decoder reads with `a3s_jserial::read` (default generous limits), **not**
  `Limits::JAVA_A3S`. Old Java versions wrote files before the current Java filter
  (`dao/A3SFilesAccessor.java:26-30`) existed. Large `mapFilesForSync` caches can exceed 250 000
  references.
- B36. Fields are looked up by name through the class hierarchy (`Graph::opt_field`). The UID is
  ignored, and unknown classes and fields are ignored.
- B37. A **missing** field takes the Java zero value (`0`, `false`, `null`), not the field
  initializer. Java doesn't run field initializers when it deserializes a `Serializable` class
  whose first non-serializable superclass is `Object`. The Java getter normalisation from
  B3-B8, B11, B18 and B19 then applies. So a legacy `Repository` without `noAutoDiscover` decodes
  to `no_auto_discover = false`. A repository without `parallelUploadConnections` or
  `numberOfRepositoryCheckConnections` stores `0`, and its getters return 4.
- B38. A field whose value has an unexpected kind (for example a primitive type change, or a
  non-String element in a string collection) is treated as missing, and the decoder records a
  warning. A null element in a list or set is skipped.
- B39. An unknown enum constant decodes to the B17/B18 default (or `None` for `Option` fields) and
  the decoder records a warning. Java would throw here (see Q3).
- B40. Root decoders:
  - `Configuration` returns `LegacyConfiguration { configuration, addon_search_directory_paths: Option<Vec<String>>, launcher_options: Option<LauncherOptions> }`.
  - `Preferences`.
  - `Profile`.
  - `Repository` returns `LegacyRepository { repository, files_for_sync: BTreeMap<String, FileAttributes>, files_for_build: BTreeMap<String, FileAttributes> }`.
    Cache entries with a null key or null `sha1` are dropped.
  - `AutoConfigExport` (`fr.soe.a3s.domain.AutoConfig`).
- B41. Hard errors: unreadable stream (`Error::Serialization`); root class mismatch
  (`Error::UnexpectedClass`); `Repository.name` null (`Error::NullValue("name")`; WP04 also rejects
  blank names, see `dao/repository/RepositoryDAO.java:116-124`); `Repository.protocole` null or
  not an `AbstractProtocole` subclass; `Profile.name` null. Everything else is lenient.
- B42. Lenient protocol decode, for any class whose hierarchy contains
  `fr.soe.a3s.domain.AbstractProtocole`:
  - `url` and `port` read null or missing as `""`;
  - `login`, `password`, `connectionTimeOut` and `readTimeOut` stay `Option`;
  - a missing `validateSSLCertificate` reads as `false`;
  - a null or unknown `protocolType` falls back to the class (B30);
  - an unknown `encryptionMode` reads as `None` and records a warning.
- B43. Lenient `FavoriteServer` decode by name, with each missing field at its zero value (old
  configs predate `modsetName` and `repositoryName`). It produces the existing
  `a3s_types::FavoriteServer`. The existing strict `FavoriteServer::decode` must **not** be used
  here.
- B44. Known historical variants (Java git history) that must decode:
  - `Repository` without `numberOfRepositoryCheckConnections` (added b3863e6) and without
    `parallelUploadConnections` (added f49736d);
  - `Preferences` without `preferGitHubUpdates` (df555cc);
  - `Configuration` with `aiaOptions` of class `fr.soe.a3s.domain.configration.AiAOptions`
    (removed b38a64b);
  - `LauncherOptions` without `launchArma3AsAdministrator`;
  - `TreeLeaf` without `workshopId` and `dlcAppId` (222dd5e, 4bd4a8e).

### `export.a3s.autoconfig` (`domain/AutoConfig.java`, `service/CommonService.java:54-108`)

- B45. `AutoConfigExport { profiles: Vec<Profile>, favorite_servers: Vec<FavoriteServer>, repositories: Vec<Repository> }`.
- B46. Encoding mirrors what Java puts in the file:
  - every profile is written with `launcherOptions = null` (`CommonService.java:62`);
  - every repository is written as `new Repository(name, protocol)`, that is, all other fields
    at the B2 defaults with empty `HashSet`, `HashMap` and `ArrayList` instances, whatever the
    Rust value holds (`:76`);
  - favorite servers are written with the existing `FavoriteServer` encoder.
  - Java mutates the live profile by clearing its launcher options (`:62`), and later the null
    getter recreates defaults. This is local-only and Rust does not do it.
- B47. When the export is decoded, a profile's null `launcherOptions` becomes the default (B11).
  Import semantics live in WP14 and are recorded here for reference:
  - profiles overwrite profiles with the same name (`:90-93`);
  - favorite servers are appended without de-duplication (`:97-99`);
  - a repository is added only if its name is absent, **but `repositoryDAO.write` is called for
    every imported repository**, so the existing file is overwritten by the bare imported one
    (`:103-108`, local-only Java bug).

### serde / TOML (new Rust store)

- B48. Every `local` type and every `constants` enum derives `Serialize` and `Deserialize`, plus
  `Clone`, `Debug`, `PartialEq` (`Eq` where there is no `f64`). Enums serialize as Rust variant
  names, consistent with the existing `ProtocolType`. `TreeNode` is internally tagged
  (`#[serde(tag = "kind", rename_all = "snake_case")]`). Sets are `BTreeSet<String>` and maps are
  `BTreeMap<String, _>` (deterministic output). Runtime-only fields (`TreeDirectory::updated`,
  `TreeLeaf::missing`) are `#[serde(skip)]`.
- B49. Deserializing TOML with missing keys yields the **Java initializer** defaults of B2, B11,
  B17, B19 and B22 (`#[serde(default)]`, with `Default` impls or per-field default functions;
  `Repository` requires `name` and `protocol`). This differs from B37 on purpose: B37 reproduces
  Java deserialization, B49 makes the new store forward-compatible.

### Java quirks to preserve (wire-visible)

- Class and field names exactly as in Java, including `configration`, `protocole`,
  `bitTorrentProtocole`, `hidddenFolderPaths` (three d's), `outOfSynk`,
  `favoriteServersSetToAutoconfig`, `nologs`, `enableHT`, `iconResizeSize`, and `startWithOS`.
  The Rust field names can be idiomatic (`hidden_folder_paths`). The descriptor strings must not
  change.
- Deprecated final fields are still serialized and must be written as `false`:
  `Repository.outOfSynk`, `TreeLeaf.duplicate`. `LauncherOptions.noFilePatching` is never
  encoded, because launcher options are null in exports.
- The profile tree root is named `"racine"`.
- `GameDlc` Java names (`vn` is lowercase) appear as keys in event `dlcNames`.
- `ModsetType` constant names `EVENT` and `REPOSITORY`.
- `numberOfConnections` keeps its raw value (B7).

### Java quirks that may be dropped (local-only; needs an approved deviation)

- `getFavoriteServers()` sorting as a side effect of reading (B20). Rust sorts explicitly instead
  (same observable order).
- `Preferences.iconResizeSize` initializer `NONE` vs null-getter `AUTO` (B18) is kept as is,
  because it is cheap. Null MinimizationType stays null in Java; Rust uses `TaskBar` (Q6).
- `Configuration.profileName` null: Java looks up the profile with a null key. Rust uses
  `"Default"` (Q7).
- A Java decode fails on an unknown enum constant. Rust falls back with a warning (Q3).
- Mutating the live profile on export (B46), and the overwrite on import (B47).
- `AbstractProtocoleFactory` returns null for A3S. The existing `Protocol::new` and encoder map
  A3S to `Http` (`protocol.rs:101`). WP03 doesn't change that and only adds the
  `Option`-returning wrapper.
- `checkData` accepts negative ports (B33). This is preserved by default. Tightening it needs a
  deviation.

### Errors, cancellation, progress

- Setters that reject a value return `local::InvalidSetting { message: &'static str }`
  (`thiserror`), carrying the exact Java message (B3, B4). `check_protocol` returns
  `ProtocolCheckError` whose `Display` is the exact Java message (B33).
- Legacy decoders return `a3s_types::Result<Legacy<T>>` (existing `Error` enum, unchanged).
  Warnings are `Vec<String>` in human-readable form, naming class and field. No I/O, no
  cancellation, no progress.

### Concurrency

None. These are pure data and codecs.
