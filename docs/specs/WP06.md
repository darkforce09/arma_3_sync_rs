## Scope

- Add write operations to `Transport`: `exists`, `upload_file`, `upload_bytes`, `mkdirs`,
  `delete` for FTP, FTPS, SFTP, HTTP-WebDAV and HTTPS-WebDAV. HTTP(S) supports `exists` only;
  every write op on HTTP returns `Error::Unsupported`.
- Add an **upload session** (`Transport::upload_session()` → RAII guard). Within a session FTP
  caches known directories and directory listings (one `LIST` per directory instead of one
  probe per file); SFTP and WebDAV cache known directories. Without a session every call is
  uncached (the connection itself is always reused: a `Transport` is one connection).
- Reject unsafe relative paths (`..`, NUL, CR, LF) before any network I/O.
- Fix three download-side gaps the upload side depends on (base directory resolution for FTP
  and SFTP, SFTP URL normalisation, SFTP default timeout). The download API signatures do not
  change.
- In-process test servers (libunftp FTP/FTPS, russh + russh-sftp SFTP, dav-server WebDAV in
  axum) usable by both upload and download tests.

## Behaviour contract

### Common (all protocols)

- B1. Remote paths are relative to the repository base directory (see B10/B20/B30); the
  repository-relative form is the one `RemoteFile.getRelativeFilePath()` produces, with or
  without the leading `/` (`dao/connection/RemoteFile.java:38-65`). Rust joins with
  `path::join_remote(base, relative)` (already in `src/path.rs`).
- B2. Path validation (new `path::validate_relative`, applied by every new op **before any
  network I/O**): replace `\` with `/`, then reject (`Error::InvalidPath`) if any segment is
  `..` (mirrors `dao/connection/sftp/SftpDAO.java:451-457`, extended to all protocols) or if
  the path contains `\0`, `\r` or `\n` (FTP command injection). Empty segments and a leading
  `/` are allowed (collapsed by `join_remote`). A `.` segment is rejected too.
- B3. `delete` and `upload_*` reject an empty / root-only relative path (`""`, `"/"`) with
  `Error::InvalidPath`: deleting the repository root is never a valid request. (`mkdirs("")`
  is a no-op `Ok(())`; `exists("")` → `InvalidPath`.)
- B4. `upload_file(local, relative)` creates the parent directories first, then writes the
  file, overwriting any existing remote file (FTP `STOR`, SFTP `Create|Write|Truncate`,
  WebDAV `PUT`) (`ftp/FtpDAO.java:506,517`, `sftp/SftpDAO.java:291-294`,
  `webdav/WebdavDAO.java:285,295`). Returns the number of bytes sent.
- B5. `upload_bytes(bytes, relative)` writes an in-memory buffer verbatim, creating parent
  directories first. Java serialises + gzips inside the DAO (`ftp/FtpDAO.java:584-591`,
  `sftp/SftpDAO.java:318-327`, `webdav/WebdavDAO.java:335-342`); in Rust the caller encodes
  with `a3s_repo_files::encode_a3s` and the transport must not alter a single byte (no
  `Content-Encoding`, FTP `TYPE I`). Remote name for metadata is `.a3s/<name>` with names
  `sync`, `serverinfo`, `changelogs`, `autoconfig`, `events`
  (`AbstractConnexionDAO.java:427`, `DataAccessConstants.java:38-43`) — the caller passes the
  full relative path.
- B6. `mkdirs(relative_dir)` creates every missing directory below the base, one segment at a
  time, parents first; existing directories are not an error (`ftp/FtpDAO.java:621-660`,
  `sftp/SftpDAO.java:372-388`, `webdav/WebdavDAO.java:436-451`). A Java "upload of a directory
  `RemoteFile`" is `mkdirs` (`ftp/FtpDAO.java:499-501`, `sftp/SftpDAO.java:281-285`,
  `webdav/WebdavDAO.java:282-283`).
- B7. `exists(relative)` answers whether a **file** exists. A missing parent directory yields
  `Ok(false)`, never an error (`AbstractConnexionDAO.java:362-391`: `FileNotFoundException` →
  `false`). Directories are never checked by callers (`ConnectionCheckProcessor.java:67`).
- B8. `delete(relative, kind)` with `RemoteKind::File` deletes one file; with
  `RemoteKind::Directory` deletes the directory **recursively**. A missing target is
  `Ok(())` (`AbstractConnexionDAO.java:458-460`, `ftp/FtpDAO.java:709-723`,
  `sftp/SftpDAO.java:355-358`, `webdav/WebdavDAO.java:378`).
- B9. Progress: every byte written to the remote side by `upload_file` and `upload_bytes` is
  added to `ctx.progress` as it is sent (Java `UploadProgressListener`,
  `AbstractConnexionDAO.java:745-790`, counted per read of the local stream). If
  `ctx.throttle` is set it is honoured; Java never throttles uploads
  (`SpeedControlListener` is download-only, `AbstractConnexionDAO.java:792-812`), so WP12
  passes a ctx without throttle. Cancellation is checked before each op and between chunks
  (`ctx.cancel` → `Error::Cancelled`).

### FTP / FTPS (`src/ftp.rs`)

- B10. Base directory, fixed at connect (affects downloads too): if `protocol.remote_path()`
  is non-empty, send `CWD <remote_path>`; failure → `Error::NotFound(remote_path)`
  (`ftp/FtpDAO.java:172-193`); base = remote_path. If it is empty, base = reply of `PWD`
  (Java uses the login directory: no `CWD`, relative names; `ftp/FtpDAO.java:70-73`). All
  commands then use absolute paths `join_remote(base, relative)`; Java's `CWD`-tracking
  (`ftp/FtpDAO.java:275-327`) is an implementation detail and is not ported.
- B11. `exists` **outside** a session: `MLST <abs>` → 2xx `true`, 550 `false`; if the server
  does not implement MLST (500/501/502/504) fall back to an uncached `LIST <abs parent>` and
  look the name up (`ftp/FtpDAO.java:479-494`). A missing parent → `false`.
- B12. `exists` **inside** a session: answer from the cached listing of the parent directory;
  on a cache miss run `LIST <abs parent>` once, parse the lines
  (`suppaftp::list::ListParser::parse_posix`, then `parse_dos`), cache the set of names, count
  one directory listing (`ftp/FtpDAO.java:437-446, 460-477`). 450/550 on `LIST` = empty set
  (missing or empty dir). If the listing is unusable (other error, or no line parses while
  non-`total` lines exist) fall back to B11 for that file (`ftp/FtpDAO.java:443-449,
  463-467`). Names starting with `.` that are absent from the listing are confirmed with B11
  before answering `false` (servers hide dot-files from `LIST`; Java never sets
  `setListHiddenFiles`).
- B13. After a successful `STOR` (file or bytes) inside a session, add the file name to the
  cached listing of its directory if that listing is cached (`ftp/FtpDAO.java:547, 597,
  673-681`). After `MKD`, add the directory to the known set and to its parent's cached
  listing, and drop any cached listing for the new directory (`ftp/FtpDAO.java:654-656,
  662-671`). After a delete, remove the name from the cached listing (Java does not; local
  improvement, harmless).
- B14. `mkdirs`: walk segments below base; a segment in the known-directory set is skipped
  (session only). Otherwise `CWD <abs>`: success → mark known; failure → `MKD <abs>`; if
  `MKD` fails, re-try `CWD <abs>` once (another worker may have created it) and only then
  fail with the server reply (`ftp/FtpDAO.java:641-658`, message "Unable to create remote
  directory …" at `:651-652`). `mkdirs` never creates components of the base path itself.
  If a known directory turns out to be gone (a later `STOR`/`CWD` returns 550), drop it from
  the set and recreate it once (`ftp/FtpDAO.java:631-639`).
- B15. `upload_file`/`upload_bytes`: `mkdirs(parent)`, then `put_with_stream(<abs>)`, copy in
  chunks (B9), then `TransferStream::finish()`. `STOR` refused with 550 → `Error::NotFound`; other
  refusals → `Error::Ftp` (`ftp/FtpDAO.java:517-525`). A non-2xx final reply → `Error::Ftp`
  (`ftp/FtpDAO.java:539-544`). Java sends `NOOP` after metadata uploads
  (`ftp/FtpDAO.java:596`); may be dropped (local-only).
- B16. On cancellation or error during a transfer, abort the data stream
  (`suppaftp` `abort(transfer)`), so the control connection stays usable; if the abort itself
  fails, the transport is poisoned and every later call returns an error whose
  `is_connection_lost()` is `true`.
- B17. `delete(File)`: `DELE <abs>`; 550 → `Ok(())`, other failure → error
  (`ftp/FtpDAO.java:716-723`). `delete(Directory)`: `LIST <abs>` (parsed as in B12, using
  `File::is_directory()`), recurse into sub-directories, `DELE` files, then `RMD <abs>`; 550 on
  any `DELE`/`RMD` is ignored, other failures abort with an error naming the path
  (`ftp/FtpDAO.java:690-715`). If the directory listing is 450/550, treat the directory as
  missing → `Ok(())`.
- B18. Session lifetime: caches exist only while an `UploadSession` guard is alive; dropping
  it clears them and logs `directory_listings` and `cached_file_checks` at info level
  (`ftp/FtpDAO.java:96-110`, counters `:54-55, 444, 474`). The counters are also readable via
  `Transport::upload_session_stats()` for tests.
- B19. FTPS uploads use the already-negotiated `AUTH TLS` + `PBSZ 0` + `PROT P` data
  protection (`ftp/FtpDAO.java:148-154`; done by `suppaftp::into_secure` in `connect`).

### SFTP (`src/sftp.rs`)

- B20. URL normalisation (affects downloads too): strip a leading `sftp://`
  (case-insensitive) and any leading `/` from `protocol.url`, then host = text before the
  first `/`, configured path = the rest **including** its leading `/`, or empty
  (`sftp/SftpDAO.java:430-449`). An empty host → `Error::InvalidProtocol("SFTP host is
  empty…")` (`:118-120`).
- B21. Base directory (affects downloads too): `validate_relative(configured)` (`..` →
  `InvalidPath`); empty → `canonicalize(".")` (home, `sftp/SftpDAO.java:161-165`); `/` → `/`;
  otherwise the configured absolute path (`sftp/SftpDAO.java:414-423`). Downloads currently
  use `join_remote(remote_path, …)`, which resolves an empty path to `/` instead of home —
  switch them to the resolved base.
- B22. Connect: an empty password → `Error::InvalidProtocol("SFTP password is empty. Key-based
  authentication is not configured yet.")` before authenticating
  (`sftp/SftpDAO.java:150-152`). If `options.connect_timeout` is `None` (protocol value 0) use
  30 s (`sftp/SftpDAO.java:531-538`). Host keys: accept and log fingerprint (decision D-6,
  already implemented).
- B23. `exists`: `stat <abs>`; `NoSuchFile` → `false`; other errors propagate
  (`sftp/SftpDAO.java:390-400`). Java counts checks and logs at 1 and every 25
  (`:271-274`) — local-only.
- B24. `mkdirs`: for each prefix of `join(base, relative)` starting at `/` (Java includes the
  base components, so a missing configured base is created; `sftp/SftpDAO.java:372-388`):
  skip if known (session) or `stat` succeeds, else `mkdir`; if `mkdir` fails, re-`stat` once
  before failing.
- B25. Upload: open with `Create | Write | Truncate`, write in chunks of at most 64 KiB
  (`SFTP_WRITE_BUFFER_SIZE`, `sftp/SftpDAO.java:45-48, 293-301`), close (flush) the handle;
  errors propagate as `Error::Sftp`.
- B26. `delete`: if `stat` says missing → `Ok(())`; directory → `read_dir`, skip `.`/`..`,
  recurse (using the entry attributes' `is_dir`), then `rmdir`; file → `remove`
  (`sftp/SftpDAO.java:339-343, 355-370`).

### WebDAV (`src/webdav.rs`)

- B30. URLs: `scheme://host:port/` + percent-encoded segments of `join_remote(remote_path,
  relative)` (existing `http::url_for`); **collection URLs end with `/`**
  (`RemoteFile.java:58-62`, `webdav/WebdavDAO.java:443-444`). Preemptive Basic auth unless the
  login is anonymous (`webdav/WebdavDAO.java:144-159`; existing `http::basic_auth`).
- B31. `exists`: `HEAD <file url>`; 2xx → `true`, 404/410 → `false`, 401/403 →
  `Error::Unauthorized`, other → `Error::HttpStatus` (Sardine `exists` = HEAD;
  `webdav/WebdavDAO.java:249-277`, mapping `:231-242`).
- B32. `mkdirs`: for each segment below the remote path (never the remote path itself,
  `webdav/WebdavDAO.java:438-449`): skip if known (session); else `PROPFIND <dir url>/` with
  `Depth: 0` → 207/200 = exists; 404 → `MKCOL <dir url>/`; MKCOL 201 → created, 405 →
  already exists (race), other → error via `check_status`.
- B33. Upload: `PUT <file url>` with an explicit `Content-Length` (file size / buffer length),
  body streamed from the local file in chunks counting progress and honouring cancel
  (B9). 200/201/204 → success; else `check_status` (401/403 → `Unauthorized`,
  404/409 → `NotFound`) (`webdav/WebdavDAO.java:295, 342`).
- B34. `delete`: `DELETE <url>` (`/`-terminated for directories; the server deletes
  recursively); 404/410 → `Ok(())` (Java does `exists` first then `DELETE`,
  `webdav/WebdavDAO.java:375-407` — same outcome, one round trip fewer).
- B35. Write verbs (`PUT`, `MKCOL`, `DELETE`, `PROPFIND`) do **not** follow redirects: build a
  second client with `redirect::Policy::none()` from the same options; a 3xx is
  `Error::HttpStatus`. GET downloads keep the existing policy.

### HTTP (`src/http.rs`)

- B40. `exists`: `HEAD <url>`; if the server answers 405/501, retry with `GET` and drop the
  body. `true` iff status is 200; 404/410 → `false`; 401 → `Error::Unauthorized`; other
  non-2xx → `Error::HttpStatus`; other 2xx → `false` (`http/HttpDAO.java:172-182, 390-407`).
  Needed because `ConnectionService.checkRepositoryContent` checks files over the
  **download** protocol, which can be HTTP (`service/ConnectionService.java:349-374`).
- B41. `upload_file`, `upload_bytes`, `mkdirs`, `delete` on HTTP →
  `Error::Unsupported { protocol: "HTTP", operation: "upload" | "mkdir" | "delete" }`
  (`http/HttpDAO.java:415-428`). `Transport::supports_upload()` is `false` for HTTP, `true`
  otherwise.

### Java quirks to preserve (wire-visible)

- Uploaded bytes are exactly the caller's bytes (`.a3s/*` byte identity is produced by
  `a3s_repo_files::encode_a3s`, not by the transport).
- Directory URLs on WebDAV end with `/` (servers answer 301 otherwise; `RemoteFile.java:58-62`).
- Remote layout: metadata under `<base>/.a3s/`, files at their repository-relative path.
- SFTP accepts `sftp://host/path` and `///host/path` stored by older builds
  (`sftp/SftpDAO.java:425-439`).
- SFTP `mkdirs` creates missing components of the configured base path; FTP and WebDAV do not
  (`sftp/SftpDAO.java:372-388` vs `ftp/FtpDAO.java:641-658`, `webdav/WebdavDAO.java:438-449`).

### Java quirks that may be dropped (local-only; needs an approved deviation)

- FTP control encoding: commons-net default ISO-8859-1 (no `setControlEncoding` anywhere);
  suppaftp sends UTF-8. Only non-ASCII file names differ — see Q3.
- FTP `fileExists` for a directory returns "last reply != 550", i.e. it checks the parent
  (`ftp/FtpDAO.java:434-436`); unreachable from callers (B7). Not ported.
- FTP listing cache is not updated on delete (`ftp/FtpDAO.java:683-725`); Rust updates it.
- FTP `NOOP` after metadata STOR (`ftp/FtpDAO.java:596`) — may be dropped.
- FTP 1 MiB socket/copy buffers (`ftp/FtpDAO.java:142, 529`), SFTP 1 MiB local buffer
  (`sftp/SftpDAO.java:45`) — Rust uses 64 KiB chunks.
- WebDAV `makeDir` builds raw, unencoded URLs (`webdav/WebdavDAO.java:443-444`) and fails on
  spaces; Rust percent-encodes.
- WebDAV: Java uses `HEAD dir/` for directory existence (`webdav/WebdavDAO.java:445`); Rust
  uses `PROPFIND Depth: 0` (HEAD on collections is unreliable). WebDAV `PUT` from a stream is
  chunked with `Expect: 100-continue` (Sardine); Rust sends `Content-Length`.
- WebDAV `LaxRedirectStrategy` (`webdav/WebdavDAO.java:103-104`) turns a redirected `DELETE`
  into `GET` (HttpClient behaviour); Rust refuses redirects on write verbs (B35).
- WebDAV timeouts: Java maps the read timeout to `connectionRequestTimeout` (pool wait,
  `webdav/WebdavDAO.java:98-101`), so it has no socket read timeout; Rust uses `read_timeout`.
- WebDAV `SchemePortResolver` forces the configured port on every host incl. redirect targets
  (`webdav/WebdavDAO.java:81-94`).
- Temporary connection per operation outside a session (`AbstractConnexionDAO.java:367-382,
  399-404, 431-436, 451-457`): a Rust `Transport` is one connection that is reused.
- SFTP: IPv4 preferred on dual-stack hosts (`sftp/SftpDAO.java:545-558`); validation of `..`
  happens before `\`→`/` replacement (`:402-412, 451-475`, so `a\..\b` slips through) — Rust
  normalises first.
- Error message texts (`ConnectionExceptionFactory`, "login or password wrong or missing")
  are not reproduced; Rust uses typed `Error` variants.
- Known-directory cache for SFTP and WebDAV sessions (Java re-checks every segment per file).

### Errors, cancellation, progress

- No retries inside the transport (Java DAOs do not retry uploads; WP12 decides). Errors
  propagate as typed `Error`; `is_connection_lost()` classifies them as today.
- New variant `Error::InvalidPath(String)` (B2/B3).
- `ctx.check_cancelled()` at the start of every op; `Cancelled` mid-transfer per B9/B16. A
  cancelled or failed upload leaves the partial remote file in place, like Java (Q2).
- Progress: `ctx.progress` += bytes sent (B9). `upload_bytes` counts too; WP12 uses a separate
  ctx for metadata if it wants file-only totals (Java total size excludes metadata,
  `ConnectionUploadProcessor.java:95-107`).

### Concurrency

- One `Transport` = one connection, `&mut self` for every op; parallelism means several
  transports (Java: one DAO per worker, each with its own session,
  `ConnectionUploadProcessor.java:146-156, 186-195`; parallel upload offered only for FTP and
  SFTP, `UploadRepositoryConnectionDialog.java:160-162`; max 10 connections is WP12/WP03).
- `Transport` and the futures returned by every new method must be `Send` (spawned on tokio
  by WP12).
- Directory creation races between workers are tolerated (B14, B24, B32).

## Public API sketch

```rust
// lib.rs
pub use session::{UploadSession, UploadSessionStats};

/// Kind of a remote entry for `delete`.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum RemoteKind { File, Directory }

impl Transport {
    /// HTTP: false. FTP(S), SFTP, WebDAV: true.
    pub fn supports_upload(&self) -> bool;

    /// Whether a remote file exists (all protocols, incl. HTTP).
    pub async fn exists(&mut self, relative: &str, ctx: &TransferCtx) -> Result<bool>;

    /// Uploads `local` to `relative`, creating parent directories. Returns bytes sent.
    pub async fn upload_file(&mut self, local: &Path, relative: &str, ctx: &TransferCtx) -> Result<u64>;

    /// Uploads an in-memory buffer verbatim (e.g. `encode_a3s` output to `.a3s/sync`).
    pub async fn upload_bytes(&mut self, bytes: &[u8], relative: &str, ctx: &TransferCtx) -> Result<()>;

    /// Creates `relative_dir` and missing parents below the base directory.
    pub async fn mkdirs(&mut self, relative_dir: &str, ctx: &TransferCtx) -> Result<()>;

    /// Deletes a file, or a directory recursively. Missing → Ok.
    pub async fn delete(&mut self, relative: &str, kind: RemoteKind, ctx: &TransferCtx) -> Result<()>;

    /// Starts an upload session: enables directory/listing caches until the guard drops.
    pub fn upload_session(&mut self) -> UploadSession<'_>;

    /// Counters of the current/last session (FTP listings, cached checks).
    pub fn upload_session_stats(&self) -> UploadSessionStats;
}

/// RAII guard; `Deref/DerefMut<Target = Transport>`. Drop clears caches and logs stats.
pub struct UploadSession<'a> { /* &'a mut Transport */ }

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct UploadSessionStats { pub directory_listings: u64, pub cached_file_checks: u64 }

// path.rs
pub fn validate_relative(relative: &str) -> Result<()>;   // B2
// error.rs
Error::InvalidPath(String)
```

## Approved deviations (orchestrator, 2026-10-10)

- B16: no `ABOR` on cancel. The transfer stream is dropped, the pending reply drained, then `NOOP` within min(read_timeout, 30 s) checks the control connection; failure poisons the transport (`ConnectionPoisoned`, `is_connection_lost() == true`). Verified sound in review.
- B12 amended (orchestrator, 2026-10-10): directory listings inside an FTP session must NOT pass the path as a LIST argument (servers split it on spaces). Mirror Java (FtpDAO.java:460-462): CWD into the directory, then LIST/MLSD without argument, then CWD back to the base. Same for recursive delete listings (prefer `LIST -a` without argument after CWD). B14: CWD into a known directory before STOR so a vanished directory is detected and recreated before the transfer starts.
