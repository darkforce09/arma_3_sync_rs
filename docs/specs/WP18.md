## Scope

- **Import** (`compare`, `import_preset`): parse an Arma 3 Launcher HTML preset (Workshop
  `ModContainer` rows and CDLC `DlcContainer` rows, preset name), compare it read-only with the local
  addons (`meta.cpp` `publishedid` / `name`, CDLC folders), and return matched/missing lists with
  Java's exact fallbacks, ordering and error messages.
- **Export** (`generate`, `write`): walk the selected modset tree, resolve selected leaves to local
  addons or CDLCs, read `meta.cpp`, fall back to the Workshop metadata store (WP04), collect metadata
  issues, warnings and errors exactly as Java does, render the launcher HTML byte-identically to
  Java's `renderHtml`, and write it atomically with Java's integrity checks.
- **`meta.cpp` scanner** that reproduces the two Java regexes exactly (two `publishedid` variants and
  `name`), hand-written.
- **Pure helpers moved out of `ui/main/AddonsPanel.java`** (Q4) so WP23 only renders: build the
  imported addon group, unique group naming, choose the export modset, suggested file name / `.html`
  extension, metadata dialog prefill and validation, message list formatting.
- No UI, no file dialogs, no persistence of the profile (WP23/WP14). No storage format for the
  Workshop metadata cache (WP04).

## Behaviour contract

### Java string semantics used throughout (local helpers in `preset/text.rs`)

- J1. **WS** = Java regex `\s` without `UNICODE_CHARACTER_CLASS` = exactly
  `[ \t\n\x0B\x0C\r]`. Every `\s` in every pattern below means WS, never Rust's Unicode `\s`.
  `\d` means `[0-9]` (ASCII).
- J2. **java_trim(s)** = `String.trim()`: strip leading and trailing chars `<= U+0020` (this
  includes all C0 controls, not U+00A0). Never use `str::trim` where Java calls `trim()`.
- J3. **java_is_blank(s)** = `String.isBlank()`: every char satisfies `Character.isWhitespace`, i.e.
  is one of U+0009–U+000D, U+001C–U+001F, U+0020, U+1680, U+2000–U+2006, U+2008–U+200A, U+2028,
  U+2029, U+205F, U+3000. (U+00A0, U+2007, U+202F, U+0085 are **not** whitespace.) The empty string
  is blank.
- J4. **Java line terminators** (for `(?m)^` and for `.` without DOTALL): `\n`, `\r\n`, `\r`,
  U+0085, U+2028, U+2029. In multiline mode `^` matches at offset 0 and right after a terminator,
  but **not** between `\r` and `\n`.
- J5. `workshop_url(id)` = `"https://steamcommunity.com/sharedfiles/filedetails/?id=" + id`
  (`service/Arma3LauncherPresetImporter.java:256-258`, `service/Arma3LauncherPresetExporter.java:276-278`).

### `meta.cpp` scanner (`preset/meta_cpp.rs`, hand-written, no regex)

- B1. Candidate start positions are the `^` positions of J4. For each candidate in increasing
  offset order: skip WS* (may cross lines), match the keyword **case-sensitively**, WS*, `=`, WS*,
  the value (B2/B3), WS*, `;`. The **first** candidate that matches completely wins; a failing
  candidate does not stop the scan. A leading UTF-8 BOM (U+FEFF) is not WS, so an assignment on the
  first line of a BOM file is not found (quirk, preserve)
  (`service/Arma3LauncherPresetImporter.java:45-48`, `service/Arma3LauncherPresetExporter.java:35-38`).
- B2. `publishedid` value, two variants:
  - **strict** (importer, `[1-9][0-9]*`, `Arma3LauncherPresetImporter.java:45-46`): maximal ASCII digit
    run whose first digit is `1-9`. `publishedid = 0123;` fails this candidate.
  - **any** (exporter, `\d+`, `Arma3LauncherPresetExporter.java:35-36`): maximal ASCII digit run of
    length ≥ 1, leading zeros and `0` accepted.
  The digit run must be followed by WS* and `;` (a digit run followed by anything else fails the
  candidate; no shorter run can succeed because the next char would be a digit).
  Example: `publishedid = 0;\npublishedid = 5;` → strict `"5"`, any `"0"`.
- B3. `name` value (`Arma3LauncherPresetImporter.java:47-48`, `Arma3LauncherPresetExporter.java:37-38`):
  `"` then a body, then `"`. Body scan: `\` followed by a char that is **not** a J4 line terminator
  consumes both chars; `\` followed by a line terminator or end of input fails the candidate; `"`
  ends the body; any other char (including raw newlines) is consumed. After the closing `"`: WS*,
  `;`, else the candidate fails.
- B4. `unescape_meta_value(raw)` = three **sequential** whole-string replacements: `\\` → `\`, then
  `\"` → `"`, then `\n` → LF (`Arma3LauncherPresetImporter.java:252-254`,
  `Arma3LauncherPresetExporter.java:280-282`). Quirk (preserve): raw `a\\nb` becomes `a`, LF, `b`.

### HTML text extraction (`preset/import.rs`, `regex` crate, see Q1)

- B5. Patterns, translated 1:1 from Java (`Arma3LauncherPresetImporter.java:28-44, 247`); `WS` is J1,
  compile once (`std::sync::LazyLock`):
  - `MOD_ROW` = `(?is)<tr\b[^>]*data-type WS*=WS* ['"]ModContainer['"][^>]*>(.*?)</tr WS*>`
  - `DLC_ROW` = same with `DlcContainer`
  - `DISPLAY_NAME` = `(?is)<[^>]*data-type WS*=WS* ['"]DisplayName['"][^>]*>(.*?)</[^>]+>`
  - `LINK` = `(?is)<a\b[^>]*data-type WS*=WS* ['"]Link['"][^>]*href WS*=WS* ['"]([^'"]+)['"][^>]*>`
  - `LINK_REVERSED` = `(?is)<a\b[^>]*href WS*=WS* ['"]([^'"]+)['"][^>]*data-type WS*=WS* ['"]Link['"][^>]*>`
  - `WORKSHOP_ID` = `(?i)[?&]id=([1-9][0-9]*)`
  - `STEAM_APP_ID` = `(?i)(?:/app/|[?&]appid=)([1-9][0-9]*)`
  - `HTML_TAG` = `<[^>]+>`
  - `HTML_ENTITY` = `(?i)&(#x?[0-9a-f]+|amp|quot|apos|lt|gt);`
  - `PRESET_NAME` = `(?is)<meta\b[^>]*name WS*=WS* ['"]arma:PresetName['"][^>]*content WS*=WS* ['"]([^'"]*)['"]`

  (Spaces above are for readability only; write `[ \t\n\x0B\x0C\r]*` for `WS*`.) Quotes are matched
  independently (`'ModContainer"` matches). Matches are non-overlapping, leftmost-first, iterated
  like `Matcher.find()`; the regex crate's leftmost-first semantics give the same captures as Java's
  backtracking for these patterns (no backreferences, no lookaround). Accepted differences
  (local-only, no test): Rust `(?i)` lets U+017F match `s` and U+212A match `k` in the keywords
  `DisplayName`, `Link`, `PresetName`; `\b` may be Unicode (`\b`) or ASCII (`(?-u:\b)`, if the regex
  crate accepts it in `Regex`).
- B6. `extract_link(row)`: first `LINK` match's group 1, else first `LINK_REVERSED` match's group 1,
  else `""`. The href is returned raw (entities **not** decoded) (`Arma3LauncherPresetImporter.java:201-208`).
- B7. `extract_display_name(row)`: first `DISPLAY_NAME` group 1 or `""`. The lazy body stops at the
  **first closing tag of any kind**: `<td data-type="DisplayName"><b>Foo</b> bar</td>` gives `<b>Foo`,
  cleaned to `Foo` (quirk, preserve) (`:210-213`).
- B8. `extract_workshop_id(link)` / `extract_steam_app_id(link)`: first match group 1 or `None`
  (`:215-223`). `?ID=12abc` gives `12`.
- B9. `clean_text(value)` (`:225-244`), in this order:
  1. remove every `HTML_TAG` match;
  2. replace every `HTML_ENTITY` match; the entity body is lower-cased: `amp`→`&`, `quot`→`"`,
     `apos`→`'`, `lt`→`<`, `gt`→`>`; `#x<hex>` → hex code; `#<digits>` → decimal code; numeric edge
     cases per Q2. Replacement text is not re-scanned (`&amp;lt;` → `&lt;`). Tags are removed
     **before** decoding, so `&lt;b&gt;` survives as `<b>`;
  3. replace every run of WS (J1) with one space (so `&#10;` becomes a space, U+00A0 is kept);
  4. `java_trim` (J2).
- B10. `preset_name(html)` = `clean_text(PRESET_NAME group 1)` of the first match, else
  `"Imported Arma 3 preset"` (`:246-250`). The `name` attribute must precede `content`. A raw `'`
  or `"` inside `content` ends the value (`content="Bob's"` → `Bob`; quirk, preserve).

### Import (`Arma3LauncherPresetImporter.java`)

- B11. `import_preset(path, local_addons)`: if `path` is not a regular file (following symlinks) →
  `ImportError::NotAFile` `"Preset file does not exist or is not a file: <path>"` (path as given).
  Read the whole file as strict UTF-8 (invalid UTF-8 → `ImportError::ReadPreset`), then `compare`
  (`:58-68`). A BOM is not stripped (harmless: patterns use `find`).
- B12. `compare(html, local_addons)` order of operations (`:73-142`):
  1. `java_is_blank(html)` → `ImportError::Empty` `"The preset file is empty."`;
  2. read local Workshop metadata (B16) — runs **before** row parsing, so its failures (Q3) win
     over B15;
  3. read local CDLCs (B17);
  4. Workshop rows (B13), then CDLC rows (B14);
  5. no rows of either kind → `ImportError::NoEntries`
     `"No Arma 3 Launcher Workshop mod or CDLC entries were found in the selected HTML file."`;
  6. split into matched/missing (B18, B19) and build the result (B20).
- B13. For each `MOD_ROW` match in document order: `link = extract_link(row)`;
  `id = extract_workshop_id(link)`; no id → skip the row silently. `name = clean_text(extract_display_name(row))`;
  empty → `"Workshop item " + id`. Insert `WorkshopMod { published_id: id, name, url: workshop_url(id) }`
  keyed by id **only if absent** (first row wins; later duplicates are dropped silently; the URL
  is canonical, not the row's href) (`:82-95`).
- B14. For each `DLC_ROW` match in document order: `link = extract_link(row)`;
  `app_id = extract_steam_app_id(link)`; none → skip. `known = GameDlc::from_steam_app_id(app_id)`
  (exact string match). `name = clean_text(extract_display_name(row))`; empty →
  `known.display_name()` or `"CDLC " + app_id` when unknown. `url = known.steam_store_url()` or the
  raw `link` when unknown. Insert `Cdlc { dlc: known, addon_key: known.java_name(), name,
  steam_app_id, url, local_addon_key: addon_key /* same value */ }` keyed by app id only if absent
  (`:97-113`). Unknown CDLCs (e.g. app `123`) are kept with `addon_key = None`; they count in
  `requested_dlc_count` and always end up in `missing_dlc`.
- B15. `requested_count` = number of distinct Workshop ids, `requested_dlc_count` = number of
  distinct app ids (`:140`).
- B16. Local Workshop metadata (`:144-181`), for each addon in the caller's order:
  1. `dir = absolute(path / name)` then lexical normalisation (`.`/`..` removed, like
     `Path.toAbsolutePath().normalize()`, no symlink resolution); skip if
     `dir.to_string().to_lowercase()` was already visited (case-insensitive dedupe on every OS);
  2. skip unless `dir/meta.cpp` is a regular file;
  3. read it as strict UTF-8 (failure: Q3);
  4. `id = meta_cpp::published_id_strict(text)`; none → skip;
  5. `name = addon.name`; if `meta_cpp::name(text)` is found, `parsed = java_trim(unescape(..))`,
     and if non-empty it replaces `name`;
  6. `addon_key = addon.key` if not `java_is_blank`, else `addon.name`;
  7. insert `(name, addon_key)` under `id` **only if absent** (first addon in caller order wins).
- B17. Local CDLCs (`:183-199`): for each addon, `dlc = GameDlc::from_name(addon.name)`
  (case-insensitive); skip if none or if `path / name` is not a directory. Insert under
  `dlc.steam_app_id()` only if absent, value `dlc.java_name()`. No path dedupe, no `meta.cpp`.
- B18. Matching Workshop (`:119-128`): iterate requested mods in insertion order; if the id is in
  B16's map → `matched` with `local_name = Some(local.name)`, `local_addon_key = Some(local.addon_key)`;
  else `missing` (both `None`).
- B19. Matching CDLC (`:130-138`): if the app id is in B17's map → `matched_dlc` with
  `local_addon_key = Some(dlc.java_name())` (the **enum name**, e.g. `"GM"`, not the addon key —
  quirk, preserve); else `missing_dlc`, whose `local_addon_key` stays equal to `addon_key` (e.g.
  `Some("WS")`, or `None` for unknown) — quirk, preserve.
- B20. `ImportResult.preset_name` = B10 result, replaced by `"Imported Arma 3 preset"` if
  `java_is_blank` (`:269-278`). Lists keep insertion order and are immutable snapshots.

### Export: `generate` (`Arma3LauncherPresetExporter.java:43-72, 119-220`)

- B21. `ExportResult.preset_name` = `modset.name`, or `"Arma3Sync Preset"` if `java_is_blank`
  (`:53, 304-306`). Java's `modset == null` → error `"No modset was selected."` (`:54-57`) is not
  representable (the Rust signature takes `&TreeDirectory`); WP23 shows its own message (B53).
- B22. Depth-first traversal of `modset.children` in stored order (`:194-197`). Directories are
  always descended into, **regardless of their own `selected` flag**. A leaf with
  `selected == false` is skipped (`:125-127`). `workshop_id` / `dlc_app_id` / `missing` of leaves
  are ignored; only `leaf.name` is used.
- B23. CDLC leaf: `GameDlc::from_name(leaf.name)` (case-insensitive). If found, insert
  `(display_name(), steam_store_url())` keyed by the enum only if absent; a duplicate CDLC is
  dropped **silently** (no warning). Return; a CDLC name always wins over a same-named mod
  (`:129-136`).
- B24. Otherwise `addon = resolve(leaf.name)`. None → error
  `"Selected addon is not available locally: " + leaf.name` and continue with the next leaf
  (`:142-146`). (Java's `"No addon resolver is available for <name>."`, `:138-141`, is not
  representable: the resolver is mandatory.) The resolver Java uses is `AddonService.getAddon`, a
  lower-case key lookup (`service/AddonService.java:195-200`) = WP13 `AddonRegistry::get`.
- B25. `meta_file = addon.path / addon.name / "meta.cpp"` (not normalised). If it is a regular
  file, read it as strict UTF-8; failure → error
  `"Could not read " + meta_file + ": " + <io error text>` and continue with the next leaf
  (`:147-157`). Parse `published_id = meta_cpp::published_id_any(text)`,
  `name = meta_cpp::name(text).map(unescape)` (**not trimmed**) (`:200-208`). No file → both `None`.
- B26. `addon_key = addon.key` (Java falls back to `leaf.name` only for a `null` key, `:159`, which
  Rust's `String` key cannot express). `known = metadata_store.and_then(|s| s.find(addon_key))`
  (`:160-161`). WP04's `find` returns `None` for a blank key or a blank stored id/name and trims
  both values (`service/WorkshopMetadataStore.java:42-53`).
- B27. Store fallback (`:162-167`): if `published_id` is not valid (B28) **and** `known` is some →
  `published_id = known.published_id` (even if that one is invalid too). If `name` is `None` (not
  merely blank) and `known` is some → `name = known.name`.
- B28. `is_valid_published_id(s)` (`:210-220`): matches `^[1-9][0-9]*$` and parses as `i64`
  (so at most `9223372036854775807`).
- B29. Name fallback (`:172-174`): if `name` is `None` or `java_is_blank` → `addon.name`. Quirk
  (preserve): `name = "";` in `meta.cpp` is `Some("")`, so the store name is **not** used and the
  folder name is.
- B30. If the id is still invalid (`:176-183`): push `MetadataIssue { addon_key, addon_name:
  addon.name, reason, published_id /* the invalid value or None */, name /* after B29 */ }` and
  continue. `reason` = `"meta.cpp is missing"` if `meta_file` is not a regular file (re-checked
  now), else `"publishedid is missing or invalid"`.
- B31. Valid id (`:185-191`): insert `(name, workshop_url(id))` keyed by id only if absent;
  otherwise push warning `"Duplicate Workshop ID omitted: " + id` (first leaf wins).
- B32. After traversal (`:63-71`): if there are no Workshop entries, no CDLC entries **and no
  errors**, push error `"The selected modset contains no selected Workshop mods or CDLCs."` — this
  happens even when metadata issues exist (quirk, preserve). Then `html = Some(render_html(..))`
  only if errors **and** metadata issues are both empty.
- B33. `ExportResult` accessors (`:295-344`): `is_valid()` = no errors and `html` is some;
  `workshop_count()`, `dlc_count()`; `warnings()`, `errors()`, `metadata_issues()` in push order;
  `summary()` = `format!("{} Workshop mods and {} CDLCs exported.", workshop_count, dlc_count)`
  (`Locale.ROOT`, plain decimal).

### Export: `write` (`Arma3LauncherPresetExporter.java:77-117`)

- B37. In order: (1) `!result.is_valid()` → `WriteError::InvalidResult`
  `"Only a valid export result can be written."`; (2) `target = absolute(target)` + lexical
  normalisation; `parent` = its parent or the normalised current directory; (3)
  `create_dir_all(parent)`; (4) html missing or not containing `</html>` →
  `WriteError::Incomplete` `"The generated preset is incomplete."` (unreachable through `generate`,

### Errors, cancellation, progress

- Import errors abort with `ImportError` (B11, B12; Q2, Q3). Export never fails as a whole:
  problems are collected as `errors` (abort-worthy), `metadata_issues` (fixable through the store,
  WP23 dialog) and `warnings` (duplicates) — all three keep processing the remaining leaves.
- `write` returns `WriteError`; `Io` wraps any `std::io::Error` from directory creation, temp file,
  rename or re-read.
- No retries, no cancellation, no progress events (Java runs all of it synchronously on the EDT,
  `AddonsPanel.java:1223-1231`). Emit `tracing::debug!` at the phases Java logged to
  `launcher-preset-export.log` (scan start/end with issue and error counts, write start/success,
  write failure) — Q5.

## Open questions

- Q1 HTML parsing: `regex` crate or hand-written? The ten Java patterns rely on lazy bodies,
  case-insensitive keywords and backtracking over attribute order; a hand-written scanner would be
  ~300 extra lines with a high risk of subtle divergence. `regex` is MIT OR Apache-2.0, already in
  `Cargo.lock` (via `tracing-subscriber`), linear-time (no ReDoS, unlike Java). `meta.cpp` is
  hand-written (B1-B4) because Java's line-terminator set for `(?m)^` and `.` cannot be expressed
  exactly with `regex`. Proposed default: `regex` 1.13 for B5, hand-written `meta_cpp`.
  Decision:
- Q2 Numeric entities in `clean_text`. Java does `(char) Integer.parseInt(..)`
  (`Arma3LauncherPresetImporter.java:237-238`): values above U+FFFF are **truncated** to 16 bits,
  surrogate values produce raw UTF-16 units (a valid pair of entities becomes a real character,
  a lone one a broken string), and `&#abc;` (matched because the class is `[0-9a-f]` without `x`)
  or values above `i32::MAX` throw `NumberFormatException`, which aborts the whole import. Proposed
  default (local-only deviation): decode to the proper code point (`char::from_u32`), combine two
  consecutive surrogate entities into one character, turn a lone surrogate into U+FFFD, and leave
