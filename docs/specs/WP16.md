## Scope

- **Run parameters** (`params`): the exact Java argument list. The order is: additional parameters,
  then the `-malloc=`/`-name=`/flags/mission file/performance flags, then `-connect=`/`-port=`/`-password=`,
  then the `-mod=` arguments. The `-mod=` arguments are grouped by addon parent path, with a
  trailing `;` and the Java string split. Also the two text renderings the UI uses: the
  Launcher Options preview and the desktop-shortcut arguments.
- **Executable checks** (`executable`): the "Executable location" check, executable-kind detection,
  the BattlEye/elevatable name tests, and the pure path swap behind the "Enable Battleye" checkbox.
- **`Arma3.cfg` clean-up** (`cfg`): remove `class ModLauncherList … };` before every launch.
- **Command planning** (`command`, `elevation`, `steam`): turn (OS, executable, parameters,
  options) into a `CommandSpec`. This is a pure function, so it is tested on Linux for every OS.
  It covers the BattlEye `2 1` prefix, Windows UAC elevation through PowerShell
  `-EncodedCommand` (UTF-16LE Base64), `.bat` through `cmd /C start`, and `.sh` through bash.
  The Java `bash -c` bug is fixed (DV1). Launching through Steam/Proton on Linux is new (Q1).
- **Runner** (`runner`): spawn on a named thread, report Java's "end"/"error" observers as events,
  and run the `autoRestart` loop with a stop handle.
- **External applications** (`external`): start the enabled external applications that are not
  already running.

## Behaviour contract

`trim` below means Java `String.trim()`: strip leading and trailing chars `<= U+0020`
(`java_trim`). `lower` means `str::to_lowercase`. "Contains" means `str::contains`, which is
case-sensitive.

### Run parameters (`params`)

- B1. `determine_run_parameters = additional_parameters ++ run_parameters`
  (`service/LaunchService.java:211-223`). The game launch (`:141`) and the desktop shortcut
  (`ui/main/MainPanel.java:715`) use it. The Launcher Options preview uses `run_parameters` only
  (`ui/main/LauncherOptionsPanel.java:853`).
- B2. `additional_parameters(profile)`: return an empty list if there is no profile or if
  `additional_parameters` is `None` or `""`. Otherwise split on the **space character only**,
  like `StringTokenizer(s, " ")`: runs of spaces are one delimiter, and tabs and newlines stay
  inside tokens. Trim each token. If `lower(token)` contains `"malloc"`, insert it at index 0;
  otherwise append it (`:427-451`). So with several malloc tokens, the **last** one comes first.
  A token that trims to `""` (for example a lone `"\t"`) is still added as `""`. Java does the same.
- B3. `run_parameters` returns an empty list when the profile is `None` (`:233-235`). Otherwise
  it appends, in this exact order (`:240-293`), with `lo = profile.launcher_options`:
  1. `"-malloc=" + v` if `lo.malloc_selection == Some(v)`. This includes `Some("")` → `"-malloc="`.
  2. `"-name=" + v` if `lo.game_profile == Some(v)`.
  3. `"-showScriptErrors"`, `"-noPause"`, `"-filePatching"`, `"-window"`, `"-checkSignatures"`,
     each when its bool is set (`show_script_errors`, `no_pause`, `file_patching`,
     `window_mode`, `check_signatures`).
  4. If `lo.mission_file` and `lo.mission_file_path == Some(p)` with `p` non-empty: `p` as is,
     with no prefix and no trimming (`:262-269`).
  5. `"-maxMem=" + v` if `max_memory_selection == Some(v)`.
  6. `"-cpuCount=" + n` if `cpu_count_selection != 0` (negative values are emitted).
  7. `"-exThreads=" + v` if `ex_threads_selection == Some(v)`.
  8. `"-enableHT"`, `"-hugepages"`, `"-nosplash"`, `"-world=empty"`, `"-nologs"` for
     `enable_ht`, `huge_pages`, `no_splash_screen`, `default_world`, `nologs`.
  9. Server join (B4).
  10. Mods (B5-B9).
  The Java comment says "Malloc must be set at first place" (`:240`), but the launcher-option
  `-malloc=` still comes **after** every additional parameter (B1). Keep this order.
- B4. Server join (`:295-311`): if `configuration.server_name == Some(s)`, find the **first**
  favourite server whose `name == Some(s)`. The comparison is exact and case-sensitive.
  `getFavoriteServers()` sorts stably by ignore-case name, so for exactly equal names the first
  in list order wins, and Rust need not sort. For that server, append `"-connect=" + ip`,
  `"-port=" + port` (decimal `i32`), then `"-password=" + pw` if the password is non-empty.
  Stop at the first match. For `None` names, passwords and IPs, see Q12.
- B5. Addon order (`:313-341`):
  - `selected` = the names of every **leaf** with `selected == true`, found by walking
    `profile.tree` recursively in child order. Directory `selected` flags are ignored
    (`:453-466`).
  - `sel` = the set `{lower(n)}`, sorted like Java `TreeSet<String>`: compare by UTF-16 code
    units (`a.encode_utf16().cmp(b.encode_utf16())`) with duplicates removed.
  - `run` = each `lower(p)` of `profile.addon_names_by_priority` that is in `sel`, in priority
    order. A duplicate in the priority list would be emitted twice; Java does the same. Then
    every name of `sel`, in `sel` order, that is not yet in `run`.
- B6. Addon resolution (`:347-355`): for each name in `run`, call `registry.get(name)`. That is
  a lowercase-key lookup, where keys may end in `*` for duplicates (WP13 B2/B13). Skip it
  silently if missing. Otherwise take a copy `Addon { key, name, path, at_arma3_install_root: false }`.
  The `-mod=` text uses `addon.name`, which has no `*` suffix.
- B7. Install-root flag (`:357-371`): only if `lo.arma3_exe_path` is `Some`, and its parent exists
  per `a3s_addons::arma3_directory` (that is, `None` for `""` and for a bare `"arma3.exe"`).
  Let `root = lower(absolute(parent))`, using `std::path::absolute`, the same function WP13 uses
  for addon paths, then `to_string_lossy`. Each addon gets
  `at_arma3_install_root = (lower(addon.path) == root)`. Otherwise every flag stays `false`.
- B8. Grouping (`:373-391`): split the resolved list into runs of **consecutive** addons with an
  identical `path`, compared exactly and case-sensitively. Non-adjacent addons with the same
  path form separate groups.
- B9. Mod string and split (`:393-421`). Build one string `mods`. For each group, in order:
  - if the group's **first** addon is at the install root: append `"-mod="`, then
    `name + ";"` for every addon in the group. The result is one argument holding all names,
    relative to the game directory.
  - otherwise, for every addon: `"-mod=" + name + ";"` if `path` is empty, else
    `"-mod=" + P(path) + SEP + name + ";"`. `P` and `SEP` come from `ModPathStyle`: Java uses
    the path as is and `File.separator`. The Wine mapping is in Q1.
  Then split `mods` on the literal `"-mod="`. For each piece whose trim is non-empty, append
  `"-mod=" + piece` with the piece **untrimmed**. This must be implemented literally, so that a
  `-mod=` inside a path or name splits the argument as in Java (A5).
- B10. Renderings:
  - `run_parameters_display(params)` = each parameter followed by `"\n"`
    (`ui/main/LauncherOptionsPanel.java:851-863`).
  - `shortcut_arguments(params)` = each parameter preceded by `" "`, which gives a leading space
    (`ui/main/MainPanel.java:715-719`).

### Executables (`executable`)

- B11. `check_arma3_executable_location(profile)`: fail with `LaunchError::ExecutableLocation`
  if the profile is `None`, or `arma3_exe_path` is `None` or `""`, or the path does not exist
  (file **or** directory, `File.exists`) (`service/LaunchService.java:43-56`). Message,
  verbatim: `ArmA 3 Executable location is wrong or missing.\nPlease checkout Launcher Options panel.`
  The UI prefixes it with `Failed to launch ArmA 3.\n` (`ui/main/LaunchPanel.java:292-296`, WP22).
- B12. Executable kind, from the **file name** of the path (`File.getName`). Java tests these in
  order: `contains(".exe")`, then `contains(".bat")`, then `contains(".sh")`, case-sensitively
  (`dao/LauncherDAO.java:126,142,161,205,258,291`). Rust uses an ASCII-case-insensitive
  `ends_with` instead (Q5).
- B13. `is_battleye(name)` = `name.eq_ignore_ascii_case("arma3battleye.exe")`.
  `is_elevatable(name)` = BattlEye, `arma3.exe` or `arma3_x64.exe`, ignoring case
  (`dao/LauncherDAO.java:208,416-420`). The names come from `GameExecutable::file_name()`
  (`constant/GameExecutables.java:5-6`).
- B14. `battleye_toggle_path(exe, os, program_files_x86_set) -> Option<PathBuf>`
  (`ui/main/LauncherOptionsPanel.java:966-995`). If `exe` has no parent, return `None`. If the
  file name is exactly `arma3battleye.exe` (case-sensitive here), return
  `parent/arma3_x64.exe` when `os == Windows && program_files_x86_set`, else `parent/arma3.exe`.
  If the name is exactly `arma3.exe` or `arma3_x64.exe`, return `parent/arma3battleye.exe`.
  Otherwise return `None`. The caller (WP24) checks that the result exists and shows
  `ArmA 3 Executable Location have changed.` (`:997-1003`).

### `Arma3.cfg` (`cfg`)

- B15. `strip_mod_launcher_list(bytes) -> Option<Vec<u8>>` (`service/LaunchService.java:170-204`).
  Split into lines the way `BufferedReader.readLine` does: terminators are `\n`, `\r\n` and
  `\r`, and a final line without a terminator is a line. Start with `record = true` and
  `found = false`. For each line:
  - if it is **exactly** `class ModLauncherList`: set `record = false`, `found = true`. No trim,
    so `" class ModLauncherList"` does not match.
  - else if `!record` and the line is exactly `};`: set `record = true` and drop this line.
  - then keep the line if `record` is true.
  The `class` line and every line up to and including the first top-level `};` are dropped.
  Indented `\t};` lines do not match. A second list is removed the same way. If no `};` follows,
  everything after the `class` line is dropped. If `!found`, return `None`. Otherwise return the
  kept lines, each followed by `"\n"`. This turns CRLF into LF and always adds a final newline.
  Rust works on bytes (Q15).
- B16. `erase_arma3_cfg_mod_launcher_list(dir)`: `path = dir/"Arma 3"/…`. Java builds
  `<My Documents>/Arma 3/Arma3.cfg` (`:165-166`). WP15's `arma3_documents_dir` already returns
  `<Documents>/Arma 3`, so the path is `dir.join("Arma3.cfg")`. If the file does not exist,
  return `Ok(false)`. If B15 returns `Some`, truncate and write the file in place, as Java's
  `FileWriter` does, and return `Ok(true)`. If not found, leave the file untouched (same bytes,
  same mtime). Java swallows every error with `printStackTrace` (`:205-207`). Rust returns the
  `io::Error`, and the launch flow (B27) logs it at `warn` and continues.
- B17. When it runs: on every Arma 3 launch, after computing the parameters and before spawning
  (`:141-144`). It does not run again on auto-restart. Java runs it on Windows only (`:159-163`).
  On Linux, see Q2.

### Command planning (`command`, `elevation`)

- B18. External application (`call`, `dao/LauncherDAO.java:117-191`). `params` are the B2-style
  tokens of `parameters` (`service/LaunchService.java:72-78`), trimmed again (`:132,151,169`):
  - kind Exe: on Windows `[exe, params…]`; on other OSes nothing runs and no error is raised
    (`:126-141`).
  - kind Bat: on Windows `cmd.exe /C start <exe> params…` (Q6 adds the `""` title); elsewhere
    nothing runs (`:142-160`).
  - kind Sh: on Linux `/bin/bash <exe> params…` (DV1; Java passed `-c`); elsewhere nothing runs
    (`:161-178`).
  - other kinds: error `"<file name> - invalid executable file."` (`:179-181`).
- B19. Game (`call2`, `:193-358`), `params` = B1 output:
  - **Windows**, kind Exe (`:205-257`). `cmd = [exe, "2", "1", params…]` when `is_battleye`,
    else `[exe, params…]`. Parameters are **not** trimmed here (`:213-221`). Log the line
    (B21). If `lo.launch_arma3_as_administrator && is_elevatable(name)`, use the elevated launch
    (B20) with `["2", "1"]` + params for BattlEye, else params (`:231-245`). Otherwise spawn
    `cmd` directly.
  - **Windows**, kind Bat: `cmd.exe /C start <exe> params(trimmed)…`, logged (`:258-286`).
    Q6 adds the `""` title.
  - **Windows**, other kinds: `"<file name> - invalid executable file."` (`:287-289`).
  - **Linux**, kind Sh: `/bin/bash <exe> params(trimmed)…` (DV1; Java: `/bin/bash -c <exe> …`,
    `:291-318`).
  - **Linux**, other kinds: `[exe, params(trimmed)…]` (`:319-345`). In `LinuxLaunchMode::Auto`,
    kind Exe goes through Steam instead (Q1).
  - **Any other OS** (macOS, BSD): `"<file name> - invalid executable file."` (`:346-348`).
    Java tests `os.name` for `"windows"`/`"linux"`. Rust uses `a3s_paths::Os::{Windows, Linux}`,
    and `OtherUnix`/`MacOs`/`Other` take this branch.
- B20. Elevation (`:427-454`). `quote_ps(v) = "'" + v.replace("'", "''") + "'"`. Q7 also doubles
  the curly single quotes. The script is, with `A = quote_ps` applied to each argument, joined
  by `,`:
  ```
  $ErrorActionPreference='Stop'; try { $arguments=@(A1,A2,…); $process=Start-Process -FilePath <quote_ps(exe)>[ -WorkingDirectory <quote_ps(dir)>] -ArgumentList $arguments -Verb RunAs -Wait -PassThru; exit $process.ExitCode } catch { exit 1 }
  ```
  `dir` = the parent of the absolute exe path; the clause is omitted when there is no parent
  (`:438-441`). The script is encoded as **UTF-16LE** bytes, then standard Base64 with padding
  (`:444`). The command is `powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden
  -EncodedCommand <b64>`. Its stdout and stderr are merged and discarded, and the result is
  PowerShell's exit code (`:445-449`). A refused UAC prompt therefore gives exit code `1`. Q7
  covers argument quoting, the empty-argument case and the hidden console.
- B21. Log line: `"Starting ArmA 3 with command line: "` + every element of `cmd` followed by
  `" "`, with a trailing space (`:224-229,269-274,301-306,327-332`). Java prints it with
  `System.out.println` **before** the elevation decision, so the elevated case logs the plain
  `cmd`. Rust logs it with `tracing::info!` with `-password=` values redacted (Q11). External
  applications print no line.
- B22. `tokenize_parameters` (B2 without the malloc reordering) is used for external
  applications (`service/LaunchService.java:72-78`).

### Runner (`runner`) and external applications (`external`)

- B23. Events. Java has two observers (`dao/LauncherDAO.java:392-410`):
  - `updateObserverEnd()` fires once per game process start, right after the spawn and before
    the wait (`:252,281,313,339`). In the elevated path it fires only **after** PowerShell
    returns, when the game has already exited (`:239-240`; Q13).
  - `updateObserverError([e])` fires for any exception, and the UI shows `e.getMessage()` in a
    dialog titled `ArmA 3 Start Game` (`ui/main/LaunchPanel.java:338-344`).
  Rust: `LaunchEvent::{Started, Exited, Restarting, Error}` sent to an `EventSink`. `Started`
  maps to Java's "end" (WP22 minimises, sends to tray or closes on it,
  `ui/main/LaunchPanel.java:346-361`). `Error` carries a `LaunchError` whose `Display` is the
  Java message.
- B24. Spawn errors: Java's `IOException` message is
  `Cannot run program "<program>": <reason>`. Rust formats `LaunchError::Spawn` the same way, with
  `<reason>` = the `io::Error` `Display`.
- B25. Auto-restart (`dao/LauncherDAO.java:241-243,254-256,283-285,315-317,341-343`). After the
  process exits (or after PowerShell returns), if `lo.auto_restart`, Java calls the same
  `Callable` again: same parameters, same plan, no `Arma3.cfg` strip, a new log line and a new
  "end" event. It does this whatever the exit code and with no limit. A spawn exception
  ends the chain with an error event. Rust uses a loop on the launch thread with
  `LaunchHandle::stop_auto_restart()` and the fast-exit guard (Q8). Each exit emits
  `Exited { code }`, then `Restarting { run }` when it loops.
- B26. Child I/O: Java pipes stdout and stderr into two `AfficheurFlux` threads that copy the
  lines to `System.out` (`dao/AfficheurFlux.java:25-31`, `dao/LauncherDAO.java:135-138`). Rust
  inherits them (Q9). The working directory is not set in Java, so the child inherits
  Arma3Sync's; Rust sets it to the exe's parent (Q10).
- B27. `launch_arma3` (`service/LaunchService.java:129-155`): do nothing if there is no profile.
  Then compute B1 with the `ModPathStyle` of the chosen method, strip `Arma3.cfg` (B16/B17),
  plan the command (B19), and spawn it on **one** named thread (`a3s-launch-arma3`). Return
  immediately with a `LaunchHandle`. Java uses `Executors.newSingleThreadExecutor()` and
  `shutdown()` (`:147-153`). If `arma3_exe_path` is `None`, Java throws a
  `NullPointerException`. Rust returns `LaunchError::ExecutableLocation` instead.
- B28. `launch_external_applications` (`service/LaunchService.java:58-92`). Walk
  `configuration.external_applications` in list order; the getter does not sort (WP03 B21). An
  application runs when all of these hold:
  - `enable` is set;
  - `executable_path` exists;
  - `!a3s_platform::process::is_running(probe, file_name)` (`:71`, WP15 P1/P4).
  Tokenize its parameters (B22), plan it (B18), and run each on its own named thread
  (`a3s-launch-ext-<i>`), waiting for exit. The exit code is ignored. Errors become
  `Error { target: External(name) }`. No `Started` event is required for external
  applications, but Rust emits one for symmetry. Java only "end"-notifies the game. The
  caller starts external applications **before** the game, without waiting
  (`ui/main/LaunchPanel.java:363-367`). Java's executor bug is in Q4.
- B29. Running checks (`service/LaunchService.java:94-127`) are WP15's
  (`is_arma3_running`, `is_arma3_server_running`, `is_ts3_running`). Callers use
  `a3s_platform::process` directly. This crate only uses `is_running` (B28) and
  `is_any_running(ARMA3_EXES)` (Q1 polling).

### Java quirks to preserve (wire-visible)

None are repository-wire-visible. The following are **process-visible**: Arma 3 sees them. They
must be preserved exactly and are pinned by the golden tests:
- Additional parameters first; launcher `-malloc=` after them; the last malloc token first (B1-B3).
- `Some("")` values emit `-malloc=`, `-maxMem=`, `-exThreads=` and `-name=` with no value (B3).
- The mission file path is a bare positional argument (B3.4).
- `-hugepages`, `-nosplash`, `-world=empty`, `-nologs` spellings; `-showScriptErrors`,
  `-noPause`, `-filePatching`, `-checkSignatures`, `-enableHT` casing (B3).
- `-mod=` grouping: install-root groups give one `-mod=a;b;` argument; other addons give one
  `-mod=<path><SEP><name>;` argument each, with a trailing `;` everywhere; the literal split
  quirk (B8-B9).
- Priority order, then the remaining selected addons in UTF-16 sort order; unknown names
  dropped (B5-B6).
- Elevation script text and UTF-16LE Base64 (B20), apart from the Q7 fixes.
- BattlEye `2 1` prefix (B19); `.exe` parameters untrimmed, `.bat`/`.sh`/Linux parameters
  trimmed (B18-B19).

### Java quirks that may be dropped (local-only; needs an approved deviation)

- `.sh` launched as `/bin/bash -c <script> args…`: the script receives none of its arguments
  (they become `$0`, `$1`, … of the `-c` string). **DV1, approved by the orchestrator brief.**
- Only the first external application runs, and launching 2+ throws, so the game does not
  start (Q4).
- Case-sensitive `contains` for extensions (Q5).
- `cmd /C start "<path with spaces>"` treats the path as the window title (Q6).
- Elevated launches split arguments that contain spaces, fail with no arguments, and do not
  escape curly quotes (Q7).
- Unbounded and unstoppable auto-restart, including an instant spawn loop with `.bat` (Q8).
- Piped child output (SIGPIPE risk after Arma3Sync exits) and inherited working directory
  (Q9, Q10).
- Password printed in the command line log (Q11).
- `NullPointerException`s on `None` fields (Q12).
- The elevated "end" event fires after the game exits (Q13).
- Lossy UTF-8 rewrite of `Arma3.cfg` (Q15).
- Java Windows `ProcessBuilder` quoting differs from Rust's MSVC-correct quoting for arguments
  that end in `\` or contain `"`. Rust std quoting is accepted without a test.

### Errors, cancellation, progress

- No retries anywhere. `Arma3.cfg` errors are logged and do not abort (B16). Spawn and wait
  errors end the current chain with an `Error` event (B24-B25). Errors in planning (invalid
  executable, Steam not found) are returned synchronously from `launch_arma3`, before any
  thread starts. The UI shows them in the same `ArmA 3 Start Game` dialog.
- Cancellation: `LaunchHandle::stop_auto_restart()` stops further restarts. It never kills a
  running game (Java cannot either). Dropping the handle detaches the thread. Exiting
  Arma3Sync must not kill the game: no kill-on-drop and no job objects.
- Progress: none, only the events in B23.

### Concurrency

Java uses one single-thread executor for the game, a fixed pool of `apps.size()` threads for
external applications, and two stream-reader threads per child. Rust uses one named
`std::thread` per launched process: `a3s-launch-arma3` and `a3s-launch-ext-<i>`. A Steam-mode
launch has one extra `a3s-launch-steam-reaper` thread (Q1). There are no stream threads (Q9).
`EventSink` is `Arc<dyn Fn(LaunchEvent) + Send + Sync>`. The crate uses no tokio.

## Open questions

- Q1 **Linux launch through Steam/Proton (new behaviour).** On Linux, Java execs the chosen
  `.exe` directly, which fails unless `binfmt_misc`/Wine is set up. Proposed default:
  - `LinuxLaunchMode::Auto`: if the exe kind is Exe, launch with
    `<steam prefix> -applaunch 107410 -noLauncher <B1 params>`. `Direct` keeps Java behaviour;
    `Steam` forces Steam.
  - The steam prefix is the first of: `steam` found on `PATH` (an executable file); then
    `flatpak run com.valvesoftware.Steam` when `flatpak` is on `PATH` and
