## Scope

- `a3s_build_info`: version, `major.minor` name, build number, copyright year range, git hash and
  target triple baked in by `build.rs`; version banner text (port of `main/Version.java`).
- `a3s_paths`: the Rust client's own config/data/cache/log/temp directories under a name that
  never collides with Java's `Arma3Sync` (`arma3sync-rs`), portable mode, explicit overrides, and
  **read-only discovery** of legacy Java data locations (per-user and installation layouts) for
  the WP04 importer. No copying/migration (Java `migrateLegacyData` is not ported).
- `a3s_log`: `tracing` setup (stderr + opt-in rotating debug file), Java-like line format,
  credential redaction helpers (port of `utils/DebugLogger.java`).
- `a3s_format`: byte sizes, speeds, `HH:MM:SS` durations — character-identical to
  `utils/UnitConverter.java` — plus a fixed medium date-time format.
- `a3s_error`: an `ErrorKind` taxonomy + `UserFacing` trait that later crates implement on their
  `thiserror` enums, error-chain formatting, and every user-facing message text from
  `exception/**`, `ConnectionExceptionFactory` and `utils/RepositoryConsoleErrorPrinter.java`
  as functions/constants (not class-by-class).

## Behaviour contract

### a3s_build_info (`main/Version.java`)

- BI1. `VERSION` is the single version source. Java: manifest `Implementation-Version`, else
  `version.properties` `app.version`, each only accepted if it matches `\d+\.\d+\.\d+`, else
  `"0.0.0"` (`main/Version.java:40-58`). Rust: `env!("CARGO_PKG_VERSION")` (workspace
  `version`); the fallback is not needed.
- BI2. `name()` = first two dot-separated parts (`"2026.4"` for `2026.4.15`), or the whole string
  if fewer than two parts (`main/Version.java:18-21`). Rust: `"{MAJOR}.{MINOR}"` from
  `CARGO_PKG_VERSION_MAJOR/MINOR` (`0.1` for `0.1.0-alpha.1`).
- BI3. `build()` = third part parsed as int, `0` if missing or not a number
  (`main/Version.java:23-31`). Rust: `CARGO_PKG_VERSION_PATCH` as `u32`. (Java would return 0 for
  `0.1.0-alpha.1` because `"0-alpha"` fails to parse; Rust returns the numeric patch. Java uses
  it only for the update check `service/ConnectionService.java:486`, which WP31 replaces.)
- BI4. `copyright_years(current_year)`: `FIRST_RELEASE_YEAR = 2013`; returns `"2013"` if
  `current_year == 2013`, else `"2013-{current_year}"` — no clamping, so a clock in 2010 gives
  `"2013-2010"` (`main/Version.java:12, 33-38`). `copyright_years_now()` uses the local calendar
  year (Java `Year.now()` uses the default time zone).
- BI5. Banner text: `"ArmA3Sync version {name}\nBuild {version} ({years})"`
  (`console/CommandConsole.java:744-745`; the About dialog shows `"Version {name}"` and
  `"Build {version} ({years})"`, `ui/help/AboutDialog.java:100-107`) and startup line
  `"Arma3Sync Installed version = {version}"` (`main/ArmA3Sync.java:90`). Note the two casings
  `ArmA3Sync` / `Arma3Sync` are verbatim.
- BI6. `GIT_HASH`: `build.rs` runs `git rev-parse --short HEAD` in `CARGO_MANIFEST_DIR`; env
  `A3S_GIT_HASH` overrides; on any failure `"unknown"`. Emits `rerun-if-env-changed=A3S_GIT_HASH`
  and, only if the files exist, `rerun-if-changed` for `<git dir>/HEAD` and the ref it points at.
  The build must succeed without git and outside a git checkout. `TARGET` = build-script `TARGET`
  env; `PROFILE` = build-script `PROFILE` env. No build timestamp (reproducible builds).

### a3s_paths — Rust's own directories (decision: TOML store, no collision with Java)

- P1. Application directory name is `arma3sync-rs` (const `APP_DIR_NAME`). It must differ from
  Java's `APPLICATION_NAME = "Arma3Sync"` (`dao/ApplicationPaths.java:17`) case-insensitively
  (Windows and macOS file systems are case-insensitive, so plain `arma3sync` would collide).
- P2. Platform roots (non-portable, no overrides). Env vars that are unset **or blank after
  trim** count as unset (mirrors Java `isBlank`, `dao/ApplicationPaths.java:207, 232`).
  Relative `XDG_*` values are ignored (XDG spec) for Rust dirs.

  | OS | config | data | cache |
  | --- | --- | --- | --- |
  | Windows | `%APPDATA%\arma3sync-rs` (fallback `<home>\AppData\Roaming\arma3sync-rs`) | `%LOCALAPPDATA%\arma3sync-rs\data` (fallback `<home>\AppData\Local\…`) | `%LOCALAPPDATA%\arma3sync-rs\cache` |
  | Linux / BSD / other Unix | `$XDG_CONFIG_HOME/arma3sync-rs` (fallback `~/.config/…`) | `$XDG_DATA_HOME/arma3sync-rs` (fallback `~/.local/share/…`) | `$XDG_CACHE_HOME/arma3sync-rs` (fallback `~/.cache/…`) |
  | macOS | `~/Library/Application Support/arma3sync-rs/config` | `~/Library/Application Support/arma3sync-rs/data` | `~/Library/Caches/arma3sync-rs` |

  Home = `HOME` (Unix) / `USERPROFILE` (Windows); missing → `Error::NoHomeDir` (Java falls back
  to `"."`, `dao/ApplicationPaths.java:203` — dropped, see deviations).
  On Windows Java's data and cache roots are the same directory (`LOCALAPPDATA\Arma3Sync`,
  `dao/ApplicationPaths.java:205`); Rust separates them with `data`/`cache` subdirectories.
- P3. Derived directories (names fixed here; file names inside them belong to WP04):
  `profiles_dir() = config/profiles` (Java `configRoot/profiles`, `:117-122`),
  `repositories_dir() = data/repositories` (Java `dataRoot/repositories`, `:131-137`),
  `temp_dir() = cache/temp` (Java `cacheRoot/temp`, `:139-141`),
  `log_dir() = data/logs` (Java writes its debug log into the configuration folder,
  `utils/DebugLogger.java:44-47`; moved out of config so config stays small/roamable).
  Java's `bin` folder and `a3s.xml` update metadata (`:143-155`) have no Rust equivalent here
  (updater: WP31).
- P4. Overrides, highest precedence first, each one independently:
  `A3S_CONFIG_DIR`, `A3S_DATA_DIR`, `A3S_CACHE_DIR` set the final directory (no app name
  appended; Java's `a3s.configPath`/`dataPath`/`cachePath` system properties replace only the
  platform root and still append `Arma3Sync`, `dao/ApplicationPaths.java:86, 198-201`).
- P5. Portable mode (Java: `a3s.portable` property or heuristics, `dao/ApplicationPaths.java:38-73,
  241-243, 265-288`). Rust: portable iff env `A3S_PORTABLE` equals `true` ignoring ASCII case
  (Java `Boolean.parseBoolean` semantics: anything else, incl. `1`, is false) **or** a marker file
  `arma3sync-rs.portable` exists next to the current executable. Portable roots:
  `<exe_dir>/arma3sync-rs-data/{config,data,cache}`. P4 overrides still win per directory.
  Java's heuristic "every non-Windows install and every Windows install outside Program Files is
  portable" (`:265-288`) is dropped (deviation D2).
- P6. `AppDirs::ensure_created()` creates config, data, cache, temp, logs, profiles and
  repositories dirs (`create_dir_all`), mirroring `main/ArmA3Sync.java:105-116`. Failure →
  `Error::CreateDir { path, source }` whose user message is
  `messages::cannot_create_directory(path)` (`exception/CreateDirectoryException.java:17-21`).
- P7. Resolution is a pure function of an injected `PlatformEnv` (OS, home, env-var lookup,
  exe dir, file-existence probe for the portable marker). `PlatformEnv::current()` reads the
  process. Tests never call `std::env::set_var` (unsafe in edition 2024; `unsafe_code = deny`).
- P8. `EXPORT_LOG_FILE_NAME = "ArmA3Sync-log.txt"` (`dao/DataAccessConstants.java:49`), used by
  the error-report export dialogs (WP29).

### a3s_paths — legacy Java discovery (read-only, for WP04)

- L1. Java per-user roots (`platformRoot`, `dao/ApplicationPaths.java:197-239`), reproduced
  exactly, then joined with `Arma3Sync`:
  - OS name contains `win` → config: `%APPDATA%`, data/cache: `%LOCALAPPDATA%`; blank/unset →
    `<home>/AppData/Roaming` resp. `<home>/AppData/Local` (`:204-211`).
  - Linux, Unix, BSD **and macOS** → `XDG_CONFIG_HOME` / `XDG_DATA_HOME` / `XDG_CACHE_HOME`,
    fallback `~/.config`, `~/.local/share`, `~/.cache` (`:213-236`). Quirk: Java uses XDG paths on
    macOS; relative XDG values are accepted as-is (no XDG-spec filtering).
  - anything else → `<home>/.arma3sync` (`:238`), so config root = `~/.arma3sync/Arma3Sync`.
- L2. Java per-user layout (non-portable): configuration dir `C/configuration`
  (`a3s.cfg`, `a3s.prefs`, `known-workshop-mods.properties`), profiles `C/profiles`,
  repositories `D/repositories`, where `C = configRoot`, `D = dataRoot`
  (`dao/ApplicationPaths.java:82-137`; workshop file: `service/WorkshopMetadataStore.java:28, 34`).
- L3. Java installation layout for an install dir `I` (portable and pre-modern):
  configuration dir = `I` if `I/a3s.cfg` **or** `I/a3s.prefs` is a regular file, else
  `I/resources/configuration` (`dao/ApplicationPaths.java:250-257`) — quirk: if only
  `I/a3s.prefs` exists, Java looks for `a3s.cfg` in `I` too and ignores
  `I/resources/configuration/a3s.cfg`; mirror this choice. Profiles `I/profiles` (`:117-120`),
  repositories `I/resources/ftp` (`:131-135`). Pre-modern sources that `migrateLegacyData`
  copied from are the same `I/profiles`, `I/resources/configuration`, `I/resources/ftp`
  (`:162-171`).
- L4. `discover_legacy_java(env, extra_install_dirs)` returns, in this order and with entries whose
  `is_empty()` is true removed and duplicates (same normalized configuration dir) dropped:
  1. the per-user layout (L2) if home/env resolve;
  2. each `extra_install_dirs` entry (L3), in the given order (WP04/WP15 pass registry
     `InstallDir` values and user-picked folders);
  3. on Windows, `%ProgramFiles%\Arma3Sync`, `%ProgramFiles(x86)%\Arma3Sync`,
     `%ProgramW6432%\Arma3Sync` (NSIS `InstallDir "$PROGRAMFILES64\${APP_NAME}"`,
     `installer/nsis/Arma3Sync.nsi:33`; env names from `dao/ApplicationPaths.java:274-278`).
  Each `LegacyJavaData` carries the source, the configuration dir Java would use, and `Some(path)`
  only for items that exist: `a3s.cfg` / `a3s.prefs` / workshop file (regular file),
  profiles / repositories (directory). Symlinks are followed (Java `Files.isRegularFile`).
- L5. Discovery never creates, writes, renames or deletes anything and never returns a path
  inside the Rust dirs. Java's copy-missing migration (`dao/ApplicationPaths.java:162-195`) is
  **not** ported; WP04 reads the legacy files in place.
- L6. `inspect_java_installation(dir)` = L3 for one directory (for a "pick a folder" import).

### a3s_log (`utils/DebugLogger.java`)

- G1. `init(&LogConfig) -> Result<LogHandle, Error>` installs a global `tracing` subscriber once;
  a second call returns `Error::AlreadyInitialized` (never panics). Stderr layer filter: env
  `A3S_LOG` (EnvFilter syntax) else `warn`.
- G2. Debug file logging is **opt-in**, as in Java (`utils/DebugLogger.java:20-25`): enabled by
  `LogConfig.debug` (the CLI maps `--debug`/`-debug` and env `A3S_DEBUG=true`, mirroring
  `main/ArmA3Sync.java:41, 63-86`; argument parsing is WP19). File filter: `debug` for targets
  starting with `a3s_` and `arma3sync`, `info` for everything else; `A3S_LOG` does not affect the
  file.
- G3. File: `<log_dir>/arma3sync-rs.log`, created with the directory if missing; appended to
  (Java `append=true`). Size-rotated: when a write would make it exceed 5 MiB
  (`5 * 1024 * 1024`), rename `.log.1`→`.log.2` (dropping old `.2`), `.log`→`.log.1`, reopen —
  at most 3 files, like Java `FileHandler(limit 5 MiB, count 3)` (`utils/DebugLogger.java:48`).
  UTF-8 (`:49`).
- G4. If the file cannot be opened, `init` still succeeds with `log_file() == None` and prints one
  line to stderr: `Arma3Sync diagnostic logging could not be initialized: {error}`
  (`utils/DebugLogger.java:57-64`). Later write/rotate I/O errors are swallowed ("Diagnostics must
  never affect the application", `:130-138`). The writer never panics.
- G5. First line written after enabling: `Debug logging enabled. Log file: {absolute path}`
  (`utils/DebugLogger.java:55`).
- G6. Line format (both layers): `YYYY-MM-DD HH:MM:SS.mmm [<thread name>] [<LEVEL>] <message>`
  followed by ` key=value` for each extra field, then `\n`; local time; unnamed threads print
  `unnamed`. Java: `"%1$tF %1$tT.%1$tL [%2$s] [%3$s] %4$s%n"` (`utils/DebugLogger.java:143-145`)
  with Java level names `INFO`/`WARNING`/`SEVERE`; Rust prints tracing level names
  (`ERROR`, `WARN`, `INFO`, `DEBUG`, `TRACE`). No ANSI colours in the file.
- G7. `redact(value: Option<&str>) -> String` ports `safe()` (`utils/DebugLogger.java:117-128`):
  1. `None` or `""` → `<empty>`;
  2. replace every `\r` and `\n` with a space;
  3. let `a` = byte index of the **last** `@`, `s` = index of the **first** `://` (−1 if absent);
     if `a >= 0 && a > s` → `"<credentials-redacted>@" + text after a` (so `user@host` without a
     scheme is also redacted);
  4. replace every case-insensitive match of
     `(password|passwd|pwd|secret|token)\s*[=:]\s*[^&\s]+` with `<keyword as written>=<redacted>`
     (alternation order as written; no word boundary, so `mypwd=1` → `mypwd=<redacted>`; `\s` is
     Java's ASCII class `[ \t\n\x0B\f\r]`; the value needs ≥ 1 char). Implement without a regex
     crate (hand-written scanner).
- G8. `describe_endpoint(protocol, host, port, remote_path)` →
  `"protocol={protocol or unknown}, host={redact(host)}, port={redact(port)}, remotePath={redact(remote_path)}"`
  (`utils/DebugLogger.java:106-115`). The `AbstractProtocole` overload lives with the type
  (a3s_types/a3s_transport call this helper).

### a3s_format (`utils/UnitConverter.java`)

All arithmetic in `f64` exactly as Java (`long` promoted to `double`, `Math.pow(10, n)` is exact),
truncation by `as i32` (Java `(int)` truncates toward zero and saturates like Rust `as`).
`java_double_to_string(f64)` reproduces `Double.toString`: shortest round-trip digits (Rust
`{:?}` for `1e-3 <= |v| < 1e7`, always at least one fractional digit), and for `|v| >= 1e7` or
`0 < |v| < 1e-3` computerized notation `d.dddE<exp>` (e.g. `1.0E7`, `2.147483647E7`).

- F1. `size(bytes: i64) -> String` (`utils/UnitConverter.java:7-28`): thresholds `>= 1e9` GB,
  `>= 1e6` MB, `>= 1e3` KB, else B (decimal units). `v = bytes / 10^n;
  v = ((v * 100.0) as i32) as f64 / 100.0`; result `java_double_to_string(v) + " GB"|" MB"|" KB"|" B"`.
  Negative input falls to the B branch (`-5` → `-5.0 B`).
- F2. `speed(bytes_per_sec: i64) -> String` (`:30-47`): GB/MB: one decimal truncated
  (`((v * 10.0) as i32) as f64 / 10.0`) + `" GB/s"`/`" MB/s"`; KB and B: integer truncation then
  printed as a double — always `.0` (`12345` → `12.0 KB/s`, `999` → `999.0 B/s`).
- F3. `duration_hms(seconds: i64) -> String` (`:49-57`): `s = (seconds as i32) % 60` (cast before
  modulo — wraps above `i32::MAX`), `m = ((seconds / 60) % 60) as i32`,
  `h = ((seconds / 3600) % 24) as i32` — **days are dropped** (`86400` → `00:00:00`,
  `90061` → `01:01:01`). Each part printed like `DecimalFormat("00")`: at least two digits,
  negative values keep a leading `-` (`-5` → `00:00:-05`). Callers convert ns → s first
  (`ui/repository/workers/AddonsDownloader.java:277`).
- F4. `datetime_medium(&chrono::DateTime<Tz>) -> String`: fixed en-US-style
  `"%b %-d, %Y, %-I:%M:%S %p"` (e.g. `Oct 10, 2026, 2:05:09 PM`, plain ASCII space before AM/PM).
  Java uses `DateTimeFormatter.ofLocalizedDateTime(FormatStyle.MEDIUM)` with the default locale
  (`service/CommonService.java:26-27`, also `FilesSynchronizationReportManager.java:19`,
  `AdminPanel.java:66`, `ChangelogPanel.java:40`) — locale dependence dropped (deviation D5).

### a3s_error (`exception/**`, `ConnectionExceptionFactory`, `RepositoryConsoleErrorPrinter`)

- E1. `ErrorKind` (`#[non_exhaustive]`, `Copy`, `Eq`, `Hash`) — mapping of the Java taxonomy:

  | Kind | Java origin |
  | --- | --- |
  | `NotFound` | `FileNotFoundException`, `exception/remote/Remote*FileNotFoundException`, `exception/repository/*FileNotFound*`, `RepositoryNotFoundException` |
  | `ConnectionFailed` | `UnknownHostException`/`SocketException` (`ConnectionExceptionFactory.java:25-28`) |
  | `ConnectTimeout`, `ReadTimeout`, `Timeout` | `SocketTimeoutException` by message (`:29-44`) |
  | `Unauthorized` | `WRONG_LOGIN_PASSWORD` (`:20`) |
  | `TlsValidation` | `SSL_CERTIFICATE_VALIDATION_FAILED` (`:21`) |
  | `IncompleteTransfer` | `IncompleteFileTransferException` |
  | `PermissionDenied` | `CreateDirectoryException`, `DeleteDirectoryException` |
  | `InvalidData` | `LoadingException`, corrupt/undecodable files, `RepositoryServerInfoReadException` |
  | `WriteFailed` | `WritingException` |
  | `InvalidInput` | `CheckException`, `ProfileException`, empty main/default folder (`RepositoryMainFolderLocationNotFoundException`, `RepositoryDefaultDownloadLocationNotFoundException`) |
  | `Launch` | `LaunchException` |
  | `Cancelled` | (Java: `isCanceled()` checks, no exception) |
  | `Unsupported` | (Rust-only: protocol lacks operation) |
  | `Io` | any other `IOException` |
  | `Internal` | anything else → "unexpected error" |

- E2. `trait UserFacing: std::error::Error { fn kind(&self) -> ErrorKind; fn user_message(&self)
  -> String { format_chain(self) } }`. `is_managed(kind)` is `kind != Internal`. Java's split:
  `RepositoryException | IOException | WritingException` → managed, else unexpected
  (`console/CommandGeneral.java:115-119`).
- E3. `ErrorKind::from_io(&std::io::Error)`: `NotFound`→`NotFound`, `PermissionDenied`→
  `PermissionDenied`, `TimedOut`→`Timeout`, `ConnectionRefused|ConnectionReset|ConnectionAborted|
  NotConnected|HostUnreachable|NetworkUnreachable|AddrNotAvailable`→`ConnectionFailed`,
  `InvalidData|UnexpectedEof`→`InvalidData`, `WriteZero|StorageFull`→`WriteFailed`,
  `Unsupported`→`Unsupported`, else `Io`. `kind_of(&dyn Error)` walks the source chain: first
  `UserFacing`-less `io::Error` found decides; none → `Internal`. (Downcasting to `dyn UserFacing`
  is not possible; crates implementing `UserFacing` call `kind()` directly.)
- E4. `classify_timeout(message: Option<&str>) -> ErrorKind`: lower-cased message contains
  `read` → `ReadTimeout`, else contains `connect` → `ConnectTimeout`, else `Timeout`; `read` is
  tested first (`exception/ConnectionExceptionFactory.java:36-43`).
- E5. Chain formatting: `format_chain(&dyn Error) -> String` joins `Display` of the error and its
  `source()`s with `": "`, skipping a source whose text equals, or is a suffix of, the text
  already emitted (avoids `"HTTP: x: x"` from `#[error("HTTP: {0}")] + #[source]`).
  `format_chain_lines` joins with `"\n"` (Java's `core + "\n" + detail` style). `DisplayChain`
  wrapper: `{}` → `": "`, `{:#}` → `"\n"`.
- E6. `messages` module — verbatim Java texts (typos preserved, see quirks):
  - `connection(core, kind, detail: Option<&str>) -> String` (`ConnectionExceptionFactory.java:23-60`):
    `ConnectionFailed` → `core + "\nConnection failed"`;
    `ConnectTimeout` → `core + "\nConnection closed by ArmA3Sync.\nServer didn't respond, connection timeout reached"`;
    `ReadTimeout` → `core + "\nConnection closed by ArmA3Sync\nServer didn't respond, read timeout reached"`;
    `Timeout` → `core + "\nConnection closed by ArmA3Sync\nServer didn't respond, connection or read timeout reached"`;
    `IncompleteTransfer` → `detail` unchanged, no core (`:45-46`);
    every other kind → `core` + (`"\n" + detail` if `detail` is `Some`) (`:47-58`).
    Constants `WRONG_LOGIN_PASSWORD = "login or password wrong or missing"`,
    `SSL_CERTIFICATE_VALIDATION_FAILED = "Failed to validate SSL certificate"`.
  - `incomplete_transfer(file_name, actual, remote)` →
    `"Incompete file size transfer: {file_name} Remote size: {remote} Bytes, Actual size: {actual} Bytes"`
    (`exception/IncompleteFileTransferException.java:9-15`).
  - `cannot_create_directory(path)` → `"Cannot create directory {path}\nPlease checkout file access permissions."`;
    `cannot_delete_directory(path)` → same with `delete` (`exception/CreateDirectoryException.java:17-21`,
    `exception/DeleteDirectoryException.java:17-21`).
  - Remote metadata missing (`exception/remote/*`, `:8-9` in each):
    autoconfig `"Remote file not found: /.a3s/autoconfig"`, changelogs
    `"Remote file not found: /.a3s/changelogs"`, events `"Remote file not found: /.a3s/events"`,
    serverinfo `"Remote file not found: .a3s/serverinfo"` (no leading `/`,
    `RemoteServerInfoFileNotFoundException.java:8`), sync `"Remote file no found: /.a3s/sync"`
    (`RemoteSyncFileNotFoundException.java:8`). Exposed as `remote_file_not_found(RemoteA3sFile)`
    with a local enum `RemoteA3sFile { Sync, ServerInfo, Changelogs, Events, AutoConfig }`
    (a3s_error cannot depend on `a3s_repo_files::A3sFile`).
  - Repository (`exception/repository/*`): `"File /.a3s/autoconfig not found on repository: {name}"`,
    `"File /.a3s/changelogs not found on repository: {name}"`,
    `"File /.a3s/events not found on repository: {name}"`,
    `"File /.a3s/serverinfo not found on repository: \n{name}"` (extra `\n`,
    `ServerInfoNotFoundException.java:9`), `"File /.a3s/sync not found on repository: {name}"`,
    `"Repository {name} not found!"`, `"Repository {name} main folder location is empty!"`,
    `"Default destination folder is empty!"` (name ignored,

### Java quirks to preserve (wire-visible)

- none — nothing in this WP is written to a repository server or read by Java.

### Java quirks preserved for user-visible parity (local-only; kept by default)

- `UnitConverter` float truncation: `1_130_000` B → `1.12 MB`, `2_010_000` → `2.0 MB`,
  `1_130` → `1.12 KB` (catalogue: "a3s_format matches UnitConverter output").
- KB/s and B/s always end in `.0`; `duration_hms` drops days and prints `-05` for negatives.
- Typos: `"has occured"`, `"Incompete file size transfer"`, `"Remote file no found"` (sync),
  `"Please checkout file access permissions."`, missing `/` for serverinfo, `\n` before the repo
  name in serverinfo-not-found, `"ArmA3Sync"` vs `"Arma3Sync"` casing.
- `classify_timeout` checks `read` before `connect`.
- Redaction treats any `@` as a credentials separator when there is no `://`.
- Java legacy layout quirks in discovery: macOS uses XDG paths; other-OS `~/.arma3sync/Arma3Sync`;
  compact-portable folder chosen when either `a3s.cfg` or `a3s.prefs` exists at the root.

### Java quirks that may be dropped (local-only; needs an approved deviation)

- D1. `migrateLegacyData` copy-on-start (`dao/ApplicationPaths.java:162-195`) → replaced by
  read-only discovery + WP04 one-time import (user decision D-4).
- D2. Java portable heuristic (non-Windows installs always portable, Windows outside Program Files
  portable, `dao/ApplicationPaths.java:38-80, 265-288`) and `a3s.installationPath` → explicit
  marker file / `A3S_PORTABLE` (P5).
- D3. `user.home` fallback `"."` (`:203`) → `Error::NoHomeDir`; Java's override properties append
  `Arma3Sync` while Rust overrides are final dirs (P4); Java's data == cache on Windows → split.
- D4. Debug log location (config dir → `data/logs`), file name `arma3sync-debug.log[.N]` →
  `arma3sync-rs.log[.N]` (Java's FileHandler actually writes `arma3sync-debug.log.0/.1/.2`),
  rotation naming, level names `SEVERE`/`WARNING` → `ERROR`/`WARN`.
- D5. Locale-dependent MEDIUM date format → fixed en-US-like format (F4).
- D6. `Version` fallback `"0.0.0"` and `build()` returning 0 for pre-release versions (BI1, BI3).
- D7. `ErrorReport`: JRE line and Java stack trace → build line and error chain (E8).
- D8. The Java `ApplicationPathsTest.migratesLegacyFilesWithoutOverwritingNewData` asserts on a
  path that is not the migration target (`configRoot` in the test lacks the `Arma3Sync` segment
  that `ApplicationPaths.configRoot()` appends, test lines 27-44), so it passes trivially; the Rust
  port tests read-only discovery instead (A-P1).

### Errors, cancellation, progress

- `a3s_paths::Error` (`thiserror`): `NoHomeDir`, `CurrentExe(io::Error)`,
  `CreateDir { path, source }`; implements `a3s_error::UserFacing`
  (`NoHomeDir`→`InvalidInput`, `CurrentExe`→`Io`, `CreateDir`→`from_io(source)` defaulting to
  `PermissionDenied` message text per P6).
- Discovery never errors: unreadable/missing paths are treated as absent.
- `a3s_log::Error`: `AlreadyInitialized`, `Filter(String)` (bad `A3S_LOG` is reported, then
  ignored → default `warn`; only `AlreadyInitialized` is returned as `Err`).
- No cancellation or progress in this WP.

### Concurrency

- Java guards `DebugLogger.enable` with a lock and a volatile flag
  (`utils/DebugLogger.java:29-41`). Rust: the rotating writer holds its file in a
  `parking_lot::Mutex`; rotation happens under the lock; safe from any thread. All other APIs are
  pure or read-only.
