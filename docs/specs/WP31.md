## Scope

- `UpdateConfig`: read `updater.toml` (same keys and defaults as Java) with the `toml` crate, user
  file → install-root file → `resources/configuration/updater.toml` precedence, plus explicit
  overrides (replacing the Java `-Da3s.updater.*` JVM properties).
- Release sources producing one normalized `Release`: GitHub Releases API, JSON manifest, legacy
  `a3s.xml` (remote + local), with the Java fallback order and error precedence.
- Per-target asset selection (new): `{target}` placeholder in asset patterns and an optional
  per-target table in the JSON manifest (proposal, see Q3).
- Version check (`is_newer`) identical to Java's numeric dotted comparator.
- HTTP client for the updater: HTTPS-only unless `allow_http`, timeouts, 1 MiB metadata cap,
  streaming archive download with byte progress, cancellation and SHA-256 verification.
- Safe ZIP handling: full validation (paths + CRC) before touching the installation, flat
  staging, zip-slip rejection, copy into the installation with `.a3s-updater-files`
  managed-files tracking and cleanup, user-data protection list.
- Diagnostic log (opt-in file log, never fails the update) and the elevated-startup marker writer.
- A documented API that WP32 (apply / self-replace / elevation / CLI flags) consumes.

## Behaviour contract

### Configuration

- B1. Exactly one config file is read, no merging. Precedence: `<user_config_dir>/updater.toml`
  if it is a regular file, else `<install>/updater.toml` if regular file, else
  `<install>/resources/configuration/updater.toml` if regular file, else no file (all defaults).
  (`U/config/UpdateConfig.java:46-55`, `:12`)
- B2. Keys and defaults (section.key → default):
  `update.manifest_url` → `trimSlash(base) + "/a3s.json"`; `update.legacy_xml_url` →
  `trimSlash(base) + "/a3s.xml"`, where `base` = override `base_url` or
  `https://arma3sync.vpzbrig21.de/updates` (`DataAccessConstants.java:23`); `trimSlash` strips one
  trailing `/` and maps blank to the default base (`UpdateConfig.java:57-59,108-111`).
  `update.dev_manifest_url` → effective `manifest_url` **as read from the file, before overrides**;
  `update.dev_legacy_xml_url` → likewise from `legacy_xml_url`; a blank dev value also falls back
  (`:62-65`). `update.allow_http` → `false`; `github.enabled` → `true`; `github.api_url` →
  `https://api.github.com/repos/vpzbrig21/Arma3Sync/releases/latest`; `github.dev_api_url` →
  `github.api_url`; `github.asset_pattern` → `Arma3Sync-{version}.zip` (Rust default: see Q3);
  `github.dev_asset_pattern` → `github.asset_pattern`; `update.connect_timeout_ms` and
  `update.read_timeout_ms` → `30000` (`:60-91`).
- B3. Overrides (Java system properties, Rust `ConfigOverrides`, applied after file values):
  `manifest_url`, `legacy_xml_url`, `dev_manifest_url`, `dev_legacy_xml_url`, `github_api_url`,
  `github_dev_api_url` replace the value when `Some` (even if empty) (`:67-74,86-89`).
  `allow_http` and `github_enabled` overrides can only force `true` (`property || file`), never
  `false` (`:76-79`). `base_url` only changes the defaults (`:57`). Asset patterns and timeouts
  have no override.
- B4. Value types: strings must be TOML strings; booleans TOML booleans; timeouts integers in
  `1..=300_000`, else error `Invalid positive TOML integer: <key>` (`TomlConfigDAO.java:37-65`).
  Unknown keys/sections are ignored (`:14-35` stores all, getters read only known keys). Any
  parse/type error makes `load` fail (the update check then fails, `Service.java:52,64-66`).
- B5. Mode accessors: every URL/pattern accessor takes `dev: bool` and returns the `dev_*` value in
  dev mode (`UpdateConfig.java:97-104`). `github_enabled`, `allow_http`, timeouts are shared.
- B6. Rust addition: `ConfigOverrides::from_env()` reads `A3S_UPDATER_USER_CONFIG_PATH`,
  `A3S_UPDATER_URL`, `A3S_UPDATER_MANIFEST_URL`, `A3S_UPDATER_LEGACY_XML_URL`,
  `A3S_UPDATER_MANIFEST_URL_DEV`, `A3S_UPDATER_LEGACY_XML_URL_DEV`, `A3S_UPDATER_ALLOW_HTTP`,
  `A3S_UPDATER_GITHUB_ENABLED`, `A3S_UPDATER_GITHUB_API_URL`, `A3S_UPDATER_GITHUB_API_URL_DEV`
  (1:1 with `a3s.updater.userConfigPath`, `.url`, `.manifestUrl`, `.legacyXmlUrl`,
  `.manifestUrl.dev`, `.legacyXmlUrl.dev`, `.allowHttp`, `.github.enabled`, `.github.apiUrl`,
  `.github.apiUrl.dev`). Booleans follow `Boolean.getBoolean`: true iff value equals `true`
  ignoring ASCII case. The library never reads env vars implicitly; callers pass overrides.

### Version handling

- B7. `is_newer(candidate, current)`: trim, split on `.`; per component keep the leading ASCII
  digits (cut at the first non-digit), empty or `> i32::MAX` → 0; missing components → 0; compare
  component-wise; first difference decides `candidate > current`; all equal → `false`.
  (`U/service/VersionComparator.java:7-24`). E.g. `2026.2.6-beta` == `2026.2.6`;
  `0.1.0-alpha.1` → `[0,1,0,1]` (newer than `0.1.0`, see Q5).
- B8. Supported-version syntax (JSON `version`, GitHub tag): ASCII regex
  `^\d+(\.\d+){2,3}([-+][A-Za-z0-9]+([.-][A-Za-z0-9]+)*)?$` on the trimmed string
  (`JsonManifestDAO.java:14-15,96-98`). Implement by hand (no `regex` dep). XML versions are not
  validated (`XmlDAO.java:52-54`).
- B9. Current version is supplied by the caller (WP32 uses the build version). Java's lookup
  (`a3s.updater.currentVersion` → `version.txt` line starting `build ` case-insensitive →
  `"0.0.0"`, `Service.java:84-94`) is provided as `read_version_txt(install)` helper only for
  completeness; the native app does not ship `version.txt` (local-only, see Q1).

### Release sources

- B10. Common URL rule `require_http_url`: scheme `http`/`https` (case-insensitive), host present,
  no user-info, else `Invalid HTTP(S) <field>.` (`JsonManifestDAO.java:100-106`).
- B11. Common file-name rule `is_safe_zip_name`: non-blank, no `/`, no `\`, not `.`/`..`, ends with
  `.zip` ASCII-case-insensitively (`JsonManifestDAO.java:91-94`, `GitHubReleaseDAO.java:110-113`,
  `XmlDAO.java:68-71`).
- B12. JSON documents (manifest and GitHub API): top level must be an object; **duplicate keys at
  any depth are rejected**; numbers must match JSON grammar (`01`, `+1`, `.5` rejected); unknown
  keys ignored (`JsonManifestDAO.java:19-28,136-153,201-210`). Rust: `serde_json` into a
  duplicate-rejecting value type (custom `Visitor` for maps).
- B13. Non-negative integer fields (`size`): absent → 0; must be a JSON number; accepted if it is an
  integer in `0..=i64::MAX` or a float with zero fractional part in that range (`1.0`, `1e3` ok,
  `1.5`, `-1`, `1e30` rejected) (`JsonManifestDAO.java:72-83`). The same rule is used for GitHub
  `size` (Java truncates there, `GitHubReleaseDAO.java:92-99`, local-only deviation).
- B14. JSON manifest (`a3s.json`, `JsonManifestDAO.read`, `:30-63`). String getter: absent/`null`
  → fallback, non-string → error `JSON field must be a string: <key>`, value trimmed (`:65-70`).
  - `version` = `version`, else `nom`; must satisfy B8 (`:33,36-38`).
  - `file` = `file`, else `filename`; `download` = `downloadUrl`, else `url` (`:34-35`).
  - If no file but a download URL: file = last `/`-segment of the URL path (decoded); empty path →
    error (`:39-45,85-89`). File must satisfy B11 (`:46`).
  - Download URL = `source.join(download)` if download non-blank, else `source.join(file)`
    (`:48-54`); must satisfy B10 (`:55`). File name and download URL are not cross-checked.
  - `sha256` = `sha256`, else `hash`; must be 64 hex chars (case-insensitive), stored lowercase
    (`:56-59,61`). `size` per B13 (`:60`). `schemaVersion` is ignored.
  - Result: `Release { format: Json, source: <manifest url> }`.
- B15. Rust addition (Q3): optional `targets` object `{ "<target-triple>": { file|filename,
  downloadUrl|url, sha256|hash, size } }`. When present, the entry for the requested target is used
  with the B14 rules (top-level `version` still required); missing entry → error
  `JSON manifest has no asset for target <t>`. When absent, the top-level single-file form applies
  (Java schema 1).
- B16. GitHub (`GitHubReleaseDAO.read`, `:16-67`):
  - API URL non-empty and B10; asset pattern non-blank (`:18-24`).
  - GET with headers `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`
    (plus B22 headers) (`:13-14,26-27`).
  - `tag_name`: must be a non-blank string (trimmed); version = tag with all leading `v`/`V`
    stripped, must satisfy B8 (`:29-30,69-77,79-83`).
  - Expected asset = pattern with `{version}` → version, then `{tag}` → tag, then (Rust addition)
    `{target}` → target triple; must satisfy B11, else `GitHub asset pattern must resolve to a ZIP
    filename.` (`:31-34`).
  - `assets` must be an array (`:36-37`); non-object elements and elements whose `name` is not
    exactly equal (not trimmed) are skipped; first match wins; none → `GitHub release asset not
    found: <name>` (`:38-47`).
  - `browser_download_url` required non-blank string, parsed, B10 (`:49,58-64`).
  - `digest`: optional string; a `sha256:` prefix (case-insensitive) is stripped and the rest
    trimmed; result must be 64 hex chars, else `GitHub release asset has no valid SHA-256 digest`
    (`:50-56`). Stored lowercase (`:65`).
  - `size` per B13. `draft`/`prerelease` are not inspected. `source` = API URL string (`:66`).
- B17. Legacy XML (`XmlDAO.read`, `:38-59`): parse with DTDs forbidden (roxmltree
  `allow_dtd: false`), no external entities (`:42-49`). Version = text content of the first
  element named `nom` anywhere in document order; file = first `file` element; text is the
  concatenated descendant text, trimmed; blank → absent (`:52-53,61-66`). No `nom` → `Ok(None)`
  (`:54`). Missing file → derived name (Java `Arma3Sync-<version>.zip`, `:55`; Rust see Q4). File must
  satisfy B11 (`:56`). Download URL = `source.join(file)`, `sha256 = None`, `size = 0`,
  `format = Xml` (`:57-58`). Root element name is not checked.
- B18. Local XML: `<install>/a3s.xml` if regular file, else `None` (`XmlDAO.java:28-36`).
- B19. Resolution order (`Service.readConfiguredManifest`, `Service.java:231-275`), given
  `dev`, `preference: UpdateSource`, `target`:
  1. If `config.github_enabled && preference != Manifest`: try GitHub (B16); on any error remember
     it and continue (`:232-240`). `preference == GitHub` behaves like `Configured`; an explicit
     `enabled = false` is authoritative.
  2. If `manifest_url(dev)` non-blank: fetch (B23) + B14/B15; on error remember it, continue
     (`:242-252`).
  3. If `legacy_xml_url(dev)` non-blank: fetch + B17; errors are **silently ignored**
     (`:254-261`). If the document parses but has no `<nom>`, Java returns `null` here and the whole
     resolution ends with "No update metadata" without trying step 4 (`:259`; Rust: Q7).
  4. Local `a3s.xml` (B18): if present, the release keeps its version/file but its download URL is
     `legacy_xml_url(dev)` (or `<default base>/a3s.xml` when blank) joined with the file name;
     `sha256 = None`, `size = 0`, `format = Xml`, `source` = local file URL (`:263-271`).
  5. Otherwise return the JSON error if any, else the GitHub error, else
     `NoMetadata` ("No update metadata was found.") (`:272-274`, `:58`).
- B20. Diagnostics around resolution: info `Reading update metadata: dev=<b>, sourcePreference=<p>`,
  info `Update metadata loaded: version=…, file=…, format=…, uri=…`, error
  `Reading update metadata failed.` (`Service.java:51,60-62,65`). Also emit the same as `tracing`
  events. Each step failure is additionally logged at debug level (Rust addition; Java swallows).

### HTTP

- B21. Only `http`/`https`; `http` only if `allow_http`, else error `Updater requires HTTPS`
  (`HttpDAO.java:135-141`). Redirects: follow at most 10, never from `https` to `http`, and every
  hop must pass the same scheme rule (Java `HttpURLConnection` never follows cross-protocol
  redirects).
- B22. Every request: `User-Agent: ArmA3Sync-Updater`; connect timeout = `connect_timeout_ms`;
  read (inactivity) timeout = `read_timeout_ms` (`:142-147`). No retries anywhere. Status outside
  `200..=299` → `Update server returned HTTP <code>.` (`:150-152`).
- B23. `read_text(url, extra_headers)`: GET; if `Content-Length > 1 048 576` → error `Update
  manifest is larger than 1 MiB.`; read at most 1 048 577 bytes, more than 1 048 576 → same error;
  decode UTF-8 lossily (`:81-96`).
- B24. `content_length(url)`: HEAD, 2xx required, returns `Content-Length` or `None`
  (`:27-36`; Java returns -1 and the caller maps `<= 0` to "Can't find update file",
  `Service.java:105-106`).
- B25. `download(release, staging, progress, cancel)`: staging dir = new temp dir prefixed
  `arma3sync-update-`; archive path = `<staging>/<file_name>` (file name re-checked with B11,
  `HttpDAO.java:38-43,173-179`); GET, 2xx; stream to file; after each chunk call
  `progress(total_bytes_so_far: u64)` (`DownloadCountingOutputStream.java:441-460`); after EOF,
  if `sha256` is `Some`, hash the file and compare case-insensitively, mismatch →
  `SHA-256 verification failed for the update archive.` (`HttpDAO.java:49-65,154-171`). On
  `sha256 == None` see Q2.
- B26. Cancellation: a `CancellationToken` aborts the in-flight request/stream promptly (< 1 s) with
  `UpdateError::Cancelled`; the staging directory is **not** deleted by cancel (`HttpDAO.java:67-75`,
  `Service.java:188-195`); `StagingDir` deletes itself on drop unless `keep()` was called
  (Java `clean()`, `HttpDAO.java:126-133`).

### Archive validation, staging and installation

- B27. `validate_archive(path)` before anything is extracted: open the central directory; for every
  entry (directories included) check the name with B29; for every non-directory entry read the
  data to EOF (CRC check); zip errors → `Update archive is invalid or incomplete: <msg>`; zero file
  entries → `Update archive is empty.` (`FtpDAO.java:117-145`).
- B28. Directory entry = zip directory flag, or name ending with `/` or `\` (`FtpDAO.java:235-244`).
- B29. Entry name rule (`resolveEntryPath`, `FtpDAO.java:246-260`): blank name → `Update archive
  contains an empty entry name.`; replace `\` with `/`; lexically normalize (`.` dropped, `a/../b`
  → `b`); result must stay strictly inside the root, else `Unsafe ZIP entry: <name>`. Rust must
  additionally reject: absolute/rooted names (`/x`), Windows drive or UNC prefixes (`C:x`, `C:/x`,
  `//server`), NUL, and any `:` in a component (Java gets these via `Path.of` throwing on Windows /
  resolving absolute paths; Rust must reject them on every platform). A **file** entry that
  normalizes to the root itself is unsafe.
- B30. `stage_archive(archive, dir)`: create `dir`; for every non-directory entry in archive order,
  write its bytes to a fresh flat temp file `entry-*.tmp` in `dir` and record
  `StagedEntry { source, relative }` (relative = normalized portable path); on a write error delete
  the temp file and fail `Could not stage ZIP entry '<name>'.` (`FtpDAO.java:200-229`). Directory
  entries produce nothing. Rust: on Unix record the entry's permission bits (`unix_mode() & 0o777`,
  never setuid/setgid/sticky) and apply them to the staged file; symlink entries are rejected (Q8).
- B31. `install_staged(dest, entries, replacer)` (`copyStagedFiles`, `FtpDAO.java:287-320`), in this
  order:
  1. create `dest`; read the previous managed set from `<dest>/.a3s-updater-files` (B33). Any
     invalid line aborts **before any file is touched** (`:288-291`).
  2. For each staged entry in order: source must be a regular file, else
     `MissingSource` whose message contains `source entry is missing` (`:297,322-325`); relative
     must be non-empty and relative (`:298-300`); skip if user-managed (B34) (`:301`); skip if the
     relative path equals `.a3s-updater-files` ignoring ASCII case (`:302`); target =
     `dest/relative` normalized and inside `dest` (`:303-306`); create parents; replace target via
     `replacer` (Java: `Files.copy(REPLACE_EXISTING, COPY_ATTRIBUTES)`, `:307-308`); add the
     portable relative path to the current set (insertion-ordered, deduplicated) (`:309`).
  3. For each previous path not present in the current set (comparison: ASCII-case-insensitive on
     Windows, exact elsewhere, `:373-380`) and not user-managed: delete it if it exists (`:312-317`).
     Deleting a non-empty directory fails the install (Java `deleteIfExists` throws). Emptied parent
     directories are left in place.
  4. Write the current set to the state file atomically (B33) (`:319`).
- B32. `install_tree(source_dir, dest, replacer)` (`copyTree`, `FtpDAO.java:262-285`): walk
  `source_dir` for non-directory entries, build `StagedEntry`s with paths relative to it, then B31.
  Missing `source_dir` → `MissingSource` (`:267-269`).
- B33. `.a3s-updater-files`: UTF-8, one portable (`/`-separated) path per line, written with the
  platform line separator (`\r\n` on Windows, `\n` elsewhere — `Files.write`), via a temp file
  `.a3s-updater-files.<random>.tmp` in `dest` renamed over the state file (atomic, falling back to
  a plain replace), temp removed in all cases (`FtpDAO.java:382-394`). Reading: missing file →
  empty set; exists but not a regular file → error `Updater state is not a file` (`:342-344`); blank
  lines skipped; trailing `\r` stripped; `\` → `/`; each path must be relative, non-root and inside
  `dest`, else `Unsafe updater state path: <line>` (`:346-367`). Rust validates **after** the `\` →
  `/` conversion (Java validates before, local-only quirk Q-list).
- B34. User-managed (never written, never deleted) relative paths (`FtpDAO.java:396-412`):
  ASCII-case-insensitive equality with `a3s.cfg`, `a3s.prefs`, `a3s.xml`, `updater.toml`,
  `resources/configuration/updater.toml`, `resources/configuration/a3s.cfg`,
  `resources/configuration/a3s.prefs`, `resources/configuration/a3s.xml`, `profiles`,
  `resources/ftp`, `resources/temp`; and anything under `profiles/`, `resources/ftp/`,
  `resources/temp/` (Java prefix check is case-sensitive; Rust makes it case-insensitive, local-only
  deviation).
- B35. `install_archive(archive, dest, replacer)` = Java `HttpDAO.install` (`HttpDAO.java:98-124`):
  archive must exist; B27 wrapped as stage `archive validation`; extract with B30 into a new temp
  dir prefixed `arma3sync-update-extracted-` (outside the download staging dir) wrapped as
  `archive extraction`; B31 wrapped as `installation copy`; the extraction dir is always removed.
  Stage wrapping message: `Update <stage> failed.[ Missing path: <p>.] <inner message>`
  (`FtpDAO.java:327-332`).
- B36. Default `FileReplacer` (`CopyReplacer`): copy `source` to a sibling temp file in the target
  directory, apply the staged permissions, then rename over `target`. (Java copies in place; in-place
  writes fail with ETXTBSY on a running Linux executable. WP32 supplies its own replacer for the
  running executable on Windows.) Modification times are not preserved (Java's
  `COPY_ATTRIBUTES` copies the staging temp file's times, i.e. extraction time).

### Diagnostics

- B37. `DiagnosticLog` is enabled only when constructed enabled (`A3S_UPDATER_DEBUG` = `true` ignoring
  case via `DiagnosticLog::from_env`, mirrors `a3s.updater.debug`, `DiagnosticLog.java:14,21-23`).
  Path: explicit (`A3S_UPDATER_DEBUG_LOG_PATH`, made absolute + normalized) else
  `<local data dir>/Arma3Sync/logs/arma3sync-updater-debug.log` (`:25-34`; Rust uses
  `directories::BaseDirs::data_local_dir()`, which is `%LOCALAPPDATA%` on Windows like Java).
- B38. Line format: `<RFC 3339 local timestamp with offset> [<thread name or "unnamed">] [<INFO|ERROR>]
  <message>`, then for errors the error chain (one `Caused by: …` line per source), then the platform
  line separator; appended under a process-wide lock; parent dirs created; every I/O failure is
  swallowed (`:58-80`).
- B39. `mark_elevated_startup(marker)`: create parents, write the current timestamp (truncate);
  failure → `error("Could not write the elevated updater startup marker.", e)` (`:44-56`). Called
  by WP32.

### Java quirks to preserve (wire-visible)

"Wire" here = files and endpoints shared with Java releases and Java installations.

- `updater.toml` key names, sections, defaults and dev-fallback semantics (B2), including dev
  values defaulting to file values *before* overrides.
- JSON manifest field names and aliases (`version`/`nom`, `file`/`filename`, `downloadUrl`/`url`,
  `sha256`/`hash`, `size`), relative URL resolution against the manifest URL, `schemaVersion`
  ignored (B14).
- GitHub: exact asset-name equality, `v`/`V` stripping, `sha256:` digest prefix, required digest (B16).
- `a3s.xml` element names `nom`/`file`, `Arma3Sync-<version>.zip` derivation (B17).
- `.a3s-updater-files` name, line format and the user-managed list (B33, B34).
- HTTP `User-Agent: ArmA3Sync-Updater`, GitHub `Accept` and `X-GitHub-Api-Version` headers (B16, B22).
- Version comparator semantics (B7), 3–4 component version syntax (B8).

### Java quirks that may be dropped (local-only; needs an approved deviation)

- TOML: Java's hand-written reader accepts booleans in any case (`TRUE`), last-wins duplicate keys,
  and arbitrary garbage values for unknown keys; rejects `\u` escapes and single-quoted strings
  (`TomlConfigDAO.java:14-98`). The `toml` crate is stricter/more complete (task allows it).
- JSON: Java's `Character.isWhitespace`, lone surrogates in `\u` escapes, and failing the whole
  document on any integer > `i64::MAX` (`JsonManifestDAO.java:201-218`) — `serde_json` behaviour is
  acceptable.
- JSON fallback getters are evaluated eagerly: `"nom": 5` fails even when `version` is valid
  (`JsonManifestDAO.java:33-35,56`). Rust may evaluate lazily.
- GitHub `size` truncates fractional numbers (`GitHubReleaseDAO.java:96`); Rust rejects them (B13).
- `DownloadCountingOutputStream` double counts: `FilterOutputStream.write(byte[],int,int)` calls the
  overridden `write(int)` per byte, then adds `length` again, and notifies `length+1` times per chunk;
  progress is also clamped to `Integer.MAX_VALUE` (`DownloadCountingOutputStream.java:435-460`).
  The Java progress bar therefore reaches 100 % halfway. Rust reports true `u64` bytes once per chunk.
- `safeFileName` accepts `a/../b.zip` because it checks the normalized path (`HttpDAO.java:173-179`);
  Rust uses B11 directly.
- Managed-state lines validated before `\`→`/` conversion, so a Linux line `..\x` passes validation
  and fails later mid-cleanup (`FtpDAO.java:349-350`); Rust validates the converted path up front.
- Case-sensitive `profiles/`, `resources/ftp/`, `resources/temp/` prefixes (`FtpDAO.java:407-411`).
- Archive validated through the central directory but extracted through local headers
  (`ZipFile` vs `ZipInputStream`, `FtpDAO.java:124,209`); Rust uses `zip::ZipArchive` for both.
- Duplicate entry names in an archive: Java stages both, last copy wins; Rust may reject the
  archive as invalid (whatever the `zip` crate does is acceptable; test documents it).
- Download size is never compared with the manifest `size` (Q9).
- Diagnostic log default path on non-Windows is `~/AppData/Local/...` in Java (`DiagnosticLog.java:31`).
- FTP update transport (`a3s.updater.protocol=ftp`, `www.sonsofexiled.fr:21`, anonymous,
  `/ArmA3/ArmA3Sync/download|development`, 30 s timeouts, passive binary; `DataAccessConstants.java:8-21`,
  `FtpDAO.java:37-73,147-155`, `Service.java:197-228`) — dropped (Q6).

### Errors, cancellation, progress

- No retries (Java has none). Every source failure during resolution is caught and the next source
  tried (B19); JSON error outranks GitHub error in the final result; XML errors are never surfaced.
- Archive validation happens fully before any staging; staging fully before any write to the
  installation; managed-state validation before any write (B27, B31.1). A failure during step 2/3
  of B31 leaves a partially updated installation (Java behaviour; WP32 may add rollback).
- Progress: `progress(u64 bytes)` after every chunk written (B25). Size for a progress total comes
  from `Release::size` or `content_length` (B24).
- Cancellation: token checked in the read loop and raced against pending I/O (B26). Archive
  operations are synchronous and not cancellable (Java same).

### Concurrency

- Java: single worker thread (Swing worker or console), `cancel()` from the UI thread;
  `DiagnosticLog` global lock; observers in a `CopyOnWriteArrayList`. Rust: HTTP functions are
  `async` (tokio + reqwest, one connection at a time); archive/install functions are blocking
  (`std::fs`, WP32 runs them in `spawn_blocking`); `DiagnosticLog` is `Clone + Send + Sync` with a
  `parking_lot::Mutex` around appends.

- Byte identity required for: nothing. Semantic compatibility required for: `updater.toml` (Java
