## Behaviour contract

Two different Java classes are both called `AutoConfig`:

- `fr.soe.a3s.domain.repository.AutoConfig` is the remote `.a3s/autoconfig` file. It already
  exists as `a3s_types::AutoConfig`.
- `fr.soe.a3s.domain.AutoConfig` is the local `export.a3s.autoconfig` file. It is
  `a3s_types::local::AutoConfigExport` from WP03.

This WP parses URLs that point to the first and does file I/O for the second.

### Autoconfig URL parsing (`autoconfig_url::parse`)

- B1. Trim the input like Java `String.trim()`: strip leading and trailing chars `<= U+0020`
  only, not Unicode whitespace (`dao/connection/AutoConfigURLAccessMethods.java:64`).
- B2. Scheme detection is an ASCII case-insensitive **prefix** match, checked in this order:
  `https://` → `Https`, `http://` → `Http`, `ftp://` → `Ftp` (`:65-77`). A scheme that only
  appears later in the string is not matched (`:66-67`). `ftps://`, `sftp://`, `a3s://`,
  WebDAV and SOCKS URLs are rejected (`:78-87`).
- B3. Rejection error, verbatim (local-only UI text, but cheap to keep):
  `"Invalid url or unsupported protocol.\nUrl must start with ftp:// or http:// or  https://"`.
  Note the **two spaces** before `https://` (`:83-85`). A Java `null` input gives
  `"Invalid url or unsupported protocol."` (`:60-62`). Rust takes `&str`, so this case can't
  happen, but the variant text is kept for the empty-suffix check (B9).
- B4. `rest` = trimmed input after the scheme prefix (`:89`). `parseA3S` is unreachable
  (commented out, `:78-81, 91-95`) and is **not** ported.
- B5. Split `rest` at its **first** `/`: `hostname` = text before it, `relative_path` = text from
  the `/` onwards (includes the `/`). Without a `/`, `hostname = rest` and `relative_path = ""`
  (`:153-159`).
- B6. Split `hostname` at its **first** `:`: `port` = text after it, `hostname` = text before it
  (`:161-165`). Quirks to preserve: IPv6 literals (`[::1]:8080` → host `[`) and userinfo
  (`user:pw@host` → host `user`, and the port `pw@host` is invalid) are not supported.
- B7. If `relative_path` contains `/autoconfig` (ASCII case-insensitive, **last** occurrence,
  not anchored to the end), cut `relative_path` just before it (`:167-170`). For example,
  `/Repo/WOG/.a3s/autoconfig` → `/Repo/WOG/.a3s`, and `/x/AutoConfigFoo/bar` → `/x`. The
  `/.a3s` segment is **kept**: the resulting protocol points at the `.a3s` folder, and callers
  fetch the relative file `autoconfig` from it (`dao/connection/AbstractConnexionDAO.java:179`,
  `RemoteFile("autoconfig", "")`).
- B8. `url = hostname + relative_path` (`:172`). `port` is kept as typed if it parses as a Java
  `int` (`Integer.parseInt`: optional `+`/`-` sign, decimal digits, i32 range; Rust:
  `str::parse::<i32>()`), else it becomes `""` (`:174-178`). An empty port becomes
  `protocol_type.default_port()` (`"443"`, `"80"`, `"21"`) (`:180-182`). The port string is
  stored as typed, for example `"+21"` or `"0021"` stay unchanged. No range check to 1-65535.
- B9. The result equals `AbstractProtocoleFactory.getProtocol(url, port, "anonymous", "",
  type, true)` (`:184-190`), so it is `Protocol::new(type, url, port, "anonymous", "", true)`:
  `validate_ssl_certificate = true` for every scheme (the comment at `:187-189` explains why),
  timeouts `Some("300000")`, `encryption_mode = None`.
- B10. An empty host is not an error in `parse` (`https://` → url `""`, port `"443"`). The
  caller is expected to run WP03's `check_protocol` (`"URL field is empty!"`,
  `domain/AbstractProtocole.java:99-102`).

### Import pre-check (`autoconfig_url::parse_import_url`), from the import dialog

- B11. Trim (B1). The text after the **last** `/` must equal `autoconfig` exactly
  (case-sensitive). If there is no `/` at all, the check fails too. On failure the error text is
  `"Url must ends with \"autoconfig\"."` (Java's grammar, verbatim)
  (`ui/repository/dialogs/connection/DescriptionPanel.java:234-253`). The check runs **before**
  `parse` (B2-B9), so `https://h/x/AUTOCONFIG` fails here even though `parse` would accept it.
- B12. After a successful `parse`, set `connection_timeout` and `read_timeout` to `Some("0")`
  (no timeout) (`DescriptionPanel.java:261-262`).

### Autoconfig URL formatting (`autoconfig_url::determine_autoconfig_url`)

- B13. If `protocol.port == protocol.protocol_type.default_port()` (exact string comparison,
  so `"021"` or `" 21"` are not default), the port is treated as empty
  (`AutoConfigURLAccessMethods.java:36-38`).
- B14. If the port is non-empty after B13, the base is `hostname() + ":" + port +
  remote_path()`. Otherwise the base is `protocol.url` unchanged (`:40-43`).
- B15. Result: `base + "/.a3s/autoconfig"`, with **no scheme** (`:45`). The value is stored in
  `Repository.auto_config_url` by the builder (WP11, `dao/repository/RepositoryBuildProcessor.java:279-280`).
  A trailing `/` in `url` produces `//.a3s` (quirk, keep). The `login == "anonymous"` →
  `""` rewrite at `:32-34` has no effect on the output (dead store). Java throws an NPE when
  `login` is null. Rust ignores the login, which is an allowed local-only difference.
- B16. Display form (`autoconfig_display_url`) = `protocol_type.prompt() + stored`. If the stored
  URL is empty it is treated as absent (`ui/repository/AdminPanel.java:410-413`,
  `console/CommandConsole.java:126-130, 158-162`). WebDAV repositories therefore show
  `http(s)://…`, and SFTP or FTPS repositories show a URL that `parse` rejects (quirk, keep).
- B17. Round trip: for an FTP, HTTP or HTTPS protocol `p` with a non-empty host,
  `parse(display(p))` yields `url == p.url + "/.a3s"` (when `p.url` has no trailing `/`) and
  `port == p.port` (after B13/B8 default handling).

### SSL validation policy (`ssl_policy`)

- B18. `host_part(s)`: Java-trim (B1), then the text before the first `/`. Null → `""`
  (`service/SslValidationPolicy.java:28-33`). The **port is not stripped**: `localhost:8443`
  stays as is.
- B19. `is_local_test_host(s)`: `host_part(s)`, lower-cased (ASCII). If it starts with `[`
  **and** ends with `]`, strip both. Then it is true for `localhost`, `localhost.`, `::1`,
  `0:0:0:0:0:0:0:1`, and anything starting with `127.` (`:13-22`). So `localhost/repository`
  is true and `localhost:8443` is false.
- B20. `is_allowed_for(host, allow_override)`: `is_local_test_host(host) || allow_override`
  (`:24-26`). In Java the override is the system property `a3s.allowInsecureSsl`
  (`Boolean.getBoolean`, case-insensitive `"true"`). In Rust it is the environment variable
  `A3S_ALLOW_INSECURE_SSL` (`"1"` or case-insensitive `"true"`), the same rule as
  `a3s_transport::TransportOptions::from_protocol`. `insecure_override_from_env()` reads it.
  Policy functions take the flag as an argument so tests don't touch the process environment.
- B21. `refusal_text()` and `warning_text(host)` reproduce `:37-39` and `:44-47` with
  `host_part(host)` substituted. The override instruction is reworded for the env var (see Q2).
- B22. The policy applies only when `validate_ssl_certificate == false` for HTTPS, HTTPS-WebDAV
  and FTPS. The UI dialogs check it for HTTPS and HTTPS-WebDAV
  (`ui/repository/dialogs/connection/RepositoryEditionDialog.java:120-125`). The DAOs enforce it at
  connect time (`dao/connection/ftp/FtpDAO.java:229`, `http/HttpDAO.java:100`,
  `webdav/WebdavDAO.java:116`). Rust transports already enforce it
  (`a3s_transport::Error::InsecureTlsRefused`). This WP only provides the shared predicate and
  texts for UI and CLI callers.

### `export.a3s.autoconfig` file I/O (`autoconfig_export`)

- B23. File name `export.a3s.autoconfig` (`dao/DataAccessConstants.java:20,46`) inside the chosen
  destination folder (`dao/CommonDAO.java:42`).
- B24. Export: `GZIP(ObjectOutputStream(domain.AutoConfig))`, unencrypted
  (`dao/CommonDAO.java:41-43`, `dao/A3SFilesAccessor.java:144-162`). Use
  `a3s_types::encode_stream(&AutoConfigExport)` (WP03 encoder, which already applies the
  "launcherOptions null" and "fresh `Repository(name, protocol)`" rules), then the same gzip
  header as `encode_a3s` (mtime 0, OS 255). Passwords in profiles and repository protocols are
  written **in clear text**, as in Java.
- B25. Before writing, the encoded stream must pass
  `a3s_jserial::read_with_limits(raw, Limits::JAVA_A3S)`, the Java reader's filter
  (`dao/A3SFilesAccessor.java:27-30`: depth 100, 250 000 references, 256 MiB). Otherwise the
  export fails and no file is written (see Q1).
- B26. The write is atomic: temporary file in the same folder, then rename, overwriting an
  existing file (`dao/A3SFilesAccessor.java:148-156, 188-200`). Use `crate::a3s_file::write_atomic`.
  The destination folder must already exist. If it doesn't, return `Error::Io { path:
  folder, source: NotFound }`, as Java `Files.createTempFile` fails there. Do **not** call
  `create_dir_all` (the Java UI checks this first, `ui/help/AutoConfigExportDialog.java:208-213`).
  Overwrite confirmation is the UI's job.
- B27. Import: read the file, gunzip with the `MAX_DECOMPRESSED_SIZE` (256 MiB) cap like
  `decode_a3s`, then `decode_legacy_stream::<AutoConfigExport>` (WP03, lenient, default limits).
  Return `Legacy<AutoConfigExport>` so callers can log warnings (`dao/CommonDAO.java:22-34`).
- B28. Import errors map to the existing `a3s_repo_files::Error` variants: missing or unreadable
  file → `Io`, bad gzip → `Gzip`, oversize → `TooLarge`, bad stream or wrong root class →
  `Types`. The Java wrapper text `"Failed to read autoconfig file.\n" + detail` and
  `"Failed to write autoconfig file.\n" + detail` (`dao/CommonDAO.java:30-31, 46-47`) is UI text
  for WP14/WP29. It is recorded here only so those WPs can reproduce it.

### Java quirks to preserve (wire-visible)

- `export.a3s.autoconfig` root class `fr.soe.a3s.domain.AutoConfig`, unencrypted gzip, profiles
  with null `launcherOptions` and reduced repositories (WP03 encoder). Passwords are in clear text.
- `.a3s/autoconfig` URLs keep `/.a3s` in the parsed protocol URL, and the file fetched is the
  relative name `autoconfig` (B7). Any other choice fetches the wrong path from real servers.

### Java quirks that may be dropped (local-only; needs an approved deviation)

- `String.toLowerCase()` in B7 uses the default locale. Under a Turkish locale `/AUTOCONFIG`
  doesn't match, and some Unicode lowercasing changes the string length. Rust uses ASCII
  case-insensitive matching (no deviation needed, Java's behaviour here is a bug).
- `Integer.parseInt` accepts non-ASCII Unicode digits. `i32::from_str` doesn't, so such a port
  becomes the default port.
- `determineAutoConfigUrl` throws an NPE for a null login. Rust doesn't (B15).
- Override mechanism `-Da3s.allowInsecureSsl=true` → env var `A3S_ALLOW_INSECURE_SSL` (already
  used by `a3s_transport`; see Q2).
- Kept verbatim although local-only (cheap): the error texts of B3 and B11, the double space,
  and "must ends".

### Errors, cancellation, progress

- `parse`/`parse_import_url` → `Result<Protocol, AutoConfigUrlError>`. No I/O, no retries.
- Export/import → `a3s_repo_files::Result`. No retries, no progress, no cancellation (single
  small file). Java prints the stack trace on write failure (`dao/CommonDAO.java:45`). Rust
  returns the error, and the caller logs it.

### Concurrency

None. All functions are synchronous and pure, except the file I/O in `autoconfig_export`.
